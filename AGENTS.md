# Offscreen RPG | agent entry

**Identify the actual repository, branch, HEAD and scope before work.** Follow this file first; its links identify the owners, not optional competing rulebooks. Do not assume `main`, infer permission from a proposal, or claim to have inspected inaccessible material.

**Change folder lifecycle (2026-11-22):** [Backlog](work/changes/backlog/README.md) is for future/deferred Changes, grouped by domain; [open](work/changes/README.md) is current/near-term and unresolved partially executed Changes; [archive](work/changes/archive/README.md) is terminal reconciled work. Never treat a Proposed backlog packet as Cursor-ready or create every future idea in open. Recheck source at promotion and repair links.

**Dev environment ownership and status:** A Git checkout is a source binding, not the durable identity of a Kubernetes environment. The integrated v2 CLI has `pnpm dev`, `dev:new`, `dev:status`, `dev:stop` and `--instance` selection; `dev:new` **still allocates and starts**, not reserve-only. **Unattended image/current-runtime readiness has not passed** on the unintegrated DXK09 branch. The selected [technical owner](docs/technical/platform/developer-environments.md) requires Tilt as sole active Deployment image writer; [operator runbook](docs/runbooks/dev-worktree-stacks.md) owns safe current commands, refusal and backoff. DXK10 reservation-only/selective profiles are **not implemented**; do not invent those commands.

**Scarce dev-runtime resources (current rule; lifecycle CLI enhancements proposed):** A Change/worktree does **not** require a running stack. Prefer source-only/unit tests; acquire a slot only when real integration proof needs it. Do not keep healthy pods running unnecessarily or launch a second full stack speculatively. Before starting inspect owned status and admission; never bypass the memory gate or commandeer another agent's environment. If an attempted launch yields a partially healthy stack, failed dependencies, resource admission/pressure, or OOM, promptly stop/park **only your own** workloads with the owned lifecycle command, preserve reservation and SQL/S3/Temporal tenants, confirm replicas/processes/ports returned to parked state, and report capacity contention. Do not leave the healthy subset consuming resources, endlessly retry, kill foreign processes, or remove the release lab. A queue is cooperative, not a global lock: back off and resume after capacity is verified. When DXK10 demand-driven reserve/activation commands are proven, use its explicit idle reservations and minimal dependency-closed profiles instead of automatically starting all six roles. [Runbook](docs/runbooks/dev-worktree-stacks.md) · [DXK10 proposal](work/changes/backlog/platform-operations/2026-11-23--dxk10-demand-driven-dev-lifecycle/CHANGE.md).

**Worktree developer environment:** [DXK09 worktree stack runbook](docs/runbooks/dev-worktree-stacks.md) is the current single owner of dev-only cluster/slot/reservation/freshness guidance and its honest T05 readiness gates. For an implementation Change, agents use the worktree-root development scripts **only after the current branch proves T05 commands available**; never silently fall back to the old shared `pnpm dev` / `pnpm stack:up` or release-lab cluster. Owner/lease records are machine-local, never Git-tracked. A stopped process does not release a slot's data or authorize tenant destruction.

## Mandatory implementation boundary

**Git:** One short-lived `change/<id>-<slug>` branch per commissioned implementation Change, created from the **actual recorded integration branch** before edits, not automatically `main`. A **separate linked worktree is mandatory for each commissioned Cursor Change**, even if it is the only chat. Never switch the user's primary checkout to a Change branch. No branch per T-ID. Parent integrates accepted work into that same reference branch and retires the temporary branch. Run the read-only pre-edit check `node scripts/repo-tools/change-branch-guard.mjs --change <ID> --target <reference-branch>` before dispatch; see [branch and integration owner policy](.agents/references/bounded-parent-orchestration.md#mandatory-change-branch-policy).

**Plan before paid execution:** Product docs ([docs/product](docs/product/README.md)) own selected behavior; technical docs ([docs/technical](docs/technical/README.md)) own guarantees; code/tests and [evidence](evidence/README.md) show what exists. Accepted new product/architecture contracts must be in their permanent docs **before** implementation commission. Planned implementation follows [Change work-unit standard](.agents/references/change-work-unit-standard.md) and [Composer task contract](.agents/references/composer-first-execution.md); unresolved architecture stays with ChatGPT. For ordinary implementation details and fixes to already accepted behavior, reconcile docs by closure, not via pointless pre-code rewrites.

**Recurring source health:** The [code-craft remediation program](work/designs/open/code-architecture-health/README.md) tracks source-architecture candidates. `pnpm repo:code-health` is the read-only AST growth report. A Change parent compares its source against the reference branch at closure with `--base` and, for newly crossed severe bands, `--strict-new`. Numeric hot spots trigger review, not automatic refactor.

**Code craftsmanship:** [One canonical quality standard](.agents/rules/code-quality.md) governs readable control flow, meaningful invariant comments, explicit boundary types, runtime validation, typed results, narrow responsibility and focused changed-file Prettier/quality-lint checks. Passing TypeScript or tests does **not** establish readability or security. Do not make Cursor produce opaque mixed-responsibility controllers merely because a packet specified working behavior.

**Execution readiness:** A packet is not Composer-ready merely because it has TASKS.md. Each selected T-ID must name exact write paths/symbols, a fully chosen edit, concrete positive/negative proofs and one contradiction stop; a multi-module move additionally needs an old→new ownership/export/caller/test migration map. Never delegate caller discovery, authorization composition, test-harness design or package-interface selection to Cursor under a `Ready` label. If those are missing, ChatGPT repairs the packet before dispatch. Read [Composer-first execution](.agents/references/composer-first-execution.md), [packet design](.agents/references/packet-design-manual.md), and the [adversarial readiness audit](.agents/references/packet-readiness-review.md) before declaring Ready.

**Cost and proof:** Cursor parent/children default to Composer Standard, use small assignments, focused tests and concise receipts; deep investigations/reviews belong to ChatGPT. Preserve real authentication, permissions, data integrity, idempotency, financial and provider-spend safeguards. `PASS`, `NOT RUN`, `source-inspected` and `live-observed` are distinct; never manufacture evidence. A Change is Done only when the accepted outcome and affected-claim reconciliation ledger are complete, with appropriate negative checks. [Budget policy](.agents/references/cursor-model-budget-policy.md) · [documentation rule](.agents/rules/documentation.md).

**Permissions:** Read-only investigation and authorized disposable local proofs are distinct from paid model calls, protected database mutation, deploys, destructive operations or secrets. The latter require explicit task-specific approval. Inspect existing work before changing files; do not reset, force-push or discard work for cosmetic Git cleanup. On an actual architectural contradiction, escalate its file/symbol and reproducer to ChatGPT rather than letting Cursor redesign.

**Parallel Changes:** Design independent Changes where practical; owner authorizes each. One integration owner serializes shared catalogs, status, technical headings, database migrations and final joins. Independent parents own their implementation branches; they do not concurrently rewrite the shared integration branch. [Parallel standard](.agents/references/change-work-unit-standard.md#batch-execution-and-parallel-change-orchestration-2026-11-19).

**Repository history:** Product/design decisions are retained in their owners, proof in evidence, terminal packets in short-lived archive/ledgers and Git. Do not keep historic design folders indefinitely. Commits follow [type(scope), Why and truthful Evidence](.agents/rules/git-commits.md). Use `pnpm repo:brief`, `pnpm wiki:find` / `wiki:read`, and targeted guards only as needed. [Architecture atlas](docs/architecture/README.md) is explanatory, not binding; [Engineering System Tour](ENGINEERING.md) is a human overview.
