# Design programs

**Owns:** multi-document design waves that combine product intent, technical proposals, evidence, and handoffs for one concern. These are **not** the product bible ([product](../product/README.md)), not technical contracts ([technical](../technical/README.md)), and not the Change queue ([changes](../changes/README.md)).

| Program | Path | Question |
| --- | --- | --- |
| Player UX | [experience/](experience/README.md) | What should create/play/return feel like? |
| Admin | [admin/](admin/README.md) | What should staff Support/ops control? |
| Engine | [engine/](engine/README.md) | What engine architecture realizes product rules? |
| Storyteller | [storyteller/](storyteller/README.md) | How should the adaptive Storyteller operate? |
| Observability | [observability/](observability/README.md) | How do we investigate real historical behavior? |
