## Concrete defects and confusion detected

1. **Wrong source path in the selected S3a plan:** it mentions `tools/chamber/scripts/story-session-report.mjs`, which does not exist on `main`. The report is actually at `scripts/repo-tools/story-session-report.mjs`. Its current code already describes result document changes, canonical document selection, request structure, generation/publication and funding metadata. A new agent should first isolate **missing** report evidence, not recreate an explorer.
2. **Old “current” statuses contradict actual scheduling:** several dossiers say active/implementing while their own checkpoints defer all new work behind S3 or require future human acceptance. An index must distinguish *legacy recorded status*, current selected code work, proposed design and evaluation.
3. **Conflated dimensions:** “Storyteller agency/taste” is quality acceptance; “memory exploration” often needs a connected experiment; “inhabitable play” begins with a storyboard. None becomes a code-bearing Change without selecting an implementation outcome.
4. **Partially repeated authority:** memory, canonical files, cost and activity plans overlap permanent technical specs. This is expected in long-running initiatives, but **do not load the whole plans as binding current design**. Use product/technical owners and only the specific legacy section needed.
5. **Dated implementation assumptions:** reviewed commits from September/October and historical run/check counts cannot certify present November source or services. Before a Change reaches Ready, revalidate its source entry and tests.

## Retention / retirement policy

**Keep now:** explicit owner-retained canon-invention dossier, selected Vvardenfell parent, other open design/architecture initiatives with unique unresolved decisions. A proposal awaiting owner feedback stays a proposal, not an implementation order.

**Shrink or eventually retire:** predominantly completed, evaluation-only, or duplicate-history dossiers (conservative evaluation, memory exploration, creative exploration, agency/taste, eventually bounded-cost) *after* verifying that their distinct decisions/acceptance and negative boundaries live in permanent authoritative documents. A small backlink or a preserved Git commit may be enough for history; do not replicate their full old PLAN into a new archive.

**No wholesale deletion in this pass:** the owner has not previously inspected these documents, several contain nuanced policy and evidence, and many relative links refer to them. Hiding them from the active work queue is safe; physically deleting/moving them without verifying unique content and inbound references is not. The [work-unit standard](../../.agents/references/change-work-unit-standard.md) defines the later migration gate.
