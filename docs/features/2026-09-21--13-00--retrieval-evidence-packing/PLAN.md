# Implementation plan

Feature: [Retrieval evidence packing](FEATURE.md).
Execution scope: approved provider-free packing and evaluation first; no compression-model call or maintenance inference.
Implementation owner: Codex under the owner's continuing instruction.

## Phases

### P1 — Multi-resolution packing contract — implemented

- Outcome: typed evidence items expose stable identity/group, authority/provenance, requiredness, utility and ordered compact/card/exact representations with measured bytes.
- Owners: retrieval contracts and application provider-free packer; canonical text remains external authority.
- Selection admits required evidence first, then group-diverse optional bases, then fidelity upgrades by marginal utility per byte. Exact duplicate bodies/provenance are emitted once.
- Exit: deterministic packs explain every selection, upgrade, deduplication, omission and mandatory overflow.

### P2 — Density and breadth evaluation — implemented

- Outcome: extend the fixed oracle with 20-person/5-place/15-node assembly pressure and stage-separated pack measurements.
- Measure required-fact/provenance recall, group coverage, unique useful bytes, duplicate bytes removed, density, selected fidelity and omission—not just total size.
- The pressure fixture begins after authority, branch, visibility and relevance filtering. Its forty items are all eligible and useful, so this phase diagnoses allocation rather than disguising a retrieval failure as a packing result.
- `usefulDensity` is unique selected evidence-body bytes divided by exact serialized packet bytes. `groupCoverage` is selected stable groups divided by eligible stable groups. Required recall counts required item identities only when their selected representation meets the declared minimum; source recall independently requires every selected required item to retain all declared source keys. Duplicate bytes compare the serialized factored packet with the same selected evidence serialized inline, while raw duplicate content/source-key byte counts remain separately inspectable.
- Posture comparison keeps the fixture fixed and varies only explicit byte/item/group limits. Reports include fidelity and omission counts so a larger packet cannot appear better merely because it contains more bytes.
- Exit: minimal, balanced and rich postures show explicit breadth/fidelity tradeoffs under fixed final packet caps.

### P3 — Cards, episodes and exact expansion

- Outcome: feed source-grounded identity/place/thread/episode cards into the packer and expand exact sources only for declared needs.
- Adapt only evidence already admitted by the captured exploration root: search/registry results provide optional leads, explicit memory reads provide required cards and explicit source reads provide required exact evidence. The adapter performs no inference, summarization or provider call.
- Stable document/revision/hash identity is the packet provenance. Logical kind selects only a generic packing group; it does not create game entities or reinterpret lore as mechanical state.
- Optional query-focused synthesis is a separately budgeted representation producer, not an invisible packer side effect.
- Exit: the connected Greywake return uses a packed final context and traces downstream evidence use.
