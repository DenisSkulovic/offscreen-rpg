## Meaning of the results

- **Retire** never means blindly delete unique facts. It means extract durable material, retain a Git provenance pointer and remove the temporary container.
- **Reconcile** means inspect every relevant section and align it to one existing or new owner. No bulk rename that leaves duplicate rules.
- **Program folders** are rejected as permanent mixed-authority containers (product + technical + evidence + handoff), even if some child files are excellent.
- **Archive and packet leaf directories** are not independently justified as *permanent* documentation; a compact immutable completion ledger and Git history replace full in-tree archives.
- **Evidence and evaluations** may be retained in a separate revision-bound evidentiary system if reproducibility, legal, privacy or incident requirements justify them.

**Limit:** this register fully audits the *tree structure*. It does not pretend that a filename proves semantic duplication. The [file-level register](FILE-DISPOSITION.md) is the input for the subsequent full claim-level reconciliation.
