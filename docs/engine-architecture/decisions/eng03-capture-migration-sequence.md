## What should generalize

**One reusable materialization mechanism, several distinct admission policies.** Reuse the ENG03-narrow application-private capture storage, validated envelope, bounded lease/retry policy, immutable CAS-by-hash loader, exact source frontier and request digest, **one provisional generation G promoted in-place** to a normal storyteller.profiled.v1 task, short locked promotion/publication, and existing generation / storyteller_publication / story_resolution / outbox / Temporal execution. Shared capture records may use a discriminated union of purpose-specific **strict** Zod schemas; do not alter the existing storytellerTaskSchema task union, old generation inputs or paid-attempt IDs. Capture is an immutable input snapshot, not a second game-state authority.

Keep **SQL lock stages short**. Stage 1 copies every mutable model-affecting SQL value, eligible source passage ID/sequence and content hash or inline content, settings/profile/execution/effective usage policy, bounded context/continuity and local identity. It records G + durable wake atomically. Stage 2 reads only immutable CAS by captured hash and builds exactly one bounded request outside the story lock, without rereading "current" campaign facts as prompt inputs. Stage 3 briefly checks narrative/actor/receipt/scene/root eligibility and publishes through existing CAS/uniqueness gates. Revalidate live commercial authority at the established dispatch boundary; a captured policy may **limit**, never authorize newly forbidden spend. Missing source means held/blocked, not fictional fallback. Unsent materialization may retry within a fixed bound; a possible/confirmed provider send cannot silently cause a second paid generation.

## What must remain purpose-specific

The **purpose fixes what the model is allowed to claim, what the authoritative receipt is, and what "stale" means**. A pending consequence is a private projection until exact settlement; a committed consequence describes a completed receipt; an interrupted consequence describes a verified interrupted transfer or controlling interruption; a continuation interprets an accepted interaction from the published source generation; a report is tied to a historical hook and may publish after current-scene revision moves; an opening is a draft candidate governed by draft revision, not a story-resolution slot. Never shoehorn all six into the pending-consequence schema or stamp every late result "stale." Source selection also differs: continuation can use selected world sections/campaign documents and generated choice provenance, reports have source-specific roll/effect summaries, opening depends on start-package manifests.

**Non-goals:** no generic saga, bus, new Temporal workflow, storytellerTaskSchema union rewrite, cloud S3 cutover, destructive migration/backfill, automatic paid retry/regeneration, game-rule/time/dice/item-holder changes, generalized historical-source rebase, or provider spend. Context capture does not grant permission to alter what an accepted game command means.
