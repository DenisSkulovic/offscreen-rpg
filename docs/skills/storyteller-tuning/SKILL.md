# Storyteller tuning

Use the [working agreement](../../../.agents/rules/working-agreement.md#agent-and-prompt-tuning-discipline) for ownership and the [tuning manual](../../engineering/storyteller-tuning.md) for evidence, rubrics and experiments. Spending and verification remain governed by repository rules. Tuning means application/configuration experiments, not model weight training.

## Diagnose before changing

Turn the complaint into an observable expectation for this profile, campaign and selected intention. Read the current feature checkpoint. Inspect the smallest useful trajectory: offered intention and private plan → accepted resolution → exact captured request → raw response → admitted/published result. Use `pnpm story:inspect <story-id>` after reviewing its read-only call path. Inspect private evidence locally; never commit provider packets, credentials or player prose. If an artifact is inaccessible, identify the missing link and narrow the conclusion.

Separate observations, owner judgment, hypotheses and unknowns. Locate the earliest deficient boundary. An action that only approaches an NPC cannot be repaired honestly by a consequence narrator pretending the conversation resolved. A funding stop is not bad model reasoning. A valid response is not proof of agency or enjoyment.

Before editing, identify the owning layer and a legitimate contrasting case. Shared instructions own supported authority, evidence and output contracts; rhythm, tone, initiative and normal choice character belong to captured profile/settings data. Campaign direction, time/rules, model policy and presentation have separate owners. Confirm effective saved settings reached the exact request; current catalogue text does not establish what an earlier call received.

## Make the next experiment discriminating

Record one falsifiable hypothesis, one changed variable, fixed inputs, expected improvement, unacceptable regression, retained evidence and cost/stop bounds in the active plan. Use the manual's compact record; do not create an evaluation framework by default.

For model comparison, hold packet, schema, profile, source state, reasoning mode and output allowance constant apart from declared transport/model differences. Validate private candidates through the normal validator without publishing into the source story. Opening/planning comparison measures proposed actions; replay from a bad committed receipt measures only downstream narration. Preserve failed trials and include a quiet or abstract contrast before broad adoption.

Do not require repeated cheap-model failures before a bounded stronger-model probe. Do not silently widen funding/operation limits or switch the live default. Check current endpoint support, prices including cache writes, account liability and the exact envelope. Respect existing authorization; preparation does not itself authorize spend.

## Decide and preserve

Return separate verdicts for authority, intent fulfillment, profile/campaign adherence, choices, continuity, time, latency/cost and owner preference. Cite concrete evidence for material failures. One response is exploratory evidence, not a reliability estimate.

Adopt only the narrow supported change; otherwise retain the baseline or leave the finding unresolved. Update the owning specification and feature checkpoint with one exact next action. Significant runtime changes follow feature-workflow and the established implementation owner. Leave shared prompts alone when evidence points to configuration, missing mechanics or an unresolved product contract.
