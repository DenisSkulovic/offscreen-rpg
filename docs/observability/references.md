# Industry references | Observability, privacy, replay and forensic reliability

**Reviewed 2026-11-15.** This is a focused external-practice evidence list, **not** a claim that tools are installed or legal counsel has approved retention. Our [product target](product-vision.md), [repository source audit](evidence/current-source-inventory-2026-11-15.md) and [technical decisions](technical/evidence-model.md) govern design choices. Sources are maintained by the named standards projects/vendors; versions change. Revalidate SDK APIs and deployed documentation at implementation.

| Primary official source | What it establishes | Offscreen RPG architectural inference / caution |
| --- | --- | --- |
| [OpenTelemetry: GenAI semantic conventions for spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md) | Model instructions, user messages and outputs may be sensitive/large; instrumentation **should not record content by default** and uses explicit content-capture control | Export **metadata-only GenAI spans** by default; protected byte-exact model packets belong in **native policy-governed evidence**, not every tracing vendor |
| [OpenTelemetry: concepts and sampling](https://opentelemetry.io/docs/concepts/sampling/) | Head sampling decides early; tail sampling may select error/latency-specific traces after considering most spans | Use error/slow/uncertain signals to prioritize OTel traces; **neither sampling nor collector delivery is business history** |
| [OpenTelemetry Collector resiliency](https://opentelemetry.io/docs/collector/resiliency/) | Queues, retries and optional `file_storage` WAL reduce loss, but loss still occurs after overflow, expiry, crash or disk failure | A robust Collector is valuable yet cannot be sole custody for a player incident; monitor exporter queues/dropped spans |
| [Prometheus instrumentation best practices](https://prometheus.io/docs/practices/instrumentation/) | Excess label combinations create time-series cardinality, storage and CPU/network cost | Do not put `storyId`, `userId`, `generationId`, free-form prompt/packet hashes or trace IDs into metric labels |
| [Prometheus metric and label naming](https://prometheus.io/docs/practices/naming/) | Label combinations are separate time series, units and metric structure matter | Use bounded enum dimensions with seconds/bytes and histograms/counters; inspect cardinality before production rollout |
| [Grafana Tempo: link traces, logs, metrics](https://grafana.com/docs/grafana/latest/datasources/tempo/configure-tempo-data-source/) | Tempo data source can correlate spans with Prometheus metrics, Loki logs and profiles | Excellent system-level drilldown. Let **native Admin** show game/context provenance and link out to the precise Tempo span |
| [Grafana trace-to-logs correlation](https://grafana.com/docs/grafana/latest/datasources/tempo/configure-tempo-data-source/configure-trace-to-logs/) | Bidirectional trace/log links require matching shared trace identifiers and explicit configuration | Join process signals using trace IDs, **not** “all process log lines for a story” as permanent investigation |
| [Temporal: Workflow replay](https://docs.temporal.io/workflows) | Workflow Event History drives deterministic code replay; completed Activities return recorded results instead of rerunning side effects | **Temporal Replay ≠ game-story playback**. Game mechanical state still requires authoritative game deltas/checkpoints |
| [Temporal: Activity idempotency](https://docs.temporal.io/activity-definition) | Activities may retry if completion is not recorded; idempotency is essential for business side effects | Do not let evidence capture duplicate paid model attempts, rolls, item transfers or receipts on redelivery |
| [RFC 8785: JSON Canonicalization Scheme](https://www.rfc-editor.org/rfc/rfc8785.html) | JCS provides deterministic canonical bytes for the I-JSON subset; long integers and special runtime types need explicit mapping | Archive validated same-shape JSON data with a versioned codec, but hash **actual provider wire bytes separately**; do not assume generic `JSON.stringify` is a lossless universal archive |
| [PostgreSQL explicit locking](https://www.postgresql.org/docs/current/explicit-locking.html) | `FOR UPDATE` blocks conflicting same-row writers until the transaction completes | Co-commit a **small** typed transition under story lock; never do remote CAS/telemetry I/O while the lock is held |
| [Grafana Tempo 3.0 configuration/deployment](https://grafana.com/docs/tempo/latest/configuration/) | Monolithic mode runs without Kafka; microservices mode uses a Kafka-compatible durable queue | Favor optional simple local tracing topology, not introducing Kafka solely for debug infrastructure |
| [Grafana Tempo ingestion limits](https://grafana.com/docs/tempo/latest/operations/manage-trace-ingestion/) | Rate/size/live-trace limits can cause spans to be partially discarded or lost | Never let Tempo act as the only custody for a paid model attempt or player event |
| [OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet) | Secret/personal/security data should be excluded or minimized; logs need protection against misuse, tampering and failures | Avoid raw prompt/player text in normal logs and spans. Use narrowly authorized, encrypted, retained private artifacts and immutable access audit |
| [European Commission: Principles of GDPR](https://commission.europa.eu/law/law-topic/data-protection/information-business-and-organisations/principles-gdpr_en) | Purpose limitation, data minimization, storage limitation, confidentiality and accountability | Retain player-published history for its actual product purpose while separately limiting raw AI debugging bodies and staff access; avoid “all data forever” |
| [European Commission: rights of data subjects](https://commission.europa.eu/law/law-topic/data-protection/information-individuals_en) | Access, erasure, portability, objection and other rights affect stored content | Deleted story, audit exceptions, shared game and incident holds need explicit lawful lifecycle and cross-store propagation |

## Tool-selection challenges

**OpenTelemetry is a standard, not a storage promise.** Use its semantic conventions, span links, instrumentation context and metrics. Do not embed entire sensitive prompt objects into `gen_ai.input.messages` by default, especially with downstream hosted collectors. The [source audit](evidence/current-source-inventory-2026-11-15.md) found no inspected configured OTel stack.

**Prometheus is an aggregator, not a forensic archive.** Grafana/Prometheus cannot reconstruct whether a specific player earned six coins at an earlier fictional time, which exact rule was used, or which memory excerpt entered a model packet. Those are immutable domain evidence questions.

**Grafana, Tempo and Loki are observability surfaces.** They are suitable for time series, latency, service topology, traces and error log search. Their raw logs are not a humane product Support console and do not replace subject-scoped Admin authorizations.

**Langfuse/LangSmith-class tools are optional integration candidates**, not prerequisites or a reason to adopt a framework. A model-workflow dashboard may be useful for prompt management/evaluation; the game must still independently retain immutable source/attempt identities and its player history. Evaluate privacy, pricing, vendor retention and exact packet interoperability before selecting one.

**Temporal's notion of replay is narrower than the user's replay dream.** It restores workflow orchestration. An actual historical scene playback is a separate domain read model, and deterministic mechanical re-execution requires recorded inputs/entropy/time and isolated sandbox semantics.

**Legal retention:** neither “30-day raw packet” nor “keep years of replay” is established by an industry logging standard. They are product/security decisions constrained by lawful purpose and measured cost. The [retention policy](technical/replay-retention-and-privacy.md) proposes candidate terms only, not a legal verdict.


**2026-11-15 wave-2 source cross-check:** PostgreSQL row locks remain transaction-scoped, so capture should minimize story-lock work; RFC 8785 is appropriate for strictly JSON-safe deterministic hashing but not lossless archival of arbitrary JS objects; Grafana Tempo's current monolithic mode does not require Kafka and its ingestion limits can drop trace content. These details strengthen the chosen native evidence + optional OTel architecture. No infrastructure version or SDK compatibility is selected by this note.
