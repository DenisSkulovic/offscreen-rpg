### 07. Source review and important corrective findings

**Observed/reviewed:** Next 16.3.5 / React 19.3.0, App Router server routes with private no-store Nest reads, strict Zod DTOs, owner-checked Nest endpoints, React client feature screens, Play/Chamber polling, forms/list pagination, integrated Playwright tests, existing GitHub Actions/strict TypeScript. **Findings changing the earlier seven-slice plan:**
- `OpeningPreviewPanel` reuses a Start story UUID after uncertain completion but rebuilds the campaign/preview body from current UI inputs. A retry with changed settings can carry a different payload under the same operation identity; a frozen Start envelope/reload contract merits a new Change, not a generic “clean up”.
- `PlayScene` and `useCampaignCommand` have in-memory stable UUID refs, but those are lost on reload. The UI must distinguish refreshing server-owned progress from guaranteed replay of an original intent. Never promise exactly-once from browser state alone.
- `preferNewerSnapshot` compares version numbers without verifying story identity; Play/history/settings have distinct remount, late-response and unsaved-data risks. Source shows missing guards/potential failure paths, **not** a reproduced cross-user leak.
- `SessionRefresh`, SSR cookie forwarding and same-origin Nest reads are valuable, but deployment rewrite and actual private RSC/router-cache behavior have not been proven. Story list fetch currently serializes two independent initial reads.
- `CampaignPlay` is large but not automatically wrong; stronger evidence is ownership coupling and preview importing a Play Client module only for pace constants.
- Lists/history differ in replace/append and abort policies; campaign settings are keyed by revision and may lose local drafts; QA run ID browser hint is not auth and should be viewer-isolated.
- Chamber Nest tools currently require authenticated ownership, **not a distinct developer-role check** in the inspected controller. Whether Chamber is local-only/self-service/restricted is a product/security deployment decision; hiding UI cannot secure the endpoint.
- Fast web-local component/race tests do not exist, but real integrated browser tests, CI and strict TS already exist. Preserve and layer those proofs instead of replacing them.

**Final stack/design choices made and recorded in [selected target](../engineering/targets/react-next.md):**
- React 19 + Next 16 App Router with private server-only Nest reads, route-group auth and per-request QueryClient SSR prefetch/dehydrate/`HydrationBoundary`; client Query provider only for authenticated area.
- TanStack Query v5 as **sole browser cache for remote data**, viewer/resource-specific keys, domain-monotonic story reconciliation, `useInfiniteQuery` for lists, explicit stale/refetch/GC/invalidation policies, no private persisted query cache.
- TanStack `useMutation` for HTTP transport with **no automatic retry/reconnect replay**; explicit typed command intent state machine, stable immutable UUID/payload, session-scoped minimal recovery reference, added owner-scoped read-only operation receipt GET for expensive story resolution.
- React Hook Form v7 + `@hookform/resolvers/zod` for draft/settings/preset edits; dirty/value/revision semantics and deliberate form reset, no accidental background replacement.
- Authenticated Nest SSE committed-version invalidation hints using PostgreSQL `LISTEN/NOTIFY`, with Query re-fetch, missed-event correction, 30s safety poll when healthy and 2s fallback while pending when stream unavailable; no WebSockets/RabbitMQ/Redis for the mere presence of realtime.
- Strict TypeScript and React/Next/TanStack lint; Vitest/RTL/user-event/MSW, Playwright + axe, Storybook for deterministic state presentations, existing CI plus real backend integration.
- **Chamber developer-only**: hosted API endpoints denied by default unless developer policy/allowlist, owner checks retained, browser run hint partitioned by viewer. Not secured by hiding a React link.
- No extra Redux/Zustand/XState, no CSS/Tailwind/shadcn visual rewrite, no gameplay expansion, no experiment-only library adoption. These are **rejected because redundant or outside scope**, not left for Cursor.

**Rationale:** Professional frontend architecture requires explicit ownership, auth/SSR/cache lifetimes, conflict/recovery semantics and testable operational boundaries. Paying the justified cost of a proper coherent stack is preferable to preserving avoidable ad hoc hooks merely because they already exist. Deciding up front does **not** make unneeded abstraction or unmeasured performance claims good engineering.
