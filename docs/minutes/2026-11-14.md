## Admin product vision and documentation-first handoff

### Owner direction

- Design a **mature internal Admin platform** for Offscreen RPG as if serving thousands of real free/paying customers; do not let vibecoded current code limit the desired end state.
- Support, Customer Success, Engineering, Business, Marketing and other professions must be **overlapping responsibilities**, with granular/composable access, conceptually inspired by IAM.
- Account management and inspection, user tiers, allowances, delegated/impersonated player viewing or controlled action, and ability to invite/authorize staff are important product needs.
- Process is explicit and **strictly sequenced**: settle **product design**, then **technical design**, then prepare code-bearing Markdown **Change folders**; hand implementation to Cursor only when the design/handoff is ready.
- Existing Cursor implementation on main should not be interrupted by an unrelated Admin redesign.

### Proposed product interpretation, not yet owner approval

- Internal operating product with distinct player/staff identity, ten logical workspaces, shared Player 360 and resource context, cases/actions, granular capability packages and risk-based governance.
- Three separate modes: read-only player preview, limited assisted session, isolated sandbox investigation.
- Game/Storyteller forensics, AI unit economics, subscription/entitlement/allowance separation, LiveOps, Trust/Privacy and audit/approvals as first-class Admin domains.
- **These details are recommendations pending owner review**, not technical decisions or permission for code.
