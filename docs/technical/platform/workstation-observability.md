# Workstation observability | local infrastructure flight recorder

**Selected direction, 2026-11-24. Target, not implemented.** Owner requests persistent evidence independent of any development attempt, including sub-second memory observations, peaks, attribution, historical queries and explicit blind spots. This is workstation infrastructure, not the application's disposable release OTLP debug collector. Canonical implementation location: `infra/monitoring/`. No dependency on game, Kind, Tilt, Node/pnpm builds, remote metrics store or Kubernetes monitoring deployment.

## Architecture and authorities

- Native Linux Netdata Agent v2 (local dashboard, native host collectors and dbengine tiers); atop-compatible historical process accounting is useful but **raw atop logs can include full command-line arguments**. Do not enable raw atop automatically. Default process history is the safe allowlisted /proc sampler below. Optional native atop raw logging, only after explicit acknowledgement of local sensitive argv retention, root-only vendor files, never exported by our command. Use kernel exit accounting if already available/authorized; absence is a coverage gap, not zero exits. No custom eBPF or kernel module installation.
- A small Python 3 standard-library companion, installed to stable /usr/local/lib/offscreen-monitor, outside worktrees, records only evidence that native metrics cannot provide: sub-second host memory windows, safe process identity, nested Docker/Kind snapshots, operation events and coverage. Native Netdata is the metrics database; the companion is bounded append-only JSONL, not a replacement TSDB or custom dashboard.
- Separate native Netdata service and `offscreen-monitor@USER.service` systemd unit running as the actual operator (not root). Stable per-user state `$HOME/.local/state/offscreen-monitor` (0700) with private data 0600; installed config /etc/offscreen-monitor/USER.json contains absolute paths, username, selected Docker context, explicit local kubeconfig path, no copied credential content. No environment inferred from current worktree. No root/Docker socket added permissions, no container privileges or cluster installs. Netdata local loopback 127.0.0.1:19999, no cloud claim/streaming/remote exposure, disable anonymous telemetry using vendor-supported opt-out. Host installation and service activation separately authorized; no WSL/Docker restart or .wslconfig changes.
- Native systemd persists across process exits, boots when distribution boots. It does **not** keep WSL alive; WSL shutdown/suspend, clock changes, Docker daemon disappearance, inaccessible /proc, kubeconfig denial and collector crash must appear as unknown coverage/gaps. Windows host metrics (physical RAM, VmmemWSL, pagefile) separate future boundary; do not describe Linux MemTotal as physical Windows RAM or assume Ubuntu procfs includes Docker Desktop internals. Docker and both exact local Kind contexts via read-only interfaces, never ambient kube context, never production/staging endpoints.
- Query/export uses local Netdata REST and private supplemental records; use native dashboard for native series, CLI for correlated historical evidence. No extra Grafana/Prometheus/OTel stack.

## Clock, schema and measurement semantics (v1)

Each supplemental record has schemaVersion=1, kind (host_window|host_rollup|process_snapshot|docker_snapshot|pod_snapshot|cgroup_snapshot|coverage|operation), collectorSession UUID, source, scopeId (installation identity + boot identity + runtime boundary), observedAt UTC ISO 8601, monotonicNs decimal string (actual collector CLOCK_MONOTONIC ns), sequence monotonic per stream/session, source timestamp where supplied, units explicitly defined. Capture wall time and monotonic together; use monotonic elapsed for intervals, wall for cross-process timeline with explicit clock-jump detection (>1s change in wall-minus-monotonic offset); reboot/clock discontinuity separates segments. Missing/unreadable/timeout/unsupported/stale/absent distinguished; no missing-to-zero, forward fill across gaps, or fabricated time precision. Scope IDs stable per installation; boot ID from /proc/sys/kernel/random/boot_id, process key=(scope, PID, /proc/PID/stat starttime ticks), container key=(Docker daemon ID or verified local context identity, full container ID), pod key=(cluster identity, namespace, pod UID), container restart identity full CRI ID and start time; never join on reused PID/name alone. Do not sum parent and descendant cgroups, Docker node and pods, RSS and cache, WSL guest and Windows VM. Record memory.usage vs working set vs RSS vs PSS as separate measures.

Host fast path: read /proc/meminfo at 200ms monotonic scheduled ticks, five observations per nominal 1s window; only MemTotal, MemAvailable, MemFree, AnonPages, Cached, SReclaimable, Shmem, SwapTotal/SwapFree, Dirty/Writeback; KiB→bytes, absent field null. Retain actual offsets and values, start/end monotonic & UTC, scheduledCount, observedCount per metric, observed min/max/sum/count/mean, max intersample gap, collection error and duration. No claim of exact extrema between samples. On delay skip missed deadlines, never manufacture catch-up samples; flush partial window with reason. Sample mean = sum/count; merge using sums/counts, never unweighted average of means. Time-weighted average only when explicitly computed from observed interval durations and labeled estimate, not invented from gauges. Roll up fast windows by fixed monotonic 60s and 3600s buckets within session/boot clock segment; preserve min/min, max/max, sum/count, expected/observed counts and coverage; partial bucket explicit. Retain raw fast windows and rollups separately. Each gauge peak is an **observed** max. Kernel /proc/PID/status VmHWM, cgroup v2 memory.peak, memory.swap.peak are lifetime/since-reset high water if available, label scope; never reset kernel peak counters, infer within-second exact peak time or equate highest observed RSS with memory.peak. Cgroup memory.events/local, /proc/vmstat oom_kill, PSI total counters, container restart/termination timestamps are separate cumulative/discrete evidence. A 500ms event can be missed even by 200ms polling, so use counters/events/peak fields and disclose residual blindness.

Native Netdata base interval 1s, RAM/CPU per-core/load/runqueue, swap, VM counters, pressure, disks, filesystem, network, collector self-metrics. Counters preserve underlying absolute values when companion collects them, delta=(end-start) only for same identity and nondecreasing counter, elapsed actual monotonic, counter reset/new identity emits reset (no negative rate). Native rate charts are interval averages, not instantaneous maxima. Netdata rollups preserve native sum/min/max/count; use correct min/max group and tier resolution, never report min of means as raw minimum. In report distinguish observed sample extrema, kernel HWM, interval counter rates, event counts. If vendor API does not expose exact sample count/coverage at a tier, report unavailable rather than infer it from points.

Process snapshot 5s: all visible PID entries, read stat/status/io/cgroup allowlisted fields (comm, PID, PPID, start ticks, state, RSS/VmHWM, user/system CPU ticks, read/write bytes, threads, voluntary/involuntary switches, cgroup path only if not sensitive). Parse stat by final ')' before numeric fields; validate same PID/start ticks after reads; races = exited/missing, not zeros. Use /proc/PID/smaps_rollup PSS only for top 10 sampled RSS processes at 30s, access denied recorded; do not sum RSS as true memory. Safe categories (node, tsc, pnpm, tilt, dockerd, buildkit, etc) via comm/exe basename and in-memory exact allowlisted argv token basenames, never persist full command line, argv, environment, process cwd, arbitrary labels, raw inspect bodies, request logs or credentials. Process exit between samples may be invisible absent kernel accounting. Native atop optional separately consented local only. Atop exit-accounting blind spot explicitly report. Do not record player/story data.

Runtime boundary: Docker CLI pinned context, read-only `docker --context CONTEXT stats --no-stream --format '{{json .}}'` (working-set-like cache-subtracted MemUsage, not cgroup raw), full ID from `docker ps --no-trunc` and inspect only safe name/start/state/image fields. 5s target, one in-flight cycle, 2s timeout; source timestamp/time range and stale/coverage explicit. Kubernetes `kubectl --kubeconfig PATH --context kind-offscreen-dev|kind-offscreen-lab --request-timeout=3s get --raw /api/v1/nodes/NODE/proxy/stats/summary` for known exact node names only after context identity verified (reuse profile constants/Kind labels, no ambient fallback). Summary API node/pod/container CPU usageCoreNanoSeconds/usageNanoCores, memory usageBytes/workingSetBytes/rssBytes, network/filesystem as exposed, source measurement timestamp. 10s target staggered per node; actual kubelet update cadence may be slower, preserve repeated/stale timestamps. Read-only pod metadata/status every 10s, select UID/owner workload/container IDs/start/termination reason/exit code/restart count/requests and limits only; events watch with resourceVersion and relist/reconnect gap, allowlisted reason/type/object UID/timestamps/count, no free-form messages. No metrics-server installation. Read cgroup v2 peak and events via one bounded batched docker exec per verified Kind node (read-only, 10s, no workload process spawn inside app pods); exact container IDs from pod statuses, match unique cgroup directory ending cri-containerd-ID.scope or ID, verify node ownership, read memory.current/peak/events/local/stat/swap.current/peak, cpu.stat, io.stat and PSI where present, report unavailable if unsupported/ambiguous/deleted. For per-process inside selected Kind node container use cgroup.procs and allowlisted stat/status reads with identity fencing; bounded top process collection, do not persist arbitrary command lines. Do not force privileges or mount host filesystem into new containers. If cgroup mapping not available, preserve summary metrics and gap. Pod/container identity and parent scope are mandatory, not merely display names.

## Persistence and limits

Local Netdata config: [db] db=dbengine, update every=1, storage tiers=3, native default 60x rollup factors; target tier0 72h/1GiB, tier1 30d/512MiB, tier2 90d/512MiB. Support v2 retention size/time keys only; installed incompatible version reports blocked, no blind install. Vendor limits soft; verify actual retained span/usage. Supplementary budget: fast 512MiB (72h raw + 30d minute +90d hour envelopes, subbudgets 384/96/32MiB), process 1GiB (7d), runtime 768MiB (72h), operations/coverage 256MiB (30d). Reserve 512MiB for metadata, rotation and overhead; total target 5GiB, not absolute hard cap for vendor storage. Warn at >4.5GiB actual total, stop optional high-cardinality sampler on sustained >5GiB or filesystem free <2GiB, keep minimal health/coverage and report storage-limited; do not delete vendor DB manually, unrelated data, or silently change cadence. Optional atop raw logging must fit process budget or remain off. Supplemental streams fixed hourly segment files with bounded size (rotate at 16MiB within hour), append O_APPEND with one writer/stream (operation records per emitting PID/start or unique attempt file), JSONL records max 64KiB, split snapshot into one record/entity + coverage summary, atomic writes under private directory, fsync every <=5s and on normal stop; tolerate truncated last line and record crash-tail uncertainty. Cap bytes+age by deleting oldest closed **owned** segments only, never active, symlink or outside root, never raw vendor files. Expose oldest/newest, count, gaps, actual cadence, version, disk bytes and suppressed streams. Store bounded local archives, no Git-tracked raw history; explicit export only, normalized allowlisted data, no raw atop or secrets. Preserve health and gap metadata under pressure. No resampling across missing windows.

Observer overhead acceptance target: 15min comparable idle baseline before/after, native+companion combined median CPU <=1 logical core-percent (one core =100%), p95 <=5% of one core, <=300MiB measured incremental private memory/working set (account nested correctly); these are targets, not guarantees. If exceeded, report measured cost, tune native enabled collectors and optional poll cadence 5→10→15s, preserve fast memory & failure events when feasible, disclose reduced resolution. Bound each command/output, no accumulating subprocesses, no retries faster than cadence. Critical memory pressure (MemAvailable below 4GiB) monitoring remains lightweight, optional PSS and nested exec suspend with explicit coverage, no change to admission guard or cluster state.

## Historical interfaces and acceptance

`pnpm infra:monitor:status`, `pnpm infra:monitor:report --last 30m` or `--from ISO --to ISO [--slot dev-N] [--json]`, `pnpm infra:monitor:export --from ISO --to ISO --out PATH` use stable installed state, not worktree-specific histories. CLI report local data only, explicit evidence and coverage per source/time, resource peaks and exact scope, overlapping operation spans, top consumers per layer, unknown if unsupported. Export normalized versioned manifest + JSONL/CSV, no credentials, no raw argv, cap 100MiB and refuse incomplete output unless explicitly narrow window; output outside tracked tree or caller path explicitly ignored. Native Netdata dashboard local only. Report correlation is temporal evidence, not automatic causality. Full state and collectors survive distro service restarts; no fabricated historical data. Reproduction uses lightweight fixture spike and synthetic counter resets, missing samples, overlapping phases, PID reuse, stale source timestamps, partial final record, rotation/disk budget, service restart gap; live optional host verification separately authorized. A real INF29 rerun is not prerequisite for source acceptance.
