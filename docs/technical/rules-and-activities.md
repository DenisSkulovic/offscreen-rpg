# Rules, admitted actions and storyteller consequences

The implemented mechanical slice uses offer-local private immediate-action plans and the existing storyteller execution/publication lifecycle. It remains an authored, offline slice. Opening and consequence tasks now return freshly validated plans, but their scripted source recognizes only controlled benchmark state; this is not general model adjudication or world understanding. Combat, private encounter disclosure and the bounded planning agent are not implemented. Those limits do not change the product requirements in [Game rules](../game-rules.md).

## Content and authority

`@offscreen/game/immediate-actions` currently owns the private playable-plan envelope: a task-local key, public label and intention, optional risk copy, evidence handles and prerequisites. Its resolution is an immediate automatic/check outcome, one admitted contribution-process definition, or a fenced request to resume a named interrupted action. The module name is historical; the public projection remains the same opaque attempt in every case. Plans contain no executable expression or tool name. The current fixture package admits up to six plans; that is an implementation bound, not a theory of player agency.

The pure proposal validator returns bounded structured diagnostics rather than throwing model-facing prose. It rejects malformed packages, duplicate or out-of-scope evidence handles, undeclared prerequisite/effect targets and situational advantage, disadvantage or modifiers that lack a supported grounding rule. It never persists, rolls or applies an effect. Fixture admission uses the same semantic validation; the later `validate_action_package` tool will call this policy rather than implementing a second validator. Ability and skill admission checks the captured capability sheet; generated setup and capability-changing transitions remain unimplemented.

`contracts/campaign.ts` defines the selected D&D ability-check subset, character state, commands and receipts. The six abilities and HP belong to this selected rules subset. Named skill proficiencies come from content. Quantities are optional. Character facts support form/capability conditions and may only be updated after declaration. A separate bounded story-fact collection records durable situation/world truth established by play. Immediate outcomes introduce one only through an explicit declaration effect with evidence; duplicate or conflicting declarations are rejected rather than treated as updates. Quantity minimums and fact prerequisites are rechecked before any roll. This is a small typed effect vocabulary, not arbitrary world simulation.

The selected D&D ruleset currently captures all six ability scores while the character's present capability sheet declares which abilities and skills actually apply. Species, body plan, scale and setting never select a code path. A future character/world planner may propose the capability sheet from the authored premise and committed transformations; deterministic admission must validate that proposal before any check can use it. Proficiency must reference the captured skill catalogue. Action admission rejects a check whose ability is unavailable or whose skill is undeclared. Form changes and capability mutation are separate admitted state changes, not ordinary immediate effects in this slice.

Opening admission explicitly selects an authored seed from a validated content catalogue. Scenario identities, inhabitants, prose, skills and starting facts live in content records; the loader has no premise-keyword, species or profile branch. The task captures the selected character, opening and facts, then the Storyteller result proposes fresh private plans. Mechanical preview exposes each plan's label, attempted intention and optional apparent risk while retaining DCs, branches and effects privately. Start uses the exact accepted plans without rereading the catalogue or regenerating them.

## Admitted action and time

The player submits an offer identity and path, never replacement mechanics. A public leaf exposes a label, attempted intention, optional apparent risk and only `{ kind: "attempt" }` as its action payload; its ID is an opaque reference within that offer. `game_offer` stores the private plans under the same offer identity, story and narrative revision. Under the story lock, admission checks command deduplication, current revision, absence of unresolved narration, exact current offer, private-plan fence, prerequisites and active commitments. A fabricated or stale public selection cannot recover a plan or roll.

Immediate settlement directly commits a durable action receipt, optional roll, effects, updated character, consumed offer, command receipt and outbox follow-up atomically. It creates no zero-duration activity and advances no tick. Storyteller context preparation happens afterward from the saved receipt. A preparation failure therefore leaves the admitted result visible and retryable without another roll; the consumed offer prevents a later action from overtaking it.

An immediate plan resolves at selection time. Automatic actions apply their admitted outcome; checked actions roll once and select the admitted success or failure branch. A process plan instead creates a version-4 activity at zero clock/contribution progress, captures the current settings revision and pace, consumes the offer, records command idempotency and schedules the activity in the same transaction. It does not create an immediate receipt, narrate completion or grant completion effects. DCs, branches and effects never enter the public offer.

The clock and process progress are distinct persisted values. At each productive cadence, the implemented contribution rule resolves one captured D&D ability check and records it under the reserved `process-contribution` identity. Its success or failure branch awards a bounded amount toward the content-defined requirement; zero contribution is valid. Declared proficiency, ability modifiers and captured tool/condition modifiers therefore affect actual productivity rather than merely changing prose. A different environmental-check cadence may wake earlier without earning contribution. Completion effects apply only when the contribution predicate is satisfied and the boundary is not interrupted; elapsed ticks alone cannot complete the process.

The conditional completion estimate is derived from current progress, cadence, the exact d20 success distribution and the captured success/failure contribution. It is presentation only. Rate-mode clock settlement is not capped at that estimate, and instant mode advances only to the next meaningful boundary; a run of failures can legitimately move the estimate later without stalling the process clock.

Each schedule has its own cadence and check identity. Ability checks succeed at or above DC; event occurrence uses a separate d20 at-or-below threshold contract, with captured modifiers. Event occurrence is not character failure. A boundary can run both contribution and a separate environmental check. Due schedules run in authored order; the first interrupt stops further schedules and future progress. An interruption retains already committed progress. Immediate encounter responses can change the facts without abandoning that progress. A later private resume plan matches one eligible retained row by action-definition identity and rechecks character prerequisites; ambiguous matches reject. Admission reanchors that row rather than creating a replacement. Starting a different process suspends an encounter/paused activity; selection while one is running rejects. Explicit abandonment and instance-specific resume offers remain unimplemented.

The worker settles at most 24 boundaries in a transaction, then schedules remaining work. Each roll stores raw dice, modifiers, captured inputs, result, effects and tick position under `(operationId, segment, checkKey)`. Story locking and the activity cursor fence duplicate workers. Pause/speed changes settle due work using the old rate before applying the new rate. Earned whole ticks and an exact rational remainder survive reanchoring. If more than one batch is due, the first batch commits and the control returns conflict/refresh while catch-up continues; it does not claim to have applied. No model call occurs in a timing transaction or per routine tick.

## Consequence narration

At a completion or interruption, the transaction saves mechanical consequences, a plain outcome passage, the new offer and a `consequence` storyteller task. Its bounded context includes current character/facts, committed receipts, available actions, continuity evidence and the current creative settings. Intermediate routine boundaries publish plain receipts without a narrative task.

That unconditional completion handoff lacks the proposed configurability. [Activity foundation phase 2](../features/2026-09-18--16-48--activity-processes-and-progress/PLAN.md) separates mechanical settlement from accepted reporting/continuation policy. [Bounded autonomy](../features/2026-09-19--00-26--bounded-autonomy-and-reentry/PLAN.md#configurable-boundary-follow-ups) owns chains and follow-up admission: quiet transition, completion or milestone narration with continuation, and interactive scene preparation are distinct supported configurations to implement. Consequence narration remains valid; it must be selectable rather than mandatory. Count generation admissions separately from provider charges and test the zero-call configuration explicitly.

The new task uses the existing generation, outbox, scripted/provider execution, budget accounting, output validation, publication and explicit retry facilities. It has a version-3 scene contract: prose plus `available` or `held` opportunities. It cannot return an interval or reroll. Zero opportunities means held, never an ended life. It proposes fresh plans, and publication independently revalidates every plan against the captured character, facts, quantities and evidence before saving the new public/private offer pair.

Publication is fenced by story revision and generation identity. It appends a passage with generation provenance and publishes continuity notes. Until publication succeeds, action admission holds. Mechanical settlement commits first; later context preparation or execution failure leaves that outcome visible and retryable. Once a task is admitted, explicit retry reuses the same task and receipts. It cannot re-enter mechanical resolution. Profile changes apply to subsequently admitted narrative tasks, not to already captured requests.

The offline consequence source repeats the deterministic outcome summary and selects authored state-responsive plans for the pineapple and microbe benchmarks. Unknown mechanical state holds rather than receiving a generic filler action. These fixture branches live outside generic application policy and do not pretend to understand arbitrary tags or worlds. The provider adapter can consume the same task contract, but live calls remain disabled and unverified.

## Opportunity boundary

`@offscreen/game/opportunities` filters captured private plans against authoritative prerequisite facts and returns separate public offer and private-plan collections. Persistence saves the private collection before making the public offer current. Consequence publication performs the same proposal validation and availability checks before creating a new immutable offer identity. This is explicit constraint filtering, not a semantic proof of tactical plausibility. A real Storyteller still needs human quality evidence after producing valid packages from scene evidence.

Contrasting authored examples enter through the same preview, private-plan lookup, resolver, receipts, narrator and recovery boundaries. They prove that an example can omit quantities, currency, human calendars, anatomy and geography without changing runtime logic. Their mechanics remain authored content until the planning agent is connected.

## Persistence and known limits

The single baseline migration creates the current database directly, including immutable `game_offer` private plans, captured activities, rolls, effects and settings. There are no prototype conversions or compatibility DTOs. Local databases must be reset when the pre-POC schema changes. Multiple unfinished rows are retained, but the campaign pointer still authorizes only one advancing instance. Named capacity is captured without reservation enforcement. The [activity foundation proposal](../features/2026-09-18--16-48--activity-processes-and-progress/PLAN.md) owns the proposed participant/capacity lifecycle and shared clock correction. Current settlement reconstructs campaign time from an instance's original start plus its cursor, which can regress chronology after other work advances; retention alone does not establish correct A → B → A timing.

Snapshot reads use their supplied repeatable-read transaction. Settings history is read-only. Start retry compares the original profile snapshot, not the subsequently edited story profile. Narration retries use existing generation/publication recovery. Broad typed rule domains, generated process planning, semantically grounded process modifiers and dynamic continuation of interrupted activities remain open work.
