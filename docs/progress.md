# Implementation overview

**Current focus:** implementation is active. Bounded S2/U2a supports quiet factual completion, exact A→B→A handoff, independently repeated authored routines, durable story-scoped completion limits and boundary-blocked prerequisites. U2b reports preserve historical evidence without replacing current authority. S3 lets the Storyteller select an exact retained activity. U2c now has its first durable two-entry path: the player accepts two current authored processes, the queue alone admits the successor after fresh checks, and pending continuation can be cancelled without stopping current work. Next add deterministic blocked-successor evidence before broadening chain length/horizons. The [gold session](technical/playthroughs/harbor-session.md) remains the connected acceptance target; it is not yet a recorded play session.

**Observability:** a player-safe append-only activity ledger records starts, suspension-by-switch, exact resumes, manual pause/resume, blockers, interruptions, completion-pending and completion atomically with mechanics. The play surface renders the newest 100 events separately from current commitments, so completed work remains readable after reload. API/worker lifecycle incidents and retryable outbox failures use safe structured JSON events with correlation. The developer-only Chamber inspector now exposes activity-report hook/source identity and generation/publication status without private payload dumps. Deterministic failure controls and a manual QA run remain missing.

[Multiple suspended commitments](features/2026-09-19--02-24--multiple-suspended-commitments/FEATURE.md) partially implements retention through A → B → A, but its test completes B through direct database writes. It does not prove real B settlement, monotonic chronology or browser experience. [Storyteller agency and taste](features/2026-09-19--00-26--storyteller-agency-and-taste/FEATURE.md) has structural evidence with owner taste outstanding; the atlas identifies unchanged Gary-failure menus and an instant beacon option whose prose promises waiting. [Inhabitable return](features/2026-09-19--00-26--inhabitable-play-and-return/FEATURE.md) and [premise-driven setup](features/2026-09-19--00-26--premise-to-playable-campaign/FEATURE.md) remain roadmap work.

**Lifecycle:** pre-POC, solo development on `main`. Live inference remains disabled. Provider adapters and accounting exist, but no live route, balance or model quality is verified. A stored key and the original $10 deposit are not authorization to spend.

**Experience direction:** activities and chains separate mechanical execution, reporting and continuation. Activity A1/A2 own clock, identity and contribution/wait rules; [authored situations](features/2026-09-19--13-49--storyteller-authored-situations/PLAN.md) own choices/current activity permission; [bounded autonomy](features/2026-09-19--00-26--bounded-autonomy-and-reentry/PLAN.md) owns quiet settlement, historical reports, controlling scenes and finite chains in separate slices. First prove independently selected quiet work and consecutive scene-only turns, then accepted continuation. Current completion always requests consequence narration; the correction makes it selectable, not forbidden. Broad cooperation and unattended decision fallbacks remain later work, not prerequisites for this first offline proof.

The Storyteller explicitly authors each mechanical situation's immediate choices and exact process/resume access; inventory/capabilities never generate extra options. Situation authorization privately retains unconsumed or explicitly repeatable activity plans while work runs. Quiet completion mechanically revalidates and projects only those plans under a fresh offer; each repeat creates a fresh instance and receipts. Limited definitions persist completed counts outside transient offers, disappear at their story-scoped limit and cannot be duplicated while an earlier instance remains open. Boundary-rechecked prerequisites block work before another attempt or reward, retain its progress and require a later explicitly authorized resume. A controlling scene replaces current authority without resetting occurrence history. Actor/site scope and irrecoverable target invalidation wait for concrete identity models.

## Where to resume feature work

The [playable DM adjudication loop plan](features/2026-09-18--17-21--playable-dm-adjudication-loop/PLAN.md) remains paused as a standalone infrastructure track. Its authority work is now consumed by the active [agency/taste plan](features/2026-09-19--00-26--storyteller-agency-and-taste/PLAN.md): offer-local private plans, direct resolution, scoped fact admission and bounded opening/consequence planning support state-shaped offline turns. Continue through the experience roadmap rather than completing mechanical subsystems in isolation.

Immediate selection resolves directly without an activity row or tick advance. Its receipt, optional roll, effects, story-fact declarations, consumed offer and follow-up commit before a separate worker operation prepares a DM turn. Mechanical opening review now projects freshly proposed plans and Start stores those exact private plans. Consequence publication independently revalidates its plans and stores their public projection atomically with the new passage. This is an execution kernel, not yet evidence of an enjoyable or time-dependent game.

The same opaque public attempt can reference a private contribution-process or resume plan. Starting records a zero-progress commitment; an event can suspend it in `encounter`; immediate responses leave that activity intact. Starting different admitted work changes the interrupted or paused row to `suspended` instead of abandoning it. The campaign pointer names only the one activity allowed to advance; all unfinished rows remain projected as compact commitments, stale wake-ups fail the pointer fence, and a unique eligible resume plan reactivates the same activity ID, clock cursor and earned contribution. Explicit abandonment, durable capacity claims and blocked/invalidated resume outcomes remain unfinished lifecycle work.

For continuing-life play, the [memory implementation proposal](features/2026-09-18--20-09--storyteller-memory-and-recall/PLAN.md) is the follow-up: first separate durable provenance from loaded source text, then add bounded scene/identity retrieval and scoped pre-narrative exploration. Compact orientation supplies registry slices, useful historical leads and tool guidance; the DM may investigate before composing. Optional semantic retrieval has an explicit investigation gate. The technical phases are a draft, not implementation authorization. A generic agent framework remains deferred; targeted retrieval must be demonstrated before claiming multi-day continuity.

The [offline acceptance contract](engineering/offline-poc-acceptance.md) defines the manual flow and responsibility-specific probes. The [trace explorer](features/2026-09-18--17-27--storyteller-trace-explorer/FEATURE.md) remains planned. Contribution-based activities, spatial movement and richer rule domains are separate designs; do not turn an example's duration, anatomy or currency into a universal mechanic.

Navigation follow-up should examine story timing/recovery and database record relationships next. Normal HTTP story composition currently passes through the Chamber wrapper; document its actual authorization and delegation before any later separation. No restructuring is implemented by this note.
