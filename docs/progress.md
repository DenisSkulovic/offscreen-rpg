## Where to resume feature work

Long-story memory is now the next product-critical implementation program by explicit owner direction. The fixed oracle/evaluator, indexed lexical route and evidence packer are permanent implemented foundations; bounded Storyteller exploration is the one active delivery slice under the shared memory umbrella. Do not select embeddings, a graph backend or global summaries before simpler connected recall is measured. The programme preserves exact state/canonical-source authority, branch and visibility isolation, configurable cost tiers and $0 provider-free development paths.

Evaluation E1 now has a versioned corpus/oracle contract and deterministic builders for 200-scene Greywake and gradient-life histories. The generated artifact carries stable source/evidence identities, scope and evidence expectations for thirteen memory query classes, and materializes into the real canonical document store. Corpus readiness remains distinct from the E2 measurements below.

Evaluation E2 now emits versioned observations and reports for retrieval, assembly and generation-use stages, plus a compact suite summary. Deliberately missing retrieval and deliberately ignored assembled evidence fail different stages. The first linear baseline exposes its severe limitation without provider calls or an LLM judge; numerical acceptance thresholds remain unset until indexed L1/L2 results exist.

Indexed retrieval L1 defines backend-neutral query, unit, candidate, coverage and result contracts. L2 adds a field-aware lexical index; L3 includes raw passages, honest noise accounting, restart snapshots and reproducible scale measurements. L4 adds inspectable minimal/balanced/rich recipes covering retrieval breadth, source participation, lexical effort, reads and retained bytes, with strict operation-envelope intersection. The local store is restart-safe but not an incremental multi-process publication consumer, and task/tier selection is not yet connected.

Storyteller task input v8 supports a durable active-scene anchor. New profiled stories begin at passage one; application admission loads every committed passage from that anchor through the locked current revision for continuation, consequence and report tasks, and the bounded selector fails instead of silently losing scoped evidence. A continuation or consequence may propose that its newly published current passage starts a fresh active situation; only revision-fenced publication can atomically replace the anchor with that exact passage. Current prose is projected once while its evidence handle remains valid. No passage-count inference, history deletion or paid condensation occurs.

Canonical recall now has a deterministic structured route before lexical discovery. Application-known character, place and thread document IDs resolve only against the captured current campaign manifest; duplicate cue reasons merge, unreadable/stale IDs and candidate-limit omissions are traced, and selected IDs still obey the exact context loader's read and byte caps. A restarted active scene can attach compatible changed records or existing captured `d#` handles with explicit identity/place/thread roles; publication stores only stable IDs, and later ordinary continuations resolve their current versions automatically. Continuing or replacing the scene preserves the expected bounded lifecycle. The conventional and abstract start-package oracle proves a corrected thread plus unchanged returning quay and an empty no-human-default cue set. Typed dynamic item creation is implemented; synchronizing its current canonical inventory projection remains separate unfinished storage work.

Storyteller publication can promote newly important people and places into passage-sourced identity and lore documents without granting them mechanical state. Revision fencing now preserves the logical document kind and accepts only same-kind descriptive Markdown targets, preventing the descriptive proposal channel from recasting lore as identity or overwriting structured character, inventory, settings, package-reference or source records. Promotion is still explicit rather than automatic entity extraction. Narrative continuations can now create and transfer bounded story items through typed, sequential, exactly-once effects at the common transaction seam; ongoing canonical inventory-file projection remains unimplemented.

Finite-action settlement now uses an event-oriented gameplay transition seam: its pure decision returns the due/waiting result, next campaign state, durable lifecycle fact and typed consequence follow-up without importing SQL, narration or workflow dispatch. Activity mechanics remain distinct, while a separate typed policy preserves quiet completion, source-frozen historical reports and controlling consequence scenes—including their ordering around accepted-plan continuation. The application applies holds and durable work in the settlement transaction. This is not event sourcing or a general event bus.

The immediate DM adjudication spine is implemented: offer-local private plans, direct exactly-once resolution, scoped fact admission and bounded opening/consequence planning support state-shaped offline turns. [Game rules](game-rules.md) and the [Storyteller runtime](technical/storyteller-runtime.md) own those contracts. The active [agency/taste plan](features/2026-09-19--00-26--storyteller-agency-and-taste/PLAN.md) owns the remaining experience-quality and owner-review gate; it is not missing adjudication infrastructure.

Finite action selection consumes the offer and records a durable execution with immutable plan, start tick and target tick. When typed authority proves the result closed and no world obligation is due through the target, admission draws once, freezes the proposed result behind source/projected-state digests and starts one explicitly pending preparation task. Nothing pending is applied or published. Settlement revalidates the source, applies that result once, links the same generation to its receipt, acquires the required-turn hold and wakes the common receipt-gated publisher; early output waits privately and late output adds no fictional time. Ineligible actions preserve sequential settlement/preparation. Mechanical opening review projects freshly proposed plans and Start stores those exact private plans. Explicit activity/action eligibility forbids unowned idle projection; intent/generation/decision ownership preserves the freeze after mechanics settle.

The same opaque public attempt can reference a private contribution-process or resume plan. Starting records a zero-progress commitment; an event can suspend it in `encounter`; immediate responses leave that activity intact. Starting different admitted work changes the interrupted or paused row to `suspended` instead of abandoning it. The campaign pointer names only the one activity allowed to advance; all unfinished rows remain projected as compact commitments, stale wake-ups fail the pointer fence, and a unique eligible resume plan reactivates the same activity ID, clock cursor and earned contribution. Explicit abandonment, durable capacity claims and blocked/invalidated resume outcomes remain unfinished lifecycle work.

For continuing-life play, implement bounded-cost B1/B2 and storage C1/C2, then the [prepared memory phases](features/2026-09-18--20-09--storyteller-memory-and-recall/PLAN.md): provenance/context capture, linked source-bounded summaries, bounded exploration, return rehearsal and local semantic/hybrid search. Creative bundle storage has its own C3 phase. The first product acceptance is a fresh Storyteller turn using a meaningful old detail correctly in a playable return, with current state, original evidence and bounded total work intact. No chapter engine, full scene lifecycle or runtime subagent framework is a dependency.

The [offline acceptance contract](engineering/offline-poc-acceptance.md) defines the manual flow and responsibility-specific probes. The [trace explorer](features/2026-09-18--17-27--storyteller-trace-explorer/FEATURE.md) remains planned. Contribution-based activities, spatial movement and richer rule domains are separate designs; do not turn an example's duration, anatomy or currency into a universal mechanic.

Normal HTTP story composition now uses the ordinary stories facade. Chamber fixture mutation, inspection and manual QA composition are constructed only when developer tooling is enabled. Storyteller recovery rejects a pending-action retry until the exact finite action has settled and promoted the same generation to its receipt; creative settings cannot change while a current resolution owns the narrative revision.
