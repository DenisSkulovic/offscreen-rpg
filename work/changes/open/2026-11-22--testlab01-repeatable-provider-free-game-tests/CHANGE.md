# TESTLAB01 | Repeatable provider-free game test tenancy and funding fixtures

**State:** READY for bounded implementation **in a fresh Cursor chat**, with live-mutation gate retained. **Owner-commissioned:** 2026-11-22. **Integration branch:** `undertaking/storyteller-workshop`. **Inspected base:** `73186189e2912d5d809a996595f8a0c1f97a53b0`. **Profile:** developer tooling / test infrastructure. **No production funding or provider spend authorized.**

## Why this Change exists
TURN03 has two stranded launch rows with null generation; the lab has zero `storyteller_current_owner_grant` entries. `loadAdmissibleGrant()` correctly refuses a launch without an approved owner grant. Only isolated test helpers currently insert a grant, not any reusable lab operator lifecycle. Directly inserting rows or granting all first users is a non-solution.

Deliver a **durable, repeatable provider-free test environment capability**, not a one-off patch: operator/test harness can prepare, inspect and reuse constrained test-owner funding for real Game Authority admission, and tests can run repeated launch/turn/fork scenarios without a paid model route. This is an independent foundation for TURN03 now and eventual SIM01 / LOAD01 later.

## Selected end state
1. **Reusable runner contracts:** `testlab funding plan|ensure|status` (or equivalent simple named commands), executable from checkout using one canonical helper. `plan` and `status` are non-mutating. `ensure` works in two deliberate modes: disposable test database in automated tests and explicitly operator-authorized named developer lab. The latter must never be invoked as a side effect of `pnpm dev`, `pnpm stack:up`, a browser login or a normal release installer.
2. **Real SQL funding semantics:** one exactly identified Better Auth user, one funding account, one run, one current-owner grant; real production schema/constraints/admission path, no fake zero-dollar bypass. `writer:launch`, prepaid, eligible account/run ceilings **250000 microUSD** (the existing `LAUNCH_MIN_MICROUSD`), one active grant per owner. This is *simulated spending capacity*, **not actual dollars funded**. Finite expiration (default 24h, max 24h) and finite attempt budget; explicit status distinguishes expired, exhausted and missing. Repeated ensure with matching active fingerprint is a no-op, and incompatible/foreign/expired/exhausted grant **refuses** rather than silently topping up or replacing it. A new test session can create a new grant only after an explicit lifecycle decision in a disposable database; no automatic funding regeneration.
3. **Provider-free execution is enforced independently of the grant:** all relevant GA/worker provider entrypoints run `scripted-offline-lab` or a provably non-network scripted transport; no OpenRouter key, provider pin, provider-authorized mode, or external model route in target Pod environments. The runner fails closed before any grant mutation or test traffic if it cannot verify this. For tests, add a provider-send tripwire/negative that demonstrates **zero actual LLM requests**. Never infer no-spend from the budget amount or a misleading `provider` label in captured launch metadata.
4. **Environment guard:** explicit `--target disposable` test-container mode or `--target kind-offscreen-lab` local operator mode; always verify the actual cluster UID/context and expected namespace, workload image/config and target Postgres instance identity. Refuse nonlab, unknown, production credentials or ambiguous worktree-to-cluster mappings; do not let `DATABASE_URL` alone select an arbitrary DB. No automatic `kubectl config use-context`, no namespace wipe or cluster reset. Future DXK09 slots must use a distinct explicit target adapter with the same tenancy contract; don't incorrectly assume they're provisioned.
5. **Audit and secrets:** approval identity is explicitly supplied by operator (never hardcode `op-p3c`/`approval-p3c` from tests); record run/owner, purpose, selected limits, expiry and target identity in a redacted JSON receipt. Do not print DB credentials, prompt text, private Library objects or tokens. Use parameterized SQL or Drizzle transaction; fail closed if the expected auth user is missing.
6. **Repeatable suite affordance:** a documented provider-free smoke entrypoint with dry-run first and machine-readable PASS/FAIL/BLOCKED report. Reuse existing TURN03 proof schema for TURN03 itself, not a fake new PASS. New suites can request isolated distinct identities/fixtures, report setup failures, and retain same generated funding IDs on retry. A stopped/crashed scenario must be rerunnable without a broader cluster/database reset.
7. **No blanket entitlement:** no changes to production `loadAdmissibleGrant`, no general user onboarding grant, no elevated public route, no real provider send, no new arbitrary cost pricing or billing system.
