## End-to-end behavior

- A **Writer Mission** captures: branch/scene state frontier, immutable Library source roots, effective Story Prompt, creative guidance/skill versions, authorized tool scopes and budget, stable operation/attempt identity. No immortal provider context. A profile file is **deterministically resolved and core-injected**; optional source material is actively explored by tools. Large input remains navigable; no all-Library preloading.
- Implement a reusable model/tool loop (not locked to 2–3 rounds): inspect next model decision, execute only granted typed tool requests, record results/quotas/provider round, repeat until final scene proposal, explicit halt or approved budget exhaustion. Deadline, total spend and resource maximums are policy-based and captured; no endless unrestricted iteration or unapproved retries.
- Tool facade provides: `library.browse` (page/prefix), `library.find` (source handles/search), `library.read` (exact hash/section), `library.diff`, `skills.open` (pinned skill); `workdesk.stage`/`read`/`diff`/`discard` for bounded private proposed Markdown; `submit_scene`. Actual tool schema names may be consolidated, but those behaviors are mandatory. The model cannot invoke raw filesystem/SQL/shell or directly publish Library roots.
- Authoritative **creative file entrypoints**: `STORY_PROMPT.md` preserves verbatim user intent; `STORYTELLER_PROFILE.md` provides creative-only behavior; `START.md` or package orientation guides browsing. Optional `skills/*.md` are versioned craft guidance. Resolve kind/scope/visibility/path/hash; creator skills cannot grant tool, spend, safety or mechanic permissions.
- Workdesk staged documents use the **same v2 immutable document/tree substrate** but belong to one operation, with exact stage revision. Writer can read its own draft and explicitly accept/revise/discard it before final submission. Nothing staged enters player canon until WR05 admits it; avoid per-note SQL bodies, use compact custody/selector metadata.
- Provider request/delivery custody preserves exact serialized tool decisions, results, returned provider output, unknown-delivery status and total cost. Resume settled results without a second call. If input/root changed after capture, hold or launch a new authorized mission, never read latest implicitly. Support no-write/no-search fast path for simple scenes, but never require one-shot mode universally.
