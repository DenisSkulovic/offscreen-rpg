# WR08 | decided complete execution algorithm (2026-11-21 post-P3)
**Source base:** `undertaking/storyteller-workshop` containing P3-A/B/C; use SOURCE-MAP.md for exact paths. This replaces the old WR04→WR08 serial design: Web and independent research core may advance simultaneously, but WR08 exclusively owns shared Worker/Temporal dispatch files and integrates that part before WR04 adds child wake.

**Scope:** deliver the player-visible P3 choice→next scene path using already admitted narrative-intent plans; connect the **missing scripted, zero-spend continuation wake** with actual P3-A Writer mission and v3 publisher. It does **not** create a real provider runtime, autonomous authoring quality or research assistants. No paid calls, production flag flip, source schema migration, fabricated model result, synthetic mechanical outcome or new command authority.

**Public flow:** Existing Launch form PUT/GET only → `/play/:storyId` existing `PlayScene` snapshot → for `campaign.offer` (even when `character=null`) show `CampaignPlay/CampaignOfferPanel`, submit exact `PUT /api/stories/:id/actions/:operationId` with `actionCommandSchema` → existing finite-action workflow settles → P3-A stores `writer.scene.v1` mission+outbox → Worker dispatcher activates a stable `writerSceneV1(missionId)` workflow → single idempotent activity reads mission/source pins and calls **scripted** `runWriterMissionModelRound` with a deterministic v3 proposal tied to this captured mission (never a client-supplied rewrite), then uses `publishAcceptedWriterScene` in Game Authority's same DB/DocumentStore boundary → snapshot GET reflects new passage. On retry, re-read mission step/receipt and publication; never generate a second attempt after uncertain delivery. A deterministic fixture is **not** presented as a true model-written scene. Missing source store/grant/capture or unknown attempt holds with no new dispatch. No provider transport activation or paid fallback.

**Authoritative Web command:** `campaign.offer.id` and `campaign.offer.nodes[].id` drive the choice; `useCampaignCommand.send('actions',{expectedRevision:story.revision,offerId,path})` sends the frozen one-time server command and uses its retry-existing behavior. `PlayScene` must show campaign offers even for characterless worlds; `legacyOffer` must be limited to stories that have **no campaign offer**. Do not pass null character through mechanical-only `requireCampaign`; backend P3-A already routes typed narrative intent correctly. Keep `storySnapshotWrite` as the only cache mutation and react to story event notifications/refetch, not an optimistic fake scene.

**Scripted continuation worker boundaries:** Build an integration adapter under `apps/worker/src/activities/scripted-writer-scene.ts` to read `storytellerWriterMission` by **missionId** (not outbox notice UUID/generationId); get the v3 captured request from `generation.input.writerMissionCapture`, ensure ownership/root/checkpoint version and `writer-mission.v3`; use the existing parent step contextId=missionId. The fake decision has `version:3`, `summary`, `scene.content`, `scene.interaction` and **matching authoredIntents**; no unpinned source evidence, Workdesk mutation or claimed provider fact. The exact data can be deterministic from captured intent and sequence, tagged in test evidence as `scripted`; if source not available, fail closed. `runWriterMissionModelRound` returns `proposal-ready` after custody; if already ready, read saved decision from its result/source rather than sending another scripted attempt. `publishAcceptedWriterScene` requires one SQL TX for the saved proposal after staging; protect against lost reply. Never inject real paid transport through this activity. Use `@offscreen/story-engine/storyteller` actual exports or add an explicit export in its owner barrel; no new package.

**Temporal:** Add `WriterSceneActivities.runScriptedWriterScene(missionId):Promise<void>`, `writerSceneWorkflowType='writerSceneV1'`, `writerSceneWorkflowId=(id)=>'writer-scene/'+id`; expose workflow with **maxAttempts:1** for any possibly sent attempt, and idempotent SQL recovery when safe. Register `WRITER_SCENE_WAKE_TOPIC` and its workflow in `apps/worker/src/outbox/dispatch.ts` and `dispatchedNoticeTopics` with `missionId` identity. Update `createWorkerActivities` and `startRuntime` with `DocumentStore` injection. Outbox idempotency and worker restart tests must demonstrate no duplicate story, scene or attempt. Live provider remains blocked absent explicit authority and a separate runtime decision.

**Entry:** Existing `/stories/launch` and `StoryLaunchForm` remain; in `apps/web/app/(authenticated)/stories/page.tsx` favor Play when feature enabled, retain `/stories/new` and draft editor for bookmarks. Server-side flag defaults OFF; do not silently enable in production. Preset labels only if pinned actual catalogue exists. Reentry/historical fork UI already exists; improve truthful status, avoid rewrites.

**Task DAG:** T01 Web home/Launch route → T02 null-character admitted choices → T03 Worker scene wake/runtime → T04 joined Play/reentry/negative proof + archive. T01 and T02 are serial because they share Web state/navigation; T03 can be a separate bounded child **only if isolated worktrees/build outputs or not running Web generated builds concurrently**; default serial one child at a time, no per-TID branches. WR04 writes are disjoint until its final Worker wake integration, which must happen **after WR08**. One integration custodian serializes Change joins, overview/status updates and any shared docs.

**Stop conditions:** exact P3-A generation capture isn't v3; publication source pins can't be validated; worker lacks a DocumentStore; feature flag would require privileged deploy; repeated uncertain paid attempt would be required; or already accepted API changes beyond these decisions. These return exact file/symbol to ChatGPT, not an open-ended architecture redesign. Ordinary local type adjustments and test fixtures are Cursor's job.

**Tests executed by planner:** NONE. Executor must run `pnpm --filter @offscreen/web test -- src/features/stories/story-launch-form.test.tsx src/features/play/view.test.tsx` (or `pnpm --filter @offscreen/web exec vitest run ...` with those exact paths), `pnpm --filter @offscreen/web typecheck`, `pnpm --filter @offscreen/story-engine build`, focused worker TypeScript build and `pnpm test:longform` only after disposable DB preflight; no general full-suite per task.
