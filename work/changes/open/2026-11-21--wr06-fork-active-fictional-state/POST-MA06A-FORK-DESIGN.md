## Selected historical fork semantics

**1. Source-of-truth:** resolve owned parent scene `N` by `story_scene_checkpoint` selector/hash. CAS historical checkpoint determines item/character/facts/clock/notes/root/offer/activities/obligations, **never live parent SQL**. The child starts with own story `revision=1` and a new child passage representing parent's selected scene; lineage metadata preserves `parentStoryId,parentPassageId,N`. Select from a later parent story revision is allowed but only with the exact scene N checkpoint. If no complete v2 checkpoint exists, the active historical fork refuses explicitly; legacy v1 quiescent fork remains compatible.

**2. Deterministic ID remap:** for each branch-local owned object, mint one deterministic UUID from `stableNamespacedDocumentId('fork',forkStoryId, `${type}:${originalId}`)`. Explicit map categories: passage, interaction, offer, activity, obligation, action operation and child outbox/wake. **Do not remap** immutable Library document IDs/hash, generic item labels/holder keys unless a typed reference demands it, or parent evidence source passage IDs (those remain lineage references). Duplicate fork request maps identically. Reject missing/colliding reference target rather than preserving old branch-local id.

**3. Semantic after-state projection:** create child story+initial passage, item rows, captured settings revisions, campaign contents/character/facts/fictional clock, active offer+plans, holds, active activity/progress/boundaries, obligations/due/fired state, active action/plan/pending state. Rewrite all typed intra-state references: `campaign.activeActivityId`, `activeActionOperationId`, offerId/plan IDs, `situationAuthorization.offerId`, `worldConditions[].provenance.obligationId`, source activity/resume references, `acceptedActivityPlan` and pending action references. Use actual `@offscreen/game` validators and WR05P2's typed v2 extraction, not blind recursive string replacement. Child `gameOffer.narrativeRevision=1`, action `baseRevision=1`; settled progress stays settled, not rerolled.

**4. Fictional time and external custody:** child `gameSecond`, pace and accepted progress equal parent as-of scene; `clockAnchorAt` set to new DB clock at fork, not inherited wall-clock elapsed time. New branch owns **no** copied provider generation, settled attempt, budget reservation, workflow or outbox row. If pending action genuinely needs a provider result, preserve semantic action as **held**, clear foreign `preparationGenerationId` and require fresh explicit permission for new dispatch; never mark it settled based on parent future. Only schedule new branch-local obligation/interval wakes where the semantic snapshot authorizes them; IDs are deterministic and notices atomically inserted with child. Delegated auto-decision timing **cannot** be inherited from an unsnapshotted parent dueAt; default to held until an explicitly captured policy permits it, rather than inventing old wall-clock remaining time.

**5. Continuity evidence and active-scene anchors (critical):** the child has its own sequence 1, but inherited notes may cite **immutable parent passage IDs**. Preserve those cited IDs and validate they belong to the ancestor story with sequence <= parent fork cutoff. Extend `StorytellerContext` with a separate bounded **`forkLineageEvidence`** list keyed by parent story, original sequence, passageId, source-root/passage hash. Context builder reads parent immutable passages by lineage FK and cutoff, verifies ownership and checkpoint source pins, and emits handles such as `a18`, distinct from current child `p1`. `boundStorytellerContext` accepts note sources that resolve either in current branch evidence or explicitly authorized ancestor evidence; branch current passage chronology remains independently constrained. `contextRequestSections` produces source-grounded parent handles, never silently rewrites cited passage IDs or mislabels parent N as child N. An activeSceneScope requiring multiple parent passages becomes a child scope rooted at child passage 1 **plus** explicitly captured lineage evidence for previous required passages and recall cues. The reader must refuse incomplete inherited evidence rather than truncate mandatory citations.

**6. Atomic fork:** outside SQL transaction, load/verify source CAS, stage child compatible v2 checkpoint and root (same root hash where v2). Under one source-story owner lock, recheck selector, source passage and owner; insert child story+passage+settings+semantic rows+new selector+authorized new outbox. If after-state child mismatch, roll everything back; pre-staged orphan CAS is inert. Idempotent same forkStoryId+source checkpoint returns same branch, while conflicting fork target/root rejects.
