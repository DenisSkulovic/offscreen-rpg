# TESTLAB02 | Decided I/O, transaction and failure algorithm

## A. Pure command + observer
1. `plan` never imports runtime kind adapter or DB library; receipt serializer `(_, v) => typeof v === 'bigint' ? v.toString(10) : v`, preserving exact integer semantics. Add CLI-level stdout subprocess test, not only exported function test.
2. `status` requires `--target kind-offscreen-lab --owner ... --suite ...`; no operator write authorization. `ensure` also requires operator/approval/authorization flag **and explicit independently provided** `--expect-cluster-uid`, `--expect-db-uid`. Operator may first read these from `status` observation; observed values are not silently filled as expected values in a write call.
3. `createTestlabKindObservation` builds exact `kubectl --context kind-offscreen-lab -o json` reads: kube-system Namespace UID, CNPG Cluster `lab-postgres/lab-pg` metadata.uid, selected `Deployment/game-authority` in `lab-authority` and `Deployment/game-executor` in `lab-workers`, owned Ready Pods, `Service/lab-pg-rw` and resolved endpoints/primary owner; `kind get clusters` includes `offscreen-lab`, current kube context is `kind-offscreen-lab`. No kubectl context switch. Require live Pod image and ready state match selected deployment template; refuse envFrom, provider key/pins even with `valueFrom`/secret refs, invalid/unknown keys and missing scripted mode. Output a redacted, fixed-shape observation containing UID, workload reference and image ID; no generic Kubernetes JSON secrets in JSON receipt. Fixed read size/timeouts; reject missing/ambiguous resources rather than guessing.
4. Guard intent `read` does not require `operatorGrantAuthorized`; guard intent `write` does. Both require observed correct cluster/DB/pod env and provider-free policy. Read operation can internally compare observed UIDs with themselves for consistency, but must **not** treat that as independent operator authorization for writing. On write, supplied expected UIDs must match actual values and be checked again immediately before SQL mutation.

## B. SQL adapter bound to CNPG
1. After A passes, `kubectl --context kind-offscreen-lab -n lab-postgres get secret lab-pg-app -o json`, decode *only* `data.uri` in memory. Validate protocol postgres/postgresql, source hostname corresponds to `lab-pg-rw` cluster service, database `lab`, username `lab`; do not let an env `DATABASE_URL` select target.
2. Start `kubectl --context kind-offscreen-lab -n lab-postgres port-forward service/lab-pg-rw :5432 --address 127.0.0.1` using spawned child; wait boundedly for forwarding-ready line to learn allocated loopback port, fail if process exits, no stdio inheritance. Connect `pg` via `createRequire` anchored at `packages/db/package.json`. Reconstruct URL with hostname 127.0.0.1 and observed port **in memory only** and preserve username/password/DB name. Never print URL/command details containing secrets. Recheck `SELECT current_database(), current_user`; require `lab`/ `lab`.
3. `status` uses DB connection and `BEGIN READ ONLY` ... `ROLLBACK` to execute current `queryReadOnly`. No `grantStore` on this path. Close Pool and child in `finally` even on SIGINT/timeout/query failure.
4. `ensure` after exact owner approval and passed guard, reobserve + compare *all* target UIDs/Pod images/readiness/Mode and service endpoints against A; if changed, block before mutation. Open one dedicated `pg` client, implement `grantStore.withTransaction(fn)` via `BEGIN`/COMMIT or ROLLBACK, and provide query through the same client. Existing `ensureTestlabGrant` performs advisory lock and idempotent three-row grant creation; never reimplement the grant SQL. Close/kill subprocess in finally.
5. All failure responses are structured `outcome: blocked, refusals:[{id,message}]` and zero SQL writes on preflight failure. K8s read failures, missing credentials, DB dial failure, stream timeout, broken endpoint, unexpected target drift are distinct refusal ids. Provider-mode key presence must fail before secret read. On unexpected error redact secrets and do not claim zero partial SQL rows unless transaction rolled back. No retries after unknown commit outcome; rerun same suite via idempotent ensure after observation.
