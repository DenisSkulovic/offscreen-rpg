# WR09A | Durable provider response custody, secure transport input, no paid execution

**State: PLANNER-READY for parallel Cursor lane B.** Inspected real implementation `6dd1276131a813f694ec3bccf4f9062ad3708208` on `undertaking/storyteller-workshop`. This is a *foundational correctness Change* toward [WR09](../2026-11-21--wr09-provider-ready-writer-runtime/CHANGE.md), not the finished live Writer. **No actual external provider calls, model account, production flag, or funded grant are authorized.**

**Problem, directly observed:** `advanceWriterMissionProviderStep` currently stores only the raw SHA of `serializedResponse` in `storyteller_writer_step.result_cas_hash`. `runWriterMissionModelRound` can interpret its in-memory scripted body, but a restarted real Writer cannot recover that body from the hash. After possible dispatch, retry conservatively becomes uncertain. The transport includes literal `Bearer test-not-live`. P3B's existing integration tests assert the legacy raw hash, so silently changing `resultCasHash` semantics is unacceptable.

**Selected safe contract:** Add a separate immutable **private response-object CAS pointer** for delivered *new* provider attempts, without overwriting the legacy raw result SHA: `storyteller_writer_step.response_object_hash` nullable SHA-256, and `writer-provider-response.v1` private structured CAS object with `attemptId, missionId, contextId, ordinal, requestSha256, responseSha256, serializedResponse`. Fixed source envelope: `format:'offscreen.structured-document.v1'`, `envelope:{documentId:attemptId, schemaVersion:1, revision:1, kind:'lore', authority:'noncanonical', visibility:'storyteller-private', sources:[]}`, `schemaId:'writer-provider-response.v1'`. Strict read-back uses the actual DocumentStore API and cryptographically validates raw bytes/hash, IDs and request hash. Private data never enters player API, Telemetry, outbox payload, logs or workflow history. Maximum stored object size follows Documents' existing 1 MiB cap; oversized response is held/uncertain, not silently truncated.

**Migration and compatibility:** Add nullable `responseObjectHash` Drizzle column, SQL migration **0023** following `0022_wr04_writer_research_child`, update meta journal as required. Legacy settled scripted/test steps remain readable with `responseObjectHash=null`, and existing `hashWriterMissionSerializedResponse`/result SHA are unchanged. Keep P3B legacy test helper compatible and explicitly **not permitted as a future live Writer route**. Introduce *new* strict `advanceDurableWriterMissionProviderStep(database,storage,input,transport)` adapter that requires a DocumentStore for any real policy, and `readDurableWriterMissionResponse(database,storage,identity)`. It should share the existing reservation/attempt/budget mechanics, not start a second attempt ledger. If existing custody cannot be safely reused through an internal strategy hook while keeping the legacy test contract, **STOP at that exact boundary**; do not duplicate money logic. A later WR09B Worker integration must use this strict entrypoint, never the legacy test-only shortcut.

**Ordering:** after verifying pinned wire/policy and reserving/marking dispatched, call injected fake transport once. On delivered usage, persist CAS, read back, record pointer on locked matching step with its bound attempt, settle existing accounting attempt idempotently and transition to result-settled. The object and pointer are immutable once linked; step revision and attempt/wire/root identities are fences. On crash/CAS failure after possible send before the pointer commit: retain dispatched/uncertain liability; restart **never sends again** and never pretends usage zero. On crash after the pointer+settlement commit, strict reader recovers exact original response and allows deterministic parsing by next Writer phase. Do **not** claim fully atomic CAS+SQL: orphaned CAS object is harmless/private and unknown delivery is explicitly held. No new charge mechanism or second clock.

**Credential preparation:** remove the hardcoded placeholder from `createWriterRoundTransport`. Inject a nonempty `apiKey` from the future Worker-only host composition input, never serialize/persist it. Missing key refuses **before fetch invocation**. Strict output policy validates frozen model/provider/wire and no fallback; tests use injected fake fetch and nonsecret test key. Do not wire real Worker credentials in WR09A.

**Exclusive source ownership:** `packages/db/src/schema/storyteller.ts`, `packages/db/migrations/0023_wr09a_writer_response_object.sql` and `packages/db/migrations/meta/_journal.json` (and any generated migration snapshot if repository convention requires); `packages/story-engine/src/storyteller/{writer-mission-custody,writer-mission-store,writer-provider-response,budget}.ts`; `packages/storyteller/src/providers/writer-round-transport.ts` and its existing `packages/storyteller/test/writer-round-transport.test.ts`; NEW focused `tools/api-integration/test/wr09a-provider-response-custody.integration.ts` (new unique basename). **No edit to** `packages/application/test/**`, `tools/api-integration/legacy-engine-tests/**`, `tools/api-integration/package.json`, `packages/story-engine/package.json`, `apps/**`, `scripts/repo-tools/module-graph*.mjs`, campaign/stories code.
