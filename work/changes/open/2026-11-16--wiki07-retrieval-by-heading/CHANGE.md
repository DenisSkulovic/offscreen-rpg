## Problem and outcome

The wiki graph can route a reader to a 62-KB technical page, but weak agents should not load 62 KB just to find a 600-character rule. A 1M context window is not a mandate for indiscriminate reading either. The answer is not a new vector DB or a chatbot over docs. It is **deterministic page#heading discovery, bounded original-text excerpt, explicit expansion**, using the existing Markdown AST and authority classifications.

Implement:
```bash
pnpm wiki:find "Who can award a mechanical reward?" --kind product --top 5
pnpm wiki:find "When is ask_memory available?" --kind technical --json
pnpm wiki:read docs/technical/storyteller/context-and-memory.md --outline
pnpm wiki:read docs/technical/storyteller/context-and-memory.md#one-owner-per-kind-of-truth
pnpm wiki:read docs/runbooks/local-development.md#checks-and-boundaries --max-chars 4500
```

These are local *read-only* operations. `wiki:find` never constructs a summary from a model; `wiki:read` returns source-exact text/line ranges with a bounded display. No paid action.

## A. Cheap hierarchical index

Implement in `scripts/repo-tools/wiki-core/` a **section index** over maintained `docs/`, `STATUS.md`, selected root/agent and source README scopes, with `work/designs/open`/`work/changes/open` as visibly **proposed/execution** collections. Evidence/history is opt-in, never ranked as the approved behavior.

Each section record: path, exact GitHub anchor generated by existing parser, H1→H3/H4 hierarchy, start/end source lines, section byte and rough word count, first concise source-exact preview, document authority class, containing link question-table context where available and source SHA/dirty flag. Reuse WIKI01 slugger, WIKI05 row context and role-aware lexical search. Never consult WIKI02/05 gold answer data for live query ranking. A page may have 100 section candidates; limit output, do not limit indexing in a way that conceals exact anchors.

Question query should return **five candidates** by default, ordered with a documented deterministic relevance score. Prefer exact selected owner when known; show `STATUS` as required companion for “implemented, tested, available, live” queries. For proposals show a separate lane and a prominent `NOT SELECTED` class. Path strings and code examples cannot masquerade as current evidence.

## B. Controlled source-exact reading

`wiki:read` accepts `path#heading`, `--outline`, optional `--from-line` and `--max-chars` with stable continuation; by default show one selected subsection and no unrelated siblings. Use AST section span from heading to next peer/superior heading, **not** naive grep in raw Markdown that might mistake a code-fenced heading for a section. Preserve code fences, tables, numbered invariants and critical “negative” text.

If a subsection exceeds display cap, show a **visible truncation warning with next exact line/fragment range**; do not silently drop the conclusion or claim the whole section was inspected. Default ~4–6 KB character envelope, calibrate on measured page types. A single massive paragraph can be chunked with explicit incomplete-sentence warning. `--outline` reveals subsections and sizes so cheap agents can skip irrelevant blocks.

**Boundary:** these are excerpts/citations, not paraphrased content. Output schema `wiki.route.v1` carries source path, heading, original line ranges, link role, revision and output size. If the user needs a 12-KB concurrency proof, allow explicit expansion; no arbitrary byte cap that loses critical safety constraints.

## C. Focused agent-instruction integration

Amend existing `AGENTS.md` / `.agents/references/documentation-navigation-standard.md` and/or a small reusable skill with **one** conditional retrieval rule:

> Known Change → its cited owner heading directly. Unknown question → `wiki:find` top 5 → `wiki:read` one section → `STATUS/source` only when needed. Stop when selected rule, actual source and negative case are known; do not preload entire wiki.

Do not grow always-on AGENTS by 1,000 words. Do not copy the full existing rule into Cursor/Claude adapters. A weak model gets a tight handoff with 2–5 likely code symbols and one counterexample; a strong model may expand deliberately. Both distinguish selected target versus current implementation and never rely on old Changes.

Fallback: if top five results miss plausible owner, route through `docs/README.md` and scoped subject map, or controlled `rg -n`. Do not stuff the wiki with benchmark keywords to “improve” ranking.

## D. Accuracy, security and regressions

Fixtures must prove:
- Question table row context is applied to the correct link/heading and not to neighboring rows.
- Heading link anchors with duplicate slugs, Unicode, same-page refs and nested H3/H4 produce correct boundaries; fenced-code faux headings do not.
- A long selected technical H2 produces concise outline and truncation/continuation, not automatic full document output.
- Status query returns both relevant contract and `STATUS` companion without claiming proof from text alone.
- Unapproved Observability proposal cannot outrank selected current owner as a normative answer.
- Historical evidence available with `--include-historic` and source label, but not default.
- Missing/renamed heading fails with exact line candidate and safe fallback, not fabricated match.
- Query and output do not touch wiki gold test dataset or call network/model provider. No repo writes beyond gitignored optional cache.
