## Settled implementation architecture

**One parent operation and one finite budget authority:** A Writer mission already has a generation-linked `storyteller_operation`, and finite `budgetSnapshot`. Each child is a **sub-allocation** under that same operation, not a new account/run. Child identity: deterministic UUID from `stableNamespacedDocumentId('writer-child',missionId,requestKey)`; requestKey is a parent-generated stable tool-call ID (frozen in parent SQL step) plus question index. Child generation attribution remains the *same* parent generation for budget accounting; each provider attempt is distinct and its attribution includes `missionId,contextId`. `contextId=missionId` retains legacy parent behavior. Outbox/workflow wake uses globally unique child `contextId`, not a model-chosen identifier.

**Child registry:** one `storyteller_writer_child` table keyed by `id UUID`, unique `(mission_id,parent_tool_call_id,child_ordinal)`, `mission_id` FK, immutable `question,library_root_hash/revision,privacy,skill_pins,tool_allowlist,modelSelection,captured_budget`, parent revision, state `pending/running/ready/held/failed/uncertain`, result CAS hash and attempt accounting. This one row is an authorization boundary; step journal continues in existing `storyteller_writer_step` with contextId childId. Avoid creating separate child-mission, generation or provider account tables.

**Budget sub-allocation:** Under one mission+operation/funding lock, claim a finite child allowance as an accounting **slice of the already effective mission limits**, not another round of real account spending. Parent-side reservation limits sum(children maxMicrousd/rounds/tokens) <= parent effective envelope remaining before delegation. Each child step draws from this sub-allowance using **existing** storyteller operation attempt reserve/dispatch/settle, which remains the ONLY actual money reservation. Do not count the same amount twice against account and operation. Child pause/failure releases *unused sub-allocation* once; real dispatched/uncertain amount remains reserved/consumed in the original operation. Attempts are permanently tied to the contextId; repeated model transport after uncertain is forbidden. If the current custody adapter cannot express shared cap safely, **extend it once across parent and children**, rather than writing a second budget engine.

**Runtime context and tools:** Generalize `runWriterMissionModelRound` and `advanceWriterMissionProviderStep` internal contract from hardcoded parent context to `{missionId,contextId}`, defaulting to missionId for legacy parent v1/v2 tests and historical hashes. Provider request for child is newly versioned `writer-research.v1`; scope is a **separate conversation/history** with child question, exact source root, skill pins, read-only grants and finite budgets. Tool executor dispatches based on a trusted SQL-pinned `kind:'parent'|'research-child'`, not an untrusted model argument: the child cannot call Workdesk/submit_scene or ask another child. Child's `library.*` reader validates root membership and visibility for every open, find and citation. Never inherit the parent's private staged Library by default. Per-child result is a bounded `{claims:[{text,evidence:[{rootHash,objectHash,section}]}], gaps,contradictions}` object; claim citations are re-opened and checked by parent before use.

**Join and authority:** Parent records a frozen join batch of child IDs and request hashes. Reader reopens ready child results, validates each cited root/object/visibility and joins **in captured request order** with explicit missing/uncertain markers. Parent remains sole author of final scene proposal. Child findings are never canon, cannot update `story`, `campaign`, `Library` or a passage selector. If optional child fails, parent receives a real gap; if the mission requires evidence from it, hold the final proposal.

**Real-provider path:** Reuse the new Writer activity from WR07B and existing OpenRouter transport/usage telemetry; select only a configured allowed provider route from server policy. Provider execution is off SQL lock with account/run grant, reserve/dispatched/settled under existing custody; uncertain state no retry. Do not expose provider mode in old `storytellerDistributedV1` (which is intentionally scripted-only). A real model invocation is **explicitly budget-authorized and optional for implementation runs**, but a controlled funded run and observed spend/response are required before declaring the *whole Undertaking* fully operational as an LLM Storyteller. No default auto-spend.
