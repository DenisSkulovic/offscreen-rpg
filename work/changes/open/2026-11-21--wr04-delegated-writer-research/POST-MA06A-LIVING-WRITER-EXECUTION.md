## Exact missing capabilities

1. Today `@offscreen/storyteller/tasks:writerMissionCaptureSchema` accepts v1 with existing `sceneFrontier`, and v2 **opening-only** `sceneScope`. No selected continuation mission carries the exact checkpoint/state/intent identity required for durable next-scene authorship.
2. `story-engine/src/storyteller/writer-loop.ts:runWriterMissionModelRound` accepts `scriptedDecisionBody` and constructs a scripted transport. It is not the durable *real-provider* runtime; `writer-mission-custody.ts:advanceWriterMissionProviderStep` already guards attempts/spend and must remain the transport authority.
3. `story-engine/src/storyteller/publication.ts:publishStorytellerResult` and `campaign/narration.ts:preparePendingActionNarration,requestConsequenceNarration` still operate through legacy `StorytellerTask`. `story-engine/src/stories/index.ts:createStories` routes current continuation through `createStoryContinuation`. This is a different creative pipeline from the new Writer's multi-round research/Workdesk and final proposal.
4. `@offscreen/storyteller/tasks:writerOpeningSceneProposalV2Schema` adds a `scene:{content,interaction}` candidate, while `story-engine/src/storyteller/writer-scene-proposal.ts:acceptWriterSceneProposal` currently returns a **v1-shaped summary/hash/evidence receipt** and not an admitted source-document delta. Hash validity != canonical adoption.
5. `storyteller_writer_step` already keys `(missionId,contextId,ordinal)`, but `writer-loop.ts` and `writer-mission-custody.ts` hardcode `contextId=missionId` for parent rounds; research children are not a working separate context yet.

## Selected architecture

**One mission lifecycle, two capture modes, one publication owner.** Add v3 `writer-mission.v3` **continuation** capture with `sceneScope.kind='continuation'`, `{storyId,baseSceneSequence,basePassageId,baseCheckpointHash,baseRootHash,baseRootRevision,baseNarrativeRevision,baseCampaignStateRevision,controllingIntentOrReceiptId,scenarioKind}` and effective policy/profile/rule/skill pins. Do **not** invent a separate Writer execution framework; v1 previous missions and v2 opening remains parse/hash unchanged. Capture a *single committed snapshot* under SQL rules; do not read live latest source after a failed stale turn. A report-only historical narration may remain a special legacy generation if its causal event binding is safe, because it does not create the next scene.

**Typed Writer result for meaningful decisions and continuations.** Define a NEW versioned Writer final proposal (do not reinterpret historical v2 bytes) with `scene:{content,interaction,authoredIntents}`. Every `choice.v1` option must have exactly one stable `narrative-intent.v1` binding carrying `optionId`, bounded `intention`, declared fictional duration/authority class and no unearned effects; option IDs must match exactly. For existing **typed-mechanical** worlds, carry an admissible typed plan or stored plan reference instead, using existing game authority. A scene with null interaction has zero authoredIntents. No author-proposed intent is mechanically authoritative until Game Authority validates and publishes it. Include **explicit Workdesk adoption selection**: `documentChanges:[{documentId,path,stagedObjectHash,changeKind,expectedBaseObjectHash,visibility,authority,sourceEvidenceRefs}]`, bounded and validated from pinned stage root. This is a *proposal*, not a SQL commit. Pair new continuation proposal version only with v3 capture. A prior v2 opening proposal may be extended by a **new version**, not by reinterpreting historical v2 bytes, when its actual WR07B pipeline requires selected canon changes. Any captured candidate must map to actual supported command-policy and authored options; a fabricated plan never becomes an executable activity solely from prose. Preserve no-mechanics absence for abstract worlds.

**Single Writer→Game Authority result adoption.** Add narrow `publishAcceptedWriterScene` adapter in Story Engine, called by new Writer continuation delivery and optionally a refactored WR07B opening path, that validates exact generation/mission, captured checkpoint, root/version/settings/effective permissions, selected document delta, content/interaction and source evidence *before staging outside SQL*. Under existing owner story lock, use WR05P2's actual v2 stage and post-image equality; write passage, authorized offer/holds/continuity/lore and scene selector once. Mechanical choice resolution remains the existing Game Authority state transition; Writer cannot reroll a prior dice/result or change fictional time. Stale captures hold, with no publication. Prevent parallel “legacy task and Writer task” for the same controlling resolution: choose a single controller route by stable source receipt/topic, including retry/uncertainty history.

**World-neutral player intent admission, chosen single-kernel design.** [Source-grounded decision](../../../undertakings/storyteller-workshop/WORLD-NEUTRAL-INTENT-RUNTIME.md) explicitly rejects fake `Character` records and a second game clock. `campaign/settings.ts:initializeCampaign` can create `mechanics:false,character:null` with an authoritative clock. `@offscreen/game/immediate-actions` requires a Character; create a distinct pure `narrative-intent.v1` plan for Writer-authored offered attempts, with bounded explicit fictional duration, no awards or mechanical effects. Preserve existing offer/finite action execution owners: store the admitted plan in the existing `gameOffer.plans` and `gameActionExecution.plan` versioned union, route selection through `campaign/actions.ts` after the same owner/offer/revision/idempotency fence, reuse `campaign.activeActionOperationId` and `projectCampaignClock` for admitted time. Extend existing finite-action settlement to this effect-free plan and capture its source receipt; **do not** call `requireCampaign` or `validateImmediateActionProposal` on the narrative variant (they require a Character), and do not create an LLM-powered free reward route. If a world supports mechanical consequences, it continues using validated typed `ImmediateActionPlan`. P3 must upgrade the WR06 fork mapper for this new typed action variant if applicable. This is a bounded extension of the one action system, not another authority subsystem.

**Mission admission for actual subsequent scenes.** Reuse WR07B's SQL generation/operation/mission/outbox and local worker mechanism, introducing a `writer.scene.v1` deterministic notice keyed to the **generation ID or globally unique source transition ID**, and a version-pinned scenario/intent capture. A player choice or due event commits mechanically first; only a resulting eligible narration boundary schedules a Writer task. A quiet accepted routine or menu/clock read schedules no Writer. A failed/held provider leaves last committed world truth and an honest pending narration state. No update to historic scene while model is waiting.

**Real provider transport.** Extract the scripted response adapter from `runWriterMissionModelRound` as an optional injected `WriterMissionProviderTransport`, but require existing custody to reserve/dispatch/settle/uncertain using actual effective owner funding grant + model selection. Keep default scripted tests and a disabled-by-default live mode. Provider adapter uses existing `@offscreen/storyteller` OpenRouter serialization/usage reporting and captured model budgets; no direct OpenRouter HTTP in SQL transactions. A real funded smoke test only under explicit owner-run permission.

**Optional delegated research** (see other design): finite child registry + context-specific Writer steps with independent conversations, read-only trusted tool permission and root-bound citations; child reserves against the **same** operation's finite budget and returns evidence/proposals, not canon. Parent can evaluate zero children, one, or several when source complexity warrants it; never enforce a fixed number of research rounds. Independent child errors become explicit gaps, not invented facts. Do not create a child agent per NPC.

**Branch and re-entry:** Every Writer reads pinned branch-correct current canonical state, immutable ancestor evidence only when authorized. Child fork sources never include later parent scenes. A scene receives bounded active-scene cues and ongoing thread identities when appropriate, not unlimited transcript stuffing. Workflow restart always resolves the same operation+capture, no new paid generation on uncertainty.

## Concrete tests, not ceremonial test sprawl

- **Life loop:** mocked/scripted provider produces an opening, follows a player-authorized choice, reads new root+earned time, makes another distinct creative offer; three publications tied to three exact state roots, no duplicate command/attempt.
- **Quiet life:** accepted long work advances to known world boundary without polling a model; an interruption invites a Writer only when prescribed; model latency does not advance fictional time.
- **Memory/canon:** give an item and promise, later verify the Writer actually reads rooted evidence and can refer to correct current holder/promise; changed relationship supersedes old current fact, history remains inspectable; private possibility never becomes public automatically.
- **Abstract world:** no humanoid anatomy, inventory, map or D&D sheet; first and next scene choices remain meaningful and executable.
- **Writer cost:** one mission with optional two child reads has one finite aggregate operation cap; no second paid attempt on lost reply; forbidden tools rejected even when model names them.
- **Fork:** inherited source retrieval stops at fork cutoff; no sibling/parent future; old v1 path remains.
- **Adoption:** mismatch source root/selected Workdesk documents, oversize source, stale scene revision or wrong authenticated owner yields no partial SQL, no new selector or new spend.

**Genuine implementation prerequisites:** WR07B's actual mission/worker/admission interfaces; WR05P2's v2 publisher and source delta; WR06 lineage evidence where involved; account authorization and controlled funding for real-provider proof. These are **specific inspection items before Ready**, not a reason for Cursor to redesign the whole product.

**Terminal scope:** one convincing ongoing authored life, optional independent research, bounded paid model transport, concrete tests and docs. This is not permission to ship multiplayer, 3D spatial simulation, infinite autonomy, per-NPC agents, chapter planning or another monorepo package explosion. **Implementation readiness remains PENDING** the actual WR07B local Writer activity and post-WR05P2 v2 APIs; the already accepted source-level authority decision is that narrative-only choices must not be falsely routed into character-bound mechanical plans.
