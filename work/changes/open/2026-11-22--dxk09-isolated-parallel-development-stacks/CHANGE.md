# DXK09 | Reliable, elastic and isolated developer environments

**State: READY for bounded foundation implementation T01–T02; T03–T07 remain PLANNER-HELD until their named design/source gates are closed.** This is a source-reviewed, staged release, **not** an assertion that all infrastructure is implementation-ready or proven. **Owner:** developer infrastructure. **Integration:** `undertaking/storyteller-workshop`. **Reviewed:** 2026-11-22, integration baseline `f6abb22b68cb` (GitHub source, no live host access). No paid model calls, destructive cleanup or release-cluster mutation authorized by this packet.

## Problem and goal

Cursor has repeatedly spent hours on build-context transfer, pnpm symlink errors (`apps/api/node_modules/@better-auth/drizzle-adapter`), oversized `tsc` processes, wrong Tilt CLI arguments, manual resource-trigger sequencing, repeated Pod readiness polls, unknown compiled/process freshness, shared runtime collisions and release/dev Tilt replacement. These are **different failure classes**. Merely creating additional namespaces will not fix them.

**End state:** Any number of worktrees may exist; each can allocate a stable isolated developer runtime when capacity allows. **Four concurrently usable full-system worktrees** are a required target-machine acceptance workload, not a hardcoded allocator limit. Fifth/tenth worktrees and beyond require no source changes. Concurrent slots may use selective service profiles, but all can request a full stack. A normal development start/check/stop requires no manual kubectl/Tilt troubleshooting.

## Decided top-level boundaries

1. **Build correctness before multiplication.** The clean dev image context excludes `**/node_modules`, .git, compiled output, caches, local credentials and large incidental files; retains all required package manifests/sources; reproduces the pnpm invalid-file-request regression. Preserve shared immutable dependency caches, distinguish cache corruption from ordinary reuse. No blanket serialization of unrelated builds based on conjecture. Make disk/context bytes, build duration and failure stage visible.
2. **Runtime truth.** A successful edit requires affected compilation + process load/reload + service readiness and a source/build/runtime fingerprint. Failed compile must mark desired revision NOT READY even if an old process stays alive. No manual in-Pod compiled-JS patch is acceptance. Health is layered: container liveness, application dependencies, compilation freshness, registered Temporal worker behavior, and optional signed-in story smoke.
3. **Lifecycle owned by tooling.** Worktree-relative `pnpm dev`, `pnpm dev:status`, `pnpm dev:stop` (target interfaces; not current implementation). Start/attach handles correct Tilt resource selection, ordered image import when WSL needs it, readiness timeout and diagnostics. Avoid repeated poll loops by every Cursor. Starting a new worktree must never SIGTERM another worktree's Tilt process.
4. **Topology.** A distinct `kind-offscreen-dev` hosts common backing servers and dynamic per-worktree application namespaces, SQL databases/logins, S3 buckets/scoped principals, Temporal namespaces/queues, credentials, images, Tilt sessions and loopback URLs. Preserve release `kind-offscreen-lab` as a physically separate runtime for immutable-image tests. No one-cluster-per-worktree; no hardcoded four slots, port table or copied per-slot Tilt/YAML trees.
5. **Capacity and concurrency.** Admission evaluates physical/WSL memory, CPU, disk, Kubernetes requests/limits, live utilization, Postgres connections and per-service process/TypeScript build memory. Existing `infra/kubernetes/lab/cnpg/cluster.yaml` has `max_connections: "20"`; it cannot be copied as the unexamined dev default for N application stacks. Dev backing-server sizing and per-app connection pools must be coordinated and measured. If four full stacks cannot run, report real deficit and optimize resource usage/architecture; don't redefine four as the ceiling or silently overcommit.
6. **Strict ownership and data boundaries.** Stable canonical worktree-to-slot binding, atomically reserved dynamic ports, fenced Kubernetes resources, database-level login privileges, bucket-scoped credentials, Temporal namespace/queues, isolated auth/session secrets; wrong context/owner refused before mutation. Stop preserves tenant data, crash recovery idempotent; destructive destroy is separate and opt-in. App endpoints must never fall back to another slot when a service is absent.
7. **OAuth without slot ceiling.** Prefer GitHub OAuth loopback redirect behavior using `127.0.0.1` with dynamically assigned ports and invariant `/api/auth/callback/github` path. Current GitHub documentation explicitly permits a loopback callback port to differ from the registered port. Confirm actual existing OAuth app settings, Better Auth generated `redirect_uri`, cookie/session isolation, and provider token limits with *live* two-port browser proof before declaring browser auth ready. Avoid wildcard redirects and an invented OAuth gateway unless this supported method fails. Each slot retains distinct `APP_ORIGIN`, signing secret and user sessions.
8. **Release acceptance without environment swaps.** Dev cluster and release lab coexist without replacing each other's Deployments, ports or data. Provide an *idempotent, bounded cold-release acceptance command* that snapshots source/image/runtime identities, checks context, deployment/migrations/config, runs a provider-free story smoke, records precise stage failure, and leaves lab ready for subsequent fault tests. It must not need to stop or restore dev Tilt. Fault injection is explicitly scoped to release lab and disposable story fixtures, never dev tenant data.
9. **Test at the cheapest valid tier.** Local unit/schema and disposable database tests don't require Kubernetes. Distributed worker, pod-failure and cold-image guarantees must still be proven in genuine Kubernetes.

## What DXK09 will / will not fix

**Will fix if accepted with live proof:** invalid dev Docker context and pnpm symlinks; automated and diagnostic dev lifecycle; stale runtime misreporting; concurrent source/Pod/SQL/S3/Temporal cross-contamination; rebuilding and restarting dev apps to switch between Tilt and release; clean release-lab preflight and replay ergonomics; capacity-related mystery failures.

**Will not by itself fix:** the observed cold-release Game Authority writer-plan HTTP 503, missing TURN03 scene-2 publication, or N5/N7/N8/N10 application fault-recovery semantics. Those remain TURN03 failures until a *separate actual release replay* passes. DXK09 supplies trustworthy infrastructure and an efficient runner; it does not grant TURN03 proof credit.
