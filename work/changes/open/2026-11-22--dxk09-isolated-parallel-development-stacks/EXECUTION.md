## A. Clean build and runtime foundation

**Post-T01a compatibility gate:** Existing worktree code uses `docker build --ignorefile`; the Docker Buildx CLI reference does not document the flag. Before claiming the build context fixed, use the Dockerfile-specific `Dockerfile.dockerignore` convention unless the exact target CLI demonstrates support, align classifier/tests, and run an actual build. Separate an unresponsive WSL Docker daemon from a build-context error.\n\n**Existing bug surface:** `infra/kubernetes/lab/dev/Dockerfile` uses root context and copies `apps`, `packages`, `tools` before pnpm install. `infra/kubernetes/lab/dev/Tiltfile` `custom_build` calls `infra/kubernetes/lab/dev/tilt/load-dev-image.sh`, which calls root `docker build ... .`. GitHub does not contain a root `.dockerignore` at inspected HEAD. The reported transfer exceeded 2 GB and failed on a nested `node_modules/@better-auth/drizzle-adapter` link. This establishes the first defect family; reproduce on workstation to prove exact failure.

**Algorithm:** (1) Build a deliberate Docker context inclusion/ignore policy (at least `**/node_modules`, `.git`, `**/dist`, `**/.next`, `**/.turbo`, local secrets, logs and bulky ignored artifacts), preserve required workspaces/config/lockfiles. (2) Record transferred context bytes and clean build elapsed time, with and without populated host node_modules, from two worktrees. (3) Build dependencies inside the container from pinned pnpm, preserve safe shared dependency layers, keep `TURBO_FILTER` scoped to the intended build stage; do not claim shared immutable cache is corruption. (4) Run affected-only rebuild / sync via existing `dev-sync-paths.mjs` graph. (5) On changed TS, prove compiled output and runtime generation changed; on compile error, desired-source readiness fails. Preserve last healthy old process only if its version is labelled stale. (6) Failed build never deletes DB or healthy deployed resources; errors identify context, install, build, import, compilation or app-init stage.

**Known local shell mistake:** Tilt resource triggers take one resource per invocation; a shared launcher should invoke supported operations with validated arguments and no fragile namespace comma lists. Query readiness via typed `kubectl --context … -n … get` per target namespace (or API equivalent). Implement bounded deadline and failure report; no endless log grep loops.

## D. App rendering, Tilt and Auth (planner gate before T04)

One typed slot config feeds one set of Kubernetes workload templates and one Tilt resource graph. Set a deterministic unique per-slot Better Auth `advanced.cookiePrefix` alongside slot-specific signing secrets and DB session state (validate pinned Better Auth 1.7.5 and all cookie-readers); prove concurrent authorization and logout on two ports in the same browser profile. Missing this would allow one slot's OAuth state/session cookie to overwrite another.\n\nAuth: existing `apps/api/src/modules/auth/config.ts` requires `APP_ORIGIN`, `BETTER_AUTH_SECRET`, GitHub client ID/secret. `auth.ts` sets Better Auth `baseURL`/trustedOrigins from the exact origin. For dynamic slot port P, use `http://127.0.0.1:P`, callback path `/api/auth/callback/github`, generate state/PKCE and cookies via unmodified Better Auth. No wildcard callback, fake user in production route, or separate OAuth application per slot. Fail with a clear operator action if provider config unavailable. GitHub user/app token limits are an external throughput consideration, not a slot allocator limit.

`pnpm dev`: worktree-relative guarded start/attach; choose role profile or complete default; start only owner resources and await compilation, runtime and dependency readiness. `pnpm dev:status`: print allocated slot, URLs, source/dirty hash, current image/runtime fingerprint, role status, failing stage, capacity estimate; read-only. `pnpm dev:stop`: gracefully stop only this owner's Tilt and app resources, preserve SQL/S3/Temporal. ## Purpose boundary and extensibility

Treat `kind-offscreen-dev` worktree slots as an **instance allocator within the dev purpose**, not a generic cluster-wide environment allocator. Existing `kind-offscreen-lab` is the independent stable production-like release-acceptance **purpose**, with immutable image builds and no Tilt-driven source updates. Both environments may coexist; do not redirect release commands into development namespaces. Identify target by an explicit, pinned purpose/context configuration at command entry; do not rely on ambient kubecontext, a generic `ENV=prod` string, or naming conventions alone. A future `e2e`, `staging` or other purpose can be added through a separate explicitly owned target/configuration that declares its own cluster/context, persistence, credentials, mutation policy and proof, reusing narrowly suitable primitives. Do not provision future environments or introduce speculative generic frameworks as part of DXK09.
