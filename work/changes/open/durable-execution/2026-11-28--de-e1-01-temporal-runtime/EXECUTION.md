## Lifecycle and failure

Admission synchronous before any await; implement methods as non-async promise-returning wrappers to share exact in-flight/settled stop/close promises. States idle/starting/running/stopping/closing/closed/failed (internal, not export). Start valid idle only; create Worker with copied native options plus owned namespace/connection, invoke `run()` immediately, capture synchronous throw and attach rejection handler before yielding; returned `termination` settles on actual run end, unexpected successful termination while not stopping is failure too. No polling-ready claim. `stopWorker`: idle before any start resolves no-op; after successful stop in idle return that generation’s existing stop receipt; current generation stopping/repeated stop shares receipt; running transitions to stopping before shutdown; call shutdown once and await run; successful quiescence resets idle; next start admitted from idle clears previous stop receipt, associates a new generation even if acquisition later fails. Start/stop/close overlaps refuse except repeat stop/close; close internally uses owned stop routine, not reentrant public admission. Once failed no restart. Unexpected run failure must remain observable even when nobody currently waits (attach observer without replacing rejected promise). Treat rejected run or shutdown exception without established quiescence as unsafe: no further Worker and no closure of still-borrowed native connection. Client cleanup still attempted independently; safe native closure after confirmed settled graceful run or no acquired Worker, never retry close automatically. `close` always settles terminal state; repeated calls share result including failure. If run unexpectedly resolves it is quiescent but failure remains; close can release both resources and still reject primary failure. Partial acquisition cleans up acquired resources independently; Worker.create rejection does not yield a Worker, close acquired connections, preserve any SDK close failure. Host has no timers, global shutdown, signals, or cluster access. Consumer owns bounded process deadline and races all scenario waits against termination; 02 handles unsafe custody residual/process stop. Test state at deferred acquisition, create, run, shutdown, close boundaries, not only synchronous mocks. Compile against installed SDK pinned signatures; mismatch of semantic ownership returns to planner, local type corrections allowed.
