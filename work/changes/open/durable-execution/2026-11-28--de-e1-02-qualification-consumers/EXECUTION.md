## Incremental custody receipt (IR-H01)

Required for every joint runner invocation, including trace-disabled mode. Operator creates a fresh private directory outside the repository (`mktemp -d`, umask 077), passes its absolute new `custody.jsonl` path as `E1_CUSTODY_PATH`, retains it regardless of exit status. Validate path before mutation: existing parent is operator-owned private directory, no symlink at directory or file, file must not exist. Open once exclusively (`wx`, mode 0600), never truncate/reuse; fail admission if creation or initial write fails. Use synchronous complete writes of one newline-delimited JSON record, `fsyncSync` before returning from each append; cap at 4096 records, 4096 bytes per line. Record only selected nonsecret identities, enum outcomes/reason codes, sequence starting at 1, timestamp, source SHA and attempt hex32 on every row; no raw error, environment, fixture arguments or payloads. Last partial/invalid line, missing sequence or missing final record is incomplete/uncertain, never PASS; retain the file unmodified for inspection. A fresh path and initial `namespace-intent` record are required before the strict namespace owner call.

Runner owns the journal; pass an explicit in-process `recordCustody(event)` callback and attempt identity to both consumers, not authority from the file. T03 wires the actual plain start and Agent Core `startRaw` (including duplicate paths), Worker generations and cleanup; T01/T02 leave their native behavior intact. Events below use an operation sequence ID (the intent row sequence) to bind each acknowledgment/outcome. All writes at mutation boundaries must finish before calling the native operation or allowing its acknowledged result to be used. For an acknowledged start, append the exact returned `firstExecutionRunId` inside the native promise continuation before exposing the handle to scenario code; retain owned handles in memory even if journal write fails. A deadline/termination race must not silently discard a late acknowledgment while the runner is alive; no new starts after failure, record late ack if available, no unbounded wait. If process dies before acknowledgment is recorded, intent remains uncertain; never infer ownership from a later lookup.

| Event | Required fields / timing |
| --- | --- |
| `namespace-intent` | Before calling strict create: exact six-field verified target, generated namespace, retentionDays 1, attempt and source SHA. |
| `namespace-admitted` | Only after strict owner returns successful in-process admission; bind intent, acknowledged creation, verified namespace ID, name, retention and unchanged target before either consumer opens host. |
| `namespace-refused` | Bind intent and bounded reason; retain potentially created residual if create cannot be excluded (including abrupt interruption after intent). No adoption, deletion or retry. |
| `worker-start-intent` / `worker-start-result` | Before host start and after actual start outcome; consumer, namespace ID, queue, generation, operation ID and outcome. Do not claim readiness. |
| `workflow-start-intent` / `workflow-start-result` | Before every native start RPC, consumer, namespace ID, queue, intended Workflow ID, fresh vs duplicate, original Run ID for duplicate. On acknowledgment record exact returned Run ID; on native duplicate refusal record explicit refusal and existing owned Run ID, not new ownership; other error/timeout is uncertain unless proven refused. Never replace original handle. Unexpected acknowledged new run is failure; record it separately as owned exact acknowledged run, no further starts. |
| `cleanup-intent` / `cleanup-result` | Before/after each owned run settlement/cancel, Worker stop (including replacement) and host close; exact run or consumer/queue/generation, operation ID, bounded settled/cancelled/failed/uncertain outcome. No foreign cleanup. |
| `final` | After cleanup and evidence finalization, native status, telemetry status, journal status and unresolved intent/run/worker identities (bounded per row; refer to prior sequence IDs); no success if any indispensable record, cleanup or proof failed. |

If append fails before mutation, do not perform that operation. If it fails after mutation, fail qualification and refuse new work; attempt bounded safe cleanup only for already acknowledged in-memory owned handles/host, never adopt unknown results. Report journal failure in final stdout if possible; do not treat stdout or missing `final` as a substitute for durable evidence. Hard timeout or abnormal exit is failure; operator retains complete prefix plus any truncated tail, treats unpaired intents as potential residuals and uses recorded exact identifiers only for read-only inspection. No automatic cleanup after process death, no namespace deletion. Forward processes are separately recorded/owned by operator. The namespace registration remains after one-day history retention; only histories expire under the configured policy.

Offline proof in `qualify.test.mjs`: injected recorder/owner/start/cleanup calls establish intent-before-call and ack-before-consumer ordering for both consumers; failed append precludes mutation, post-ack failure precludes further starts, duplicate refusal preserves original identity, ambiguous start/create never adopted. Spawn a local credential-free child importing only the journal helper, write/sync namespace intent/admission and Workflow intent, notify parent only after writes; parent kills that owned child before finalization and awaits its exit with a finite 5s bound. Verify exact retained rows, no final, uncertain unpaired Workflow intent; repeat with truncated final line via local fixture, never PASS. No cluster call or actual workflow in this offline interruption test.

### Independent observation oracle and finalization (IR-H02)

Freeze the mandatory traced cases in `traces.mjs` as a static case-to-required-observation table (not generated from the emitted spans or successful constructor calls). Bind each case to the existing scenario entry/exit and exact acknowledged Workflow/Run ID; require each named case exactly once, distinct trace ID and run correlation per case. Plain replacement includes both active and closed duplicate checks on the same original execution. Agent case names are actual `runScenarios` `researcher-tool` and `runRecovery` `fresh-worker`. No replay dispatch/span; no initial Worker start or final teardown span in the case matrix (only the checkpoint replacement calls). Other maintained Agent Core scenarios still run every original native assertion and retain raw physical observation/late/incomplete diagnostic counts; no required positive trace retrieval for those cases, no exported diagnostic traces in E1. In particular timeout/cancel are not positive trace cases and incompleteness there cannot be substituted for a passing required positive observation. The native exporter-negative plain normal is a sixth distinct trace with the same local completeness predicate as plain normal, injected failed submission, no backend query; never count it as positive.
