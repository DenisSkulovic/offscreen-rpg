# WR10 | selected two-phase protocol, durable ordering and exact refusal behavior

## Protocol schemas (new `@offscreen/contracts/writer-round-private-custody`)

Version `writer-round.private.v1`; **separate** `/internal/v1/writer-rounds/:missionId/:ordinal/prepare` (POST), `/internal/v1/writer-rounds/:missionId/:ordinal/outcomes/:attemptId` (PUT), `/internal/v1/writer-rounds/:missionId/:ordinal/status` (GET). Strict Zod bounded body, 64KiB server limit. Prepare input `{schemaVersion,contextId:uuid,attemptId:uuid,expectedRevision:positiveInt}`; **no price/model/owner/root chosen by caller**. Prepare output discriminated `ready|replayed|held|uncertain`: ready carries exactly one frozen `{missionId,contextId,ordinal,attemptId,requestSha256,serializedWire,model,provider,unitPriceVersion,maxOutputTokens,timeoutMs}`, with `serializedWire<=32768 bytes`, and a SHA256 digest over the canonical wire. No secret. Outcome input `{schemaVersion,requestSha256,outcome: delivered({serializedResponse<=32768 bytes,usage,telemetry,exactWireSha256})|failed({sent,usage?,telemetry?,failureCode})|unknown({telemetry?})}`, only existing typed fields. Status response `{status:'dispatched'|'settled'|'uncertain'|'held'|'failed',attemptId?,responseSha256?}`, **never raw body**.

## GA-side immutable preparation

1. Parse/validate executor role and body BEFORE accessing story data. Resolve `missionId/contextId` from DB; require parent v3 continuation, existing captured request and operation grant, stored owner/story/root/revision and budget policy; no new mission, no client-supplied policy override. Read private Library/tool summaries via existing `prepareWriterMissionModelStep`. Verify frozen wire and its computed digest before SQL reservation. Require `<=32KiB` wire before marking dispatched.
2. Check SQL step/attempt state. Settled/replayed => return no-send status, uncertain/dispatched => return uncertain **without a new prepare token or wire**. On model-request-prepared/attempt-reserved, under one transaction acquire global advisory `714092631` FIRST, call existing `planWriterProviderStepInTransaction` and `markWriterMissionDispatched` as previously; pin exact attempt/model/provider/pricing hash and step revision. Commit possible-send before responding ready. Concurrent prepare: only one ready response may authorize send; **because a network response may be lost, repeated prepare returns uncertain instead of emitting another ready**, even if no provider request was sent.
3. The executor receives ready at most once. It validates frozen wire SHA, model/policy, provider allowlist, credentials in memory, fake prepared transport preflight and either attempts **one** fake send or records known-unsent/unknown outcome. No SQL or DocumentStore injected. Never auto retry provider on HTTP request/response timeout.

## GA submission

4. PUT validates executor token, exact route/attempt identity and frozen persisted request pin under SQL. For delivered: validate reported exact-wire SHA and usage/telemetry bounds against stored policy; call existing private CAS put/read helper **before SQL transaction**; inside one advisory-first TX call existing budget `settleStorytellerAttemptInTransaction`, CAS-write matching step `resultCasHash` + response-object pointer and state `result-settled` using `finalizeDurableWriterDeliveryInTransaction`. No separate charge, no budget release on unknown outcome. A duplicate identical PUT returns same status; mismatched second result/usage is 409 without mutation.
5. `failed,sent:true` follows `finalizeDurableWriterSentFailureInTransaction` and one charge/failed step; `failed,sent:false` uses existing confirmUnsent/hold only with an explicitly trusted recorded unsent outcome; unknown or socket loss => uncertain (not resubmitted). HTTP timeout after request means executor does **GET status** for observation only; GET may not be used to initiate a second send.
6. After GA durable settlement, the **GA-owned** existing `interpretPersistedWriterDecision` can consume `readDurableWriterMissionResponse` and persist tools/next model step/proposal using WR09B; this first WR10 Change tests it via explicit private test harness, **not** a new production Temporal workflow or Launch path. Future composer owns v3 continuation admission, activity taskQueue/wake and real provider authorization.
7. Ensure old `advanceDurableWriterMissionProviderStep` delegates to shared prepare/finalize helpers when passed the in-process fake transport. Existing WR09A/B tests retain their one-send/one-charge/replay behavior. If a necessary helper is private, extract it within same custody module with invariant preservation. Do not copy SQL/charge arithmetic or move SQL authority to Worker.

**Non-goals / stop:** request/response too large for 64KiB GA HTTP => held unsupported (not charge-as-success); no S3 pre-signed URLs in v1; no live OpenRouter secret, no launch mode switch, no Worker activity queue registration; no second generic Provider gateway package. If extending the current in-process custody refactor requires changing budget lock order or public result SHA, STOP with exact failing test and source lines; do not downgrade safety to meet a schedule.
