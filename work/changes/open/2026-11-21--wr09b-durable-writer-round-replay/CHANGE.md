## Why this is necessary
writer-loop.ts:runWriterMissionModelRound currently requires scriptedDecisionBody, invokes a synthetic in-memory delivered transport and immediately interprets that same local string. If an actual provider result is already settled, this function returns only 'replayed' without recovering the decision, applying missing tools or making a final proposal available to publish. Existing library tool path executes before looking for a matching already-completed toolCallId; uniqueness on storyteller_writer_step(mission_id,context_id,tool_call_id) stops duplicate rows but doesn't replay a completed result. A crash between receiving a valid response and applying its tools cannot safely be treated as Done. A second model-round prep must also avoid duplicate ordinal insertion on retry.

## Chosen scope and outcome
Introduce a **separate** runDurableWriterMissionModelRound API for an already admitted, pinned **v3 continuation parent mission**, receiving the prepared/credentialed transport and WriterRoundModelPolicy from the caller. It uses WR09A strict custody for first delivery and reads exact private CAS body for replay; both paths feed ONE extracted decision interpreter shared with the old scripted route. Accept existing Library/Workdesk tool grants, enforce original pinned root/round/price policy, at most capture.budgets.maxModelRounds, re-use tool-call receipts and next-step ordinal on retries, and return the original validated final v3 scene proposal when mission/step is proposal-ready. No additional provider send after possible-send or already-settled states.

**Explicit non-goals:** no live provider secret/composition, no paid call, no change to launch/opening admission, no new provider mode in player API, no Workshop feature flag, no research-child provider execution, no permission to publish from an untrusted Worker. These are future WR09C/runtime and undertaking final gates. A test caller supplies fake PreparedWriterRoundTransport and an already-persisted v3 continuation capture; this stage genuinely exercises delivered provider-shaped bytes and multi-round tool execution *offline*, not a production live Writer.

**Write ownership:** packages/story-engine/src/storyteller/writer-loop.ts, optional one new private writer-round-replay.ts helper, and tools/api-integration/test/wr09b-round-recovery.integration.ts (new exact basename).
