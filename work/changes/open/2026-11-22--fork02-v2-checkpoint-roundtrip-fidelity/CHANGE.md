### Key source constraints (decision, not conjecture)
- `game_offer.plans` is `jsonb NOT NULL` in `packages/db/src/schema/campaign.ts`. **SQL NULL is prohibited**. However PostgreSQL **JSONB literal `'null'::jsonb` differs from SQL NULL** and is allowed by this constraint. Whether Drizzle/pg preserve that distinction must be proven on disposable Postgres before adopting it.
- `buildOfferSnapshot` currently renders `plans: null` only when *no associated game-offer row* exists. A row with an actual JSON null is currently wrapped as `{version:1,body:null}`. Therefore simply writing JSONB null does **not** solve the round trip: readback semantics must be adjusted deliberately if this is the chosen representation.
- The fork inserts game-offer records separately, and future action semantics may depend on their existence. **Do not silently omit the game-offer row** merely to obtain `plans:null` on readback.
- `extractOfferPlans` converts null to `[]`, and `parseStoredActionPlan` / `immediateActionPlanSchema.parse` may normalize/strip data. Checkpoint payload integrity is not permission to rewrite open data.
- `campaignOfferColumnFromFictional` parses the offer tree into `offerSchema` and can rewrite its shape; `offerTreeFromCampaignColumn` emits only `{id,nodes}` for a nodes-based tree. Preserve explicitly meaningful open payload keys, while preventing `source`/`meaning` envelope fields from being duplicated in nested tree payload.
- The historical mapper `fork-reconstruct.ts::v2ForkRowPlan` is presently a separate, non-live API. Do not create a parallel contract; after live fix, retain it only if active tests/callers require it and apply the same round-trip invariants when covered.

## Decided end state

1. **One symmetric as-of contract.** The mapped v2 checkpoint (after intentional fork ID remapping) must deep-equal the v2 fictional snapshot reconstructed from its inserted SQL after-state, **for every compare field**, with no weakening/ignoring fields, hashing, owner, canonical root or rollback semantics. Deterministic valid checkpoint snapshots from both scripted scene1 and rich active scenes must be representable.
2. **Absent plans vs present plans retain meaning.** For a current checkpoint offer with `payload.body.plans === null`, retain the current `game_offer` row and store a JSONB *value* `null` (not SQL NULL), only after a real disposable PG proof that the column accepts it and the driver reads it as JS `null`. Make `buildOfferSnapshot` emit checkpoint `plans:null` when the associated row's `plans` is JSON null, but still render a wrapped payload for actual empty arrays or object/array plans. Distinguish `null` from `[]`. No DB migration.
3. **Non-null open plans are not lossy.** Persist the exact **unwrapped** mapped-checkpoint plan body (including unknown allowed keys) in `game_offer.plans`; readback must wrap it exactly once. Validate where mandated, but **never use a schema-parsed transformed result as stored data** if that changes a valid open payload. If genuine invalid plans are rejected by existing checks, continue to reject them.
4. **Offer metadata and tree remain intact.** Preserve `id`, `source`, `meaning`, and the exact nested offer tree from the mapped checkpoint. Do not silently fall back to an empty tree when the checkpoint has an invalid/nonrepresentable tree. For existing legitimate live offer snapshots, preserve the same nested offer shape during SQL round trip. Any unknown-key stripping by parsers/readback must be tested and corrected **within the precise offer boundary**, not by altering global `offerSchema`.
5. **Find all mismatches, not just first.** Introduce a **test-only** field-by-field collector comparing all fields of `SceneCheckpointV2FictionalState` after the *actual readSceneAfterState -> toV2FictionalState* path. Keep production `assertV2PostStateMatches` strict and first-failure behavior. The helper must identify all unequal fields and targeted nested paths, so no acceptance test can hide later mismatches. Verify fields after offer: accepted activity plan, IDs, situation authorization, world conditions, active activities, obligations and active action.
6. **Fork integrity.** Wrong owner/hash and malformed payload refuse, no child row, parent checkpoint and revision unchanged, deterministic remapped IDs and no parent future leakage. Same fork ID/request preserves existing replay/conflict semantics. No real provider sends.
7. **No rolling fixes.** Resolve any additional mismatch found by the comprehensive disposable test *in this same Story Engine Change*, if localized to v2 fork mapper/readback, before requesting another live TURN03 attempt. Cross-owner schema/architecture contradictions go back to ChatGPT with exact source/evidence. Live kind test remains TURN03 ownership.
