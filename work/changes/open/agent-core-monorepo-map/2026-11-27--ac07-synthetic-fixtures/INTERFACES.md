# AC07 | selected execution contract

## Fixture identity and scenarios

Shared constants: definition IDs `researcher`, `arithmetic`, version 1. Instructions include fixed `E1_DEF_RESEARCHER` or `E1_DEF_ARITHMETIC`. Tools `readDocument` and `calculate` respectively; no cross-exposure. Model ID `e1-synthetic`. Exact user input scenario string (no arbitrary user data): `E1_SINGLE`, `E1_TOOL`, `E1_UNKNOWN_TOOL`, `E1_BAD_ARGS`, `E1_THREE_TOOLS`, `E1_TOOL_FAIL`, `E1_MODEL_FAIL`, `E1_PARTIAL`, `E1_CANCEL_HOLD`, `E1_TIMEOUT_HOLD`, `E1_RESTART` (restart uses same normal tool behavior). Researcher `E1_SINGLE` text `E1_SINGLE_RESEARCHER_OK`, arithmetic `E1_SINGLE_ARITHMETIC_OK`; researcher normal read fixed `history/promise.md` result `POC_SOURCE_OLD_BRIDGE_DAWN: A promise was made to meet at the old bridge at dawn.` then answer `The promise was to meet at the old bridge at dawn.`; arithmetic normal `{a:7,b:5,op:'add'}` yields `'12'`, answer `'12'`. No arbitrary eval.

## Model response rules

Use actual ProviderV4 options.prompt: system instructions marker, user text exact scenario; inspect assistant `tool-call` and `tool` role `tool-result` structured parts and toolCallId/name, output `text` or JSON string shape accepted by pinned SDK. Never infer previous tool result from substring anywhere in user text. P0 returns text/stop. P1 first request without a result emits one `tool-call` with ID `e1-call-1` and JSON args, finish `tool-calls`; subsequent request only if exact matching result returns text/stop. `E1_UNKNOWN_TOOL` emits `notRegistered` call; `E1_BAD_ARGS` emits selected tool with invalid input (e.g. path other than literal). If SDK sends error result, respond with `UNSAFE_FALSE_SUCCESS` text/stop to test sticky denial, not success. `E1_THREE_TOOLS` emits three calls with distinct IDs, valid schema, same selected tool; if any subsequent result, respond `UNSAFE_FALSE_SUCCESS`, expected mission limit. `E1_TOOL_FAIL` arithmetic uses valid {-999,0,'add'} sentinel, after tool error fake returns false success; `E1_MODEL_FAIL` throws stable error; `E1_PARTIAL` returns nonempty text and finish `length`. `E1_CANCEL_HOLD`/`E1_TIMEOUT_HOLD` are bounded abort-aware Activity holds; cancellation hold 8s, timeout hold 12s >10s Activity start-to-close, on delay expiry throw bounded stable failure (never return success from either hold); ensure timer is cleared in finally, no unbounded promise. Workflow-timeout scenario AC08 test adapter pauses before native loop or waits on restart gate under 30s timeout rather than weakening production envelope. `E1_RESTART` same normal result-driven behavior.

Emit ProviderV4 shape matching R10 `vercel.model.mjs` (`content`, `finishReason:{unified,raw:undefined}`, usage input/output totals, warnings:[]). JSON arguments bounded <=1024 and model/fixture text <=4096. `observations` passed by trusted host per Worker lifetime: collect model/tool events `{workflowId, activityId, attempt, phase, kind, toolName?}` from actual Activity Context; no raw prompt, no decision dependency. Fresh instance has fresh observations; history reconciles completed Activity IDs across lifetimes. Keep pure `decideFixture` separately testable, return explicit scenario classification for held/failure cases; host `doGenerate` executes held mode only inside Activity. Reject unexpected options/missing tool result; unsupported output/model families throw.

## Synthetic tool Activity

`runSyntheticTool(request: SyntheticToolRequest): Promise<string>` uses exact request shape in AC05 `INTERFACES.md#capability-contract`. Validate `actualWorkflowId === missionWorkflowId(request.missionId)`, UUID, known definition/version, unique effective names subset of static definition, requested tool membership, exact fixture args and serialized input <=1024. Revalidate independently (don't trust Workflow schema). Reject unknown or wrong root with stable error before effect; pure read/calculation only. `evaluateFixtureTool` pure; `createFixtureActivities(observations)` captures observations and wraps actual Context.current().info. Log only IDs/status and counts. For sentinel throw after validation, count attempted Activity but no successful result. Use current Activity cancellationSignal before execution; no retry, no background work. This is synthetic fixture fence, not real resource authorization.
