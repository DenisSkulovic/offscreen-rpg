## End state, reduced to four enforceable invariants

1. **Scene after-state is exact:** `readHistoricalScene(owner,story,sequence)` uses the immutable v2 scene payload, not current campaign, offers, activities, obligations or notes. Every new scene publication selects an object containing the actual *post-commit* semantic state and source-root/choice identity.
2. **No CAS/provider under lock:** prepare immutable passage/Library/checkpoint bytes before the owner-scoped SQL lock, verify hash and expected base. Under lock, revalidate, apply the existing transaction's mutations, compare final semantic SQL projection with staged v2, then select checkpoint and outbox/receipt atomically. Any mismatch rolls everything back, except inert unselected CAS blobs.
3. **Fictional vs operational state:** store clock, settings revision, facts/items, offer/permission snapshot, holds, open activity/execution semantic progress, obligation states, continuity notes, playable choices and source pins. Exclude billing reservations, worker leases, task attempts and queues. Don't fabricate a nonhuman body/abilities or impose a mechanical campaign on a narrative-only world.
4. **Compatibility:** v1 historical reads and v1 quiescent fork behavior unchanged; v2 is required for *newly eligible published scenes* under this wave, not retroactively fabricated from old SQL. Same idempotent operation/transition returns the original selector, never a second model request.

## Execution algorithm (for Composer, once WR05S exports are real)

**Prestage, no story lock**
1. Read owner story/revision/view/root + campaign/settings/items/active activity/obligation/execution/offer rows from one consistent repeatable-read snapshot (no CAS under SQL lock). Read frozen generation/task/notes evidence and current root. Reject owner mismatch or inconsistent base.
2. Determine fixed operation/passage/interaction/offer IDs **once** before staging. For Storyteller path, use stable source-generated IDs where already specified (e.g. `publicationPassageId(id)`); allocate any other random UUID exactly once per preflight, keep as input throughout commit. Do not reroll under tx.
3. Compute `projectSceneAfterState(base, finiteSceneMutation)`: current semantic state plus known admitted changes (item effects, notes, offer/decision/hold transitions, active work rows). This function is **not** a universal campaign simulator; if a specialized write cannot be represented from the frozen data, explicitly reject `state_not_representable` rather than omit its row.
4. Stage passage, changed Library root and complete v2 checkpoint with canonical pins and post-state via `stageSceneCheckpointObject`. Reject malformed/over-cap payload before opening lock.

**Commit, same story transaction**
5. Recheck the exact owner/revision/view/base root and source generation/task/notes evidence, plus relevant row identities/revisions (activities, obligations, offers, action state and settings) against captured base under owner lock. A stale value aborts before inserting publication.
6. Execute **existing authoritative mutations**, using preselected IDs and admitted typed decision values. Apply continuity patch exactly once, update campaign holds/offer/authorization and source/publication rows as appropriate. Avoid any DocumentStore/provider/tool calls.
7. Read a normalized semantic after-state **inside the same transaction**. Compare every v2 field required for a future fork to the staged checkpoint: items, notes, scope, clock, offer, plans, holds, activity, obligations and active action. On mismatch throw conflict and roll back *all* SQL effects; the CAS blob stays inert.
8. Insert v2 selector via `insertStagedSceneCheckpointSelector` with same operation/transition; enqueue notices/set published receipt in same tx; commit. On replay of already selected hash, return prior result, no extra paid dispatch. If already published without v2 because legacy, preserve old rules rather than synthetic upgrade.
