## Exact algorithm and ownership

src/connection/admission.ts: bounded FIFO controller with maxActive=config.max, maxQueued=managed.queueLimit. Clock monotonic performance.now (inject clock and schedule/clear timer for deterministic tests). Each call computes total deadline = now+options.timeoutMs, acquisition deadline=min(total deadline, now+managed.acquireTimeoutMs). Validate positive finite bounded timeout (1..300000), reject pre-aborted, closed and full queue. Immediate grant only if active<max and queue empty; otherwise enqueue once; timer and abort remove waiting request and reject. On grant increment active BEFORE pool.connect; retain permit while acquisition pending even if caller deadline/abort/close rejects. If late client arrives after rejection, release exactly once, never invoke callback; if pool.connect rejects, release permit and preserve original error. Once checked out, clear acquisition timer/abort listener, no automatic callback race or pretending AbortSignal cancels SQL. Pass remainingMs=max(0,totalDeadline-now) and discard callback that marks tainted lease; callback success/error settles, then release client once (release(true) if discarded), finally release permit; never release while callback still executing. If release throws, still retire permit and preserve failure; no client returned twice. FIFO drain only while open; reject queued and pending acquisition on close, hold permits until actual acquire/callback settles. Closing does not forcibly interrupt callback. Track active/pending/queued with bounded structures; delete waiter and timer on every path; no accumulating abandoned promise queue.

src/connection/managed-client.ts: generic typed narrow lease port for source tests, e.g. C extends {release(err?:Error|boolean):void}, injected connect():Promise<C>, end():Promise<void>, clock/timers. Production instantiate with PoolClient and real pool; fake structural clients test without casts to a fake pg Pool. close is memoized Promise, synchronously stops admissions, rejects queued/pending, waits actual active count zero, then pool.end once; if work never settles, do not report false close or release live capacity. No automatic process kill. Existing raw pg pool operations still governed by driver. Use safe background error sink wrapper that cannot throw into idle socket event.

database.ts: createDatabase retains drizzle(pool) and composes managed runtime. checkConnection routes SELECT 1 through managed withClient using min(config.connectionTimeoutMillis,managed.acquireTimeoutMs) probe deadline; server statement_timeout stays unchanged. To bound caller-visible health response even if network hangs after acquisition, only checkConnection may race its returned result against a probe timer; underlying withClient retains actual permit until query settles, mark lease discarded on timeout if acquired, observe eventual rejection, clear timer; no general withClient execution race. This is a bounded probe response, not guarantee socket cancellation or successful shutdown. No change to authoritative query semantics.
