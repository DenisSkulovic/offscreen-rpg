# OBS-D03 candidate implementation contract

**Not dispatch authority.** Accepted guarantees from R5; detailed implementation candidate and numerical mechanisms require affected planner resolution before commission. Current contract sections below are the proposed narrow mechanism; no old packet precedence chain. No live mutation or compatibility bypass.

## Lock and pending
Public contract: acquireCustody(contextName,{mode='exclusive',...existingDeps}) returns a held handle with fd, mode, pendingPath, lockDirectory, cancelled, cancel(), close(); exclusive additionally exposes assertOwnPending(), begin({phase,tuple,operation='ensure',details={}}), advance({phase,tuple,details}), clear(). Shared omits mutation methods. acquireProofCustody is separate as specified below. Never promote a shared handle.

Same context/service lock basename and state root. Separate acquireProofCustody(contextName,deps) uses same private flock implementation with '-observability-proof.lock' suffix, exclusive only, no pending methods or independent mutation authority. Caller acquires platform then proof lock; release reverse order. acquireCustody validates context against actual dev/release profile context names; no path traversal or arbitrary key. Owner-private lockDirectory verified lstat, uid/mode, no symlink, stable dev/ino; open lock O_CREAT|O_NOFOLLOW|O_RDWR 0600, fstat/lstat same inode/dev/nlink=1. Check pending before and after acquiring both shared and exclusive platform locks. Use the owned-child primitive('flock',[mode==='shared'?'--shared':'--exclusive','--wait',seconds,'3'],{fds:[lockFd],deadline:lockDeadline,now,signal}) before exposing the handle. lockDeadline=min(caller deadline,phase start+10000); seconds is decimal floor((lockDeadline-now()-killGraceMs)/1s) to millisecond precision, additionally clamped by configured lockWaitSec; no spawn if nonpositive. For two proof-session locks the same 10s phase deadline is shared, not 10s each. Await outcome and require observed close/exit0 plus inode and pending recheck before returning. On ordinary failure close opened parent fd only after observed close; on close-unconfirmed retain fd and fail terminal operation, no lock capability returned, no further writes. Test actual competing flock, pre-abort, timeout and inherited descriptor retention; no synchronous flock wait. Do not unlock with flock --unlock: close only parent fd so inherited open file description remains locked until last child exits. Never unlink lock file. Proof lock no pending record, cannot substitute for platform capability. Shared and proof handles omit begin/advance/assertOwnPending/clear entirely.

Pending disk record schema2 exact top-level fields {schema:2,operationId,service,context,start,operation,phase,tuple,details}; use randomUUID, ISO UTC start; operation ensure/upgrade/persistence/outage; phase nonempty bounded string; tuple exact D02 fields, targetNamespaceUid null only ensure namespace phase before bind; details object no secrets. Ensure details empty; upgrade and persistence/outage reject until D06/D10 respectively install exact validators and transitions. D03 owns ensure only; no opaque details acceptance. Preserve legacy schema-less valid record as readable occupied fence, no adoption/update/clear; unknown schema or malformed record remains pending invalid. readPending public retains exactly {pending,valid}, read-only no mkdir; require owner-private regular non-symlink nlink1 file; bounded 256KiB JSON read, verify stable inode and metadata around read using O_NOFOLLOW fd; ENOENT alone means absent only when parent path is safe or positively missing. Invalid/unreadable/too-large/replaced -> pending true valid false. Legacy validator retains previous shape solely for fence recognition.

Exclusive begin requires held lock identity, no active record, no existing pending, not cancelled; structuredClone validated input (avoid mutable alias); O_EXCL|O_NOFOLLOW 0600, write/fsync/close, fsync dir. If partial/unknown write, retain whatever exists, latch failed and prohibit later mutation. assertOwnPending verifies open lock identity and exact current record by deep equality and file dev/ino from last successful write, returns clone; missing, replaced, invalid, changed content throws and latches authority failure. advance accepts phase/tuple/details, preserves operationId/start/operation/service/context; only tuple change permitted is ensure initial null -> actual namespace UID once during namespace phase; all other identity fields immutable. Compare own record, write unique same-dir temp O_EXCL|O_NOFOLLOW 0600, fsync/close, compare own again immediately before rename, rename over exact pending path, fsync directory, read/verify new exact record and inode, update in-memory clone only after success. On error retain pending and prohibit more writes; remove only provably owned unused temp file, never restore stale record or retry ambiguous rename. Compare-clear requires active exact own record and held lock, compare then unlink exact path, fsync dir, verify absence. Missing/replaced invalid is failure, not idempotent green. ordinary clear refuses after cancellation; D10 private outage-only finalization method is the sole narrow exception specified below. Separate cancellation from authority-failure latch; public advance also refuses after cancellation, private D10 restore-intent transition is the sole exception. Closed handle rejects all operations; close idempotent; if child still active refuse close until child settles. All cooperative writers hold same lock; compare+rename/unlink is not hostile same-UID filesystem CAS, no claim of hostile isolation.


## Owned child
Owned process primitive in forward.mjs (D03 creates primitive only; D05 adds forward orchestration). startOwnedChild(command,args,{fds,deadline,now,signal,stdoutLimit=1048576,stderrLimit=1048576,killGraceMs=5000,env,input}) -> handle {pid,closed:Promise<Result>,outcome:Promise<Result>,stop():Promise<Result>,onOutput(fn)}. closed resolves only on observed close (or proven no spawn); outcome is bounded terminal assessment, normally same as closed. For finite commands deadline includes all termination and close grace: g=killGraceMs (default5000, integer >=2), c=max(1,floor(g/5)); refuse if deadline-now<=g. TERM at D-g; KILL at D-c; at D unresolved outcome={ok:false,closeUnconfirmed:true,attempted:true,...}, not a synthetic close. On explicit stop/abort shorten effective D=min(originalD,now+g), use same schedule with immediate TERM. Late close only releases the actual active-child registration; never changes terminal outcome. For foreground children stop creates D=now+g. For foreground children D05 uses separate startup/session management, no artificial fixed session duration; child primitive accepts deadline=null only for explicitly foreground mode, stop still bounds TERM/KILL grace and awaits close. Abort before spawn returns settled attempted=false handle (pid null); no Python process launch. Spawn python3 absolute exec-owned.py path, expected parent PID, fd count, exact command argv; stdio [input===undefined?'ignore':'pipe','pipe','pipe',...fds], no shell, detached false. Optional input is an explicitly provided UTF-8 string or Buffer, at most 1MiB, validated before spawn; use child.stdin.end(input) once, no inherited ambient stdin. Attach stdin error listener before writing; EPIPE/write error latches failure and stops owned child, attempted=true if spawned. Drain output and await close on every path. Never include input in log/receipt. Only D07 proof-resource manifest creates and D11 quota create need this stdin mode; installer retains its existing private manifest path, no change to Secret custody. Wrapper Linux only, prctl(PR_SET_PDEATHSIG,SIGKILL), immediate getppid check, set fd3.. inheritable, execvp direct command. No script shell pipeline or subprocess children deliberately launched by wrapper; parent death guarantee is direct exec process, not cancellation of already accepted API writes or arbitrary grandchildren. All runtime Helm/kubectl command argv are direct binaries. Child env retains required PATH/HOME and unrelated safe settings, refuses or strips known target overrides consistently with D02; do not pass secrets in argv. No automatic process scan or PID reuse after close.

Attach error, close, stdout/stderr listeners immediately; bounded Buffer accumulation (byte counts, not string characters), continue draining after cap, latch overflow and stop; never log raw child output. onOutput registers internal observer for bounded startup-line parsing; buffer lines across chunks, no lost early line (replay existing bounded captured output to new listener), observer exceptions latch failure and stop. Stop/cancel/timeout latch once, TERM then KILL owned ChildProcess only if not exited/closed, remove timers/listeners on close. Result {ok,stdout,stderr,exitCode,signal,timedOut,cancelled,attempted,closeUnconfirmed}; retain bounded stdoutBytes/stderrBytes Buffers privately on the internal primitive result for internal bounded output handling (never serialize them); stdout/stderr remain decoded strings for existing parsers. ok only code0 and no error/timeout/cancel/overflow/stop latch. attempted=true conservatively once spawn requested, even if wrapper fails; false only proven no launch. Error event records failure but finalizes on close, not prematurely releasing fd. All finite callers await outcome; all custody release and snapshot cleanup require actual closed. On closeUnconfirmed latch terminal authority failure, retain pending and private snapshot, prohibit any further mutation/proof/restore/cleanup using uncertain authority; return sanitized failed result to CLI without claiming cleanup. The active handle retains fd; inherited child FD continues to fence even if CLI exits nonzero. Do not unconditionally await unresolved closed in a finally before failure receipt; do not pretend explicit close succeeded. Foreground close returns ok=false on same bound and retains authority. Exceptional non-reap/OS I/O limitation remains explicit.


## Mutation
runMutation retains existing custody/now/deadline/timeoutMs/signal/killGraceMs options, delegates primitive using custody.fd, effective deadline=min(worker/phase absolute deadline,now+timeoutMs) (timeoutMs is inclusive; no addition of grace). Install PHASE_TIMEOUT_MS namespace/secret=30000, Helm=210000, upgrade=240000, disruption patch=30000, all inclusive. Start only if full scheduled allocation fits work deadline; grace is inside each allocation. Require exclusive active own pending and not cancelled before start; compare record immediately before spawn. Register active handle synchronously, custody.cancel() actively stops it, abort signal invokes cancel; await bounded outcome and unregister only on actual closed, do not close custody until closed. On closeUnconfirmed return terminal failure and prohibit further authority use. After cancellation no later normal mutation; D10 restoration must use distinct explicitly authorized restoration adapter with fresh identity+own pending and bounded reserve, never reset cancellation latch or reuse normal runMutation to bypass it. Restoration adapter is owned by D10 and specified in its section; no live permission. D03 updates install runWrite handling attempted/confirmed/possible: unknown/timeout/cancel/invalid namespace result possible; confirmed only verified completed writes; prefix preserved, no later write on any failure. Existing failed phase tests must assert possible when request outcome uncertain, not no mutation. Ensure admission and finalization do not gain public bypass; D04 owns compare-owned shape finalization.
