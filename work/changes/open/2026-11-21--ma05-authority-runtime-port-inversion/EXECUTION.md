# MA05 | planner-owned dependency inversion design, NOT a Cursor algorithm yet

This file records a **selected direction**, a complete known edge matrix and the **decisions not yet safe to freeze**. It does not license code implementation. See [source map](SOURCE-MAP.md).

## Chosen boundary strategy
- **Authority core:** story/campaign domain rules, story owner/revision/lock, approved commands, campaign clock and transactional outbox facts remain authoritative SQL operations. No authority module imports Storyteller runtime implementation, developer fixtures or provider client.
- **Runtime implementation:** prepares/captures/replays Storyteller generation; honors admission/cost/pins; calls narrow authority operations for actual committed story transitions. A callback that executes within an existing SQL transaction must receive that **same typed Transaction** or be applied inside one explicit outer transaction: never convert it to post-commit async work.
- **Outer composition:** host/application creates both sides and injects selected, typed callable adapters. `@offscreen/application/stories` stays backward-compatible at public boundary while core is relocated to independent internal module(s) without back-edge. Prefer narrow named ports grouped by trust/transaction phase, **not** one service locator or `any` object.
- **No unjustified new packages:** first prove inversion within Application using import graph. MA06 owns later workspace movement after contracts, caller paths, generated outputs and direct-use tests are settled.
