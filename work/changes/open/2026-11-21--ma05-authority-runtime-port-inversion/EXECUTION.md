# MA05 | planner-owned dependency inversion design, NOT a Cursor algorithm yet

This file records a **selected direction**, a complete known edge matrix and the **decisions not yet safe to freeze**. It does not license code implementation. See [source map](SOURCE-MAP.md).

## Chosen boundary strategy
- **Authority core:** story/campaign domain rules, story owner/revision/lock, approved commands, campaign clock and transactional outbox facts remain authoritative SQL operations. No authority module imports Storyteller runtime implementation, developer fixtures or provider client.
- **Runtime implementation:** prepares/captures/replays Storyteller generation; honors admission/cost/pins; calls narrow authority operations for actual committed story transitions. A callback that executes within an existing SQL transaction must receive that **same typed Transaction** or be applied inside one explicit outer transaction: never convert it to post-commit async work.
- **Outer composition:** host/application creates both sides and injects selected, typed callable adapters. `@offscreen/application/stories` stays backward-compatible at public boundary while core is relocated to independent internal module(s) without back-edge. Prefer narrow named ports grouped by trust/transaction phase, **not** one service locator or `any` object.
- **No unjustified new packages:** first prove inversion within Application using import graph. MA06 owns later workspace movement after contracts, caller paths, generated outputs and direct-use tests are settled.

## Selected MA05D contract, executable only AFTER MA05C: frozen Storyteller wake facts

**Current verified source at post-MA05B HEAD (2026-11-21):** `campaign/follow-up-intents.ts` imports `storytellerNoticeTopicForWake` from `storyteller/records.ts` and `isProvisionalContextCapture` from `storyteller/capture-materialization.ts`. The first reads persisted outbox rows to recover the **frozen** notice topic, rejects mixed topics and missing topic; the second reads generation.kind and compares it to the neutral `storytellerContextCaptureKind`. Neither performs a provider call. The caller enqueues the consequence wake or the frozen Storyteller wake *within the same authoritative SQL transaction*. `story03-notice-topic-freeze.test.mjs` has an existing exact disposable SQL harness and cases for legacy/distributed flag flips, missing and inconsistent topic history.

**Chosen ownership direction, pending focused packet and post-C branch recheck:**
1. Move the **immutable notice topic string literals** `storyteller.profiled.v1`, `storyteller.distributed.v1` to a neutral `@offscreen/contracts/storyteller-notices` subpath, separate from the MA05A `generation.kind` identities. Preserve `storyteller/records.ts`'s old two named exports and its admission-time environment flag selector without changing topic choice.
2. Place the **transactional read-only helpers** `readFrozenStorytellerNoticeTopic(tx,operationId)`, `storytellerNoticeTopicForWake(tx,operationId)` and `isProvisionalContextCapture(tx,generationId)` together in **`application/src/campaign/storyteller-wake.ts`**, using `@offscreen/db/{outbox,outbox-schema,generation-schema}`, `drizzle-orm`, and the neutral contract constants. This authority-facing adapter reads the same rows using the same tx; no environment-derived wake decision, no SQL mutation, no duplicate implementation.
3. `storyteller/records.ts` imports/reexports both notice-topic reader functions from `../campaign/storyteller-wake`; keeps `selectStorytellerNoticeTopicAtAdmission` as the current runtime admission-only selector and other runtime functions untouched. `storyteller/capture-materialization.ts` reexports `isProvisionalContextCapture` from the same Campaign helper (old module export remains available to direct consumers). `campaign/follow-up-intents.ts` imports both functions from `./storyteller-wake`, deleting its two runtime imports.
4. The new helper becomes an independently movable **authority SQL cohort** in MA06; it does **not** own dispatching, provider routing or Storyteller generation. This avoids adding a domain-specific transport protocol to generic `@offscreen/db/outbox`, avoids runtime→authority→runtime cycles, and retains historical topic/error semantics. No table migration.
5. Focused proof: current `story03-notice-topic-freeze.test.mjs` SQL suite plus a new disposable-generation fixture with `generation(kind='storyteller.context-capture.v1')` true, ordinary generation false, absent generation false; strict equality of old/new re-exported function references; source graph shows both `campaign/follow-up-intents → storyteller/*` edges gone; same transaction/notice error strings preserved. No provider calls. Parent only joins after the negative SQL test succeeds.
