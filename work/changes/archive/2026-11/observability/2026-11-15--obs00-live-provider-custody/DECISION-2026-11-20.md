TURN04's future real-provider validation needs a separate explicitly approved distributed-provider design and a spending approval. Neither is needed for local, provider-disabled OBS00-B implementation and tests.

## Chosen minimal persistent authority (not an account/billing redesign)

**A. `storyteller_current_platform_policy`:** one explicitly selected active row with `revision`, typed `usageEntitlementProfileSchema` profile (platform ceilings), `enabled=false` by default and a versioned *exact route map*: route key, provider, model, priceVersion, funding modes and allowed execution policy/source digest. Strict full-row validation; no permissive environment fallback. A missing row/revision/profile/route is **DENY**. Do not seed a production enabled row.

**B. `storyteller_current_owner_grant`:** scoped to one verified `user.id`, exact `storyteller_funding.id`, and exact `storyteller_run.id` (whose accountId must match that funding ID); one immutable ID and mutable positive revision, typed entitlement profile, optional typed restrictions, `enabled`, `revokedAt`, expiry or explicit no-expiry, current route/funding scope, explicit operator/approval identity and updatedAt. **No implicit first-user grant, default enabled row, paid seed, environment entitlement, or client-supplied tier.** Account ownership is independently established by this grant and checked against persisted generation owner plus source story/draft owner. A funding row's money is not an entitlement. A prior grant re-enabled after revocation must bump revision, never restore old captured authority by coincidence.

**C. Resolver:** `loadCurrentDispatchAuthority(tx, lockedAttemptAndOperation)` reads `generation` source and owner, `story` or `story_draft` owner as applicable, platform policy, grant/restrictions, route map and funding/run stop flags. Validate frozen `generation.input`, `storyteller_operation`, `storyteller_attempt`, `task.execution` account/run/provider/model/priceVersion and task source ID. Recompute with **existing** `resolveEffectiveUsagePolicy` using the **captured requested route and funding mode**, then deep-compare via `retainsIndependentCurrentAuthority`. All contributing platform/profile/restriction revisions must match captured `task.resources.authority.policy`. Binding is *per attempt*, including repair/memory rounds. Missing ownership, version, disabled grant, banned route/model, expired grant, invalid typed policy or DB failure is deny. Deny must expose safe reason codes, not secrets.

The exact two-table model is a bounded recommendation based on the absence of a present policy store; implementer should inspect current migrations and user/draft schema before committing the physical FK details. Do not make a full subscription/Stripe or multi-tenant permission system. The route map can be immutable typed JSON in the one platform row rather than a separate route table; budget accounting remains untouched except its dispatch gate.

## Atomic dispatch semantics and lock order

**One transaction = one authorization decision** for moving `storyteller_attempt` from `reserved` to `dispatched`.

1. Existing `createStorytellerBudget.dispatch` obtains its existing advisory funding lock `pg_advisory_xact_lock(714092631)`, then funding/run, attempt and operation locks. Preserve existing lock order.
2. Pass **attempt ID + trusted DB owner/source identities**, not `authorityGranted:boolean` as a sufficient authorization for any billable real dispatch. Within that same transaction, lock policy and current grant consistently (shared locks acceptable if revocation UPDATE conflicts), validate ownership/policy/route and compare to the exact committed generation/task. All grant/revocation mutators must respect this same serialization/lock order. If a new parallel route can call `dispatch(id, execution, true)` without SQL authorization, the security goal is **not met**.
3. In the **same transaction**, check funding stop, run enabled and unknown dispatched/uncertain attempts, plus current policy/grant; on any refusal, perform existing reserved→**unsent** release of account/run/operation/window reservations. No provider call; no invented uncertain charge.
4. If granted, commit the usual `reserved→dispatched` attempt plus window/operation updates and a small audit record of current policy/grant revisions and grant ID **without private prompt or API key**. That durable transition is the **potential-liability boundary**. Send only the **already-reviewed frozen wire** after commit. If process crashes after commit but before HTTP, existing conservative uncertain/recovery path remains authoritative; never auto-repeat as "not sent".
5. **Revocation race rule:** revoked/changed policy committed **before** the dispatch transaction's authority decision must deny; a revocation serialized *after* a completed dispatch transition does not retroactively annul possible liability. This is a precise statement, not a promise that a network send is impossible after every future revocation wall-clock instant. Test both commit orderings with separate DB connections.
6. No story `FOR UPDATE` in the accounting transaction, no model/network/DocumentStore activity inside it, no nested budget transaction, no new funding reservation implementation. The live owner/route reads may use targeted key-share/reference locks as necessary, but must not deadlock with the game command story lock. Retry lost DB connections as **deny/hold**, never as permission.

**Compatibility:** adapt existing provider-disabled test doubles that inject a pinned `dispatchAuthority`: they are **synthetic fixtures**, not a valid production grant source. Migrate any test that expects successful SQL `budget.dispatch` with a Boolean to insert explicitly owned **synthetic disabled-by-default test policy/grant** in an isolated database; do not weaken the gate or rewrite assertions as "allow by test callback". Re-run OBS00-C's previously completed mock-wire suite to prove no altered serialization/provenance. Empty real production DB continues to deny.

## Complete bounded acceptance, with zero billable send

- **Pure:** disabled/missing platform, disabled/missing/revoked/expired owner grant, owner/story/draft mismatch, account/run scope mismatch, route/model/price mismatch, restrictions, changed revisions and policy tightening all refuse. Equal **independently recomputed current** source is the only positive.
- **Disposable SQL:** two separate connections race owner grant revocation vs reserved→dispatched; whichever commits authority first wins. No positive decision after prior committed revoke. A second worker on same attempt does not dispatch; after reserved→unsent, exactly one release of funding/run/window; after dispatched/uncertain, never automatic retry.
- **Wire:** normal, repair, memory and held review use OBS00-C's single frozen serialized body and persisted per-attempt review SHA; unauthorized attempts result in 0 mock transports. Existing 15/15 C receipt is **historical**; rerun after modifications and record actual new results, don't re-implement it.
- **Safety:** no provider HTTP in any test; make global `fetch` throw, use disposable database with safe naming, fake keys, zero external cost, no production grants. Check `apps/worker/src/activities/storyteller-distributed-execution.ts` still refuses provider mode; the Kubernetes scripted-turn tests still run.
- **Proof ledger:** actual command, source SHA, 0 paid calls, SQL FK/constraint migration proof, test PASS/FAIL/NOT-RUN, race traces, no grant created on production, current QUEUE. Only after B is tested and code is live behind independent grants may OBS00 be archived **Done**. **A successful local mocked dispatch does not authorize TURN04 paid send.**
