## Architectural decision

**Preserve the key security boundary:** `apps/worker/src/bootstrap/config.ts:forbidBroadDatabaseOnExecutor` deliberately rejects all general SQL credentials. The executor may hold an executor-scoped GA bearer credential and eventually an independently injected provider key, but **not** a DB connection, object-store keys, a story-publish token or a general account budget. The existing `runDurableWriterMissionModelRound(database,input)` and `advanceDurableWriterMissionProviderStep` therefore **cannot be directly invoked** in an execution Worker process. GA has SQL/DocumentStore authority and must prepare/finalize; the executor sends the pinned model request and reports its delivered/failed/unknown outcome over the authenticated private route. Temporal workflow history stores IDs and status only, not private model inputs/outputs.

Build a **versioned, private two-phase Writer round protocol**, invoked by an already-admitted **v3 continuation mission** in a provider-free, explicit test path:
1. `POST /internal/v1/writer-rounds/:missionId/:ordinal/prepare`: executor-authenticated GA verifies persisted mission/context/actor/root and funded operation, then chooses the exact **model/policy/price from a trusted GA-installed fake-only server policy** checked against the pinned capture and persisted budget snapshot (the initial full price policy does not yet exist on the mission); prepares frozen request wire from stored Library/tool summaries and **atomically reserves/marks possibly-dispatched** via the existing WR09A budget/Writer step helpers. Returns a single attempt-bound immutable `writer-round-execution.v1` envelope **with fully pinned provider policy and canonical decimal-string money fields (no bigint across JSON)** with a byte-bounded serialized provider wire, SHA, model/provider policy and attempt identity. **No raw secret.**
2. Execution Worker validates the envelope, checks the **fake** provider adapter's synchronous wire preflight, sends *once*, and `PUT /internal/v1/writer-rounds/:missionId/:ordinal/outcomes/:attemptId` posts a strict delivered/sent-failed/unsent/unknown outcome (plus exact pinned wire hash and bounded response bytes). The GA **does not call provider HTTP**. GA validates caller role, durable attempt, request and usage, persists the private response object, and atomically settles the existing budget attempt + Writer pointer/step using WR09A's internal accounting helpers. On replay of an already-terminal attempt, read and return status/IDs, never resend; rehydration and tools can be processed by the existing durable round interpreter at the GA boundary under a separately bounded test adapter, **not** in the executor.
3. On any possibly-dispatched uncertain response (including HTTP timeout, response lost, process death), the executor **never reclaims/resends the same attempt**. A known unsent failure uses the existing confirmUnsent path, but an ambiguous network failure does not. GA's status/result replay can survive executor restart and must never double-charge.

**Critical scope separation:** The current distributed `executeFrozenStoryteller(generationId)` contract and `storytellerDistributedV1` workflow are a **different v1 generation pipeline**. Do **not** turn every existing `StorytellerTask.execution.mode='provider'` into a Writer v3 mission or reuse generationId as missionId. Implement a dedicated `WriterRoundPrivateCustody` route and executor-side `executePreparedWriterRound` adapter, proven through direct injected-fake HTTP tests. Actual Temporal Writer wake/mission lifecycle scheduling and Launch/provider policy switch are **subsequent WR10B work**. Preserve all existing scripted workflows.
