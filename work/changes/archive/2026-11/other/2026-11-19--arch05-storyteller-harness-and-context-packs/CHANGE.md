# ARCH05 | Storyteller harness, role recipes and context packs

**State:** Done (2026-11-19)  
**Kind:** documentation  
**Owner direction:** One Storyteller task is packed before inference. Known current state is injected. Related material is a short orientation with handles. Unknown history is one intention-level query whose deterministic backend does the reads. Role recipes stay separate. A normal scene is one composition call.  
**Selection:** Authorized documentation Change. No application code, no migration, no provider call, no Cognee install, no vector database, and no code-mode runtime.  
**Parent program:** [Distributed architecture laboratory](../../../../README.md#distributed-architecture-laboratory-new-2026-11-19)  
**Baseline:** `21792e0e`. ARCH03 is already on this branch. ARCH02 is already on this branch.

## Outcome

The packing rule now lives on the technical headings below. This Change does not implement a packer. Today's code does not assemble P0–P3 this way. `prepareStorytellerTask` still builds a `bounded-scene.v3` request from a caller-supplied snapshot. Ordinary admission still captures `single-turn.v1` or `repairable-turn.v1` with tools disabled. A funded `memory-exploration.v1` recipe can ask and read inside one operation. That recipe is the landed controller, not the pack.

Known current state is injected: branch, checkpoint, canon root, mechanical constraints, receipts, intent, actor knowledge, and the pinned rule fragments that apply. Related material is a short orientation with stable handles. Unknown history uses `ask_memory`. The deterministic backend does the reads. `read_memory` opens one exact source when the wording matters. Role recipes stay separate. A normal scene is one well-packed composition call. It is not a chain of mandatory models.

Cognee, vectors, and code mode stay unselected. Code mode is not the default. Model-generated shell, SQL, filesystem, or network writes are prohibited. Search indexes are not authority. The engine commits the checkpoint. The Storyteller proposes and does not commit it. There is no Game Economy service.

## Positive and negative acceptance

- **Positive:** A reader can say how one task is packed, which recipe is included, and that a normal scene is one composition call. The same reader can see that the pages describe a selected pack and that today's code still uses the narrower recipes.
- **Negative:** At scene 10 the king is alive and the hero holds a sword. At parent scene 20 the king is dead and the sword is gone. A fork from scene 10 must be packed with the living king and the held sword. An `ask_memory` lookup on that fork must not return the scene-20 death, including through a stale global index. A rumor that the king died is an attributed rumor, not a committed fact.
- **Reading check:** The negative is present on [Task pack](../../../../../../docs/technical/storyteller/context-selection-and-recall.md#task-pack--selected-target-2026-11-19) and on [Selected compilation and tool contract](../../../../../../docs/technical/storyteller/prompts-and-tools.md#selected-compilation-and-tool-contract). The product retrieval route still allows one or two ordinary-language questions. The landed controller still caps a round at two.

## Semantic claim map

Before this Change, task roles said not to invoke every role on every turn, and the compilation heading numbered an older P0–P6 compile list. The two-loop diagram retrieved and then composed, without saying that known state is injected and unknown history is one intention-level query. Context selection deferred role recipes and pre-injected packs to this packet. The fork read oracle already kept a scene-10 king alive. It did not say the fork is packed with the held sword, and it did not say an `ask_memory` lookup must miss the scene-20 death through a stale global index.

After this Change, those headings state the pack. P0 is stable authority plus one role recipe. P1 is the injected present. P2 is a short orientation with handles. P3 is one intention-level query whose deterministic backend does the reads. P4 is optional and capped. Code mode, Cognee, and vectors stay unselected. The pages say plainly that they do not implement the packer. Product pages and application code stay as they were.
