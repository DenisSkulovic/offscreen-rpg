## Outcome and decided algorithm

Provide a **versioned v2 payload** and SQL selector that can persist full active fictional state, while keeping existing v1 hashes/reader/schema unchanged. Reuse the existing content-addressed scene checkpoint store; **no new storage service/table**.

- In `packages/documents/src/schema.ts`, rename existing exported `sceneCheckpointSchema` implementation to `sceneCheckpointV1Schema` (same shape, same validation) and add `sceneCheckpointV2Schema`; exported `sceneCheckpointSchema=z.discriminatedUnion('format',[sceneCheckpointV1Schema,sceneCheckpointV2Schema])`, `SceneCheckpointV1`, `SceneCheckpointV2`, `SceneCheckpoint` union types. Keep the existing 1-MiB canonical JSON cap on both.
- V2 retains v1 **identity, canon, ancestor, source, pins and passage** fields verbatim (reuse one shared base schema definition to avoid duplicating behavioral validation). Use `format:'offscreen.scene-checkpoint.v2'`, `stateSchemaVersion:2`, and `fictionalState` in place of v1's quiescent-only `mechanics`. The schema represents **all** active states, not silently coercing them to quiescent.
- `fictionalState` is a strict discriminated union: `{mechanicsAbsent:true, continuityNotes, activeSceneScope}` or `{mechanicsAbsent:false, character,items,storyFacts,activityOccurrences,location,gameSecond,clock,pace,settingsRevision,content,continuityNotes,activeSceneScope,holds,offer,acceptedActivityPlan,activeActivityId,activeActionOperationId,situationAuthorization,worldConditions,activeActivities,worldObligations,activeAction}`. Reuse the exact existing schema definitions for character/items/facts/clock/pace/world conditions and v1 anchor. Import no `@offscreen/contracts` or `@offscreen/game` into Documents (would cause package cycle). For open-work fields define strict self-contained **versioned snapshots** that preserve their stored JSON input faithfully rather than inventing defaults: `holds` max20 with disjoint typed kind/id, `offer` typed id/source/meaning + bounded opaque versioned *payload* (do not grant permissions based on this schema alone), `acceptedActivityPlan` bounded versioned payload, active activities max256 with id/state/revision and bounded versioned plan/progress payload, world obligations max256 with id/revision/state/dueGameSecond and bounded versioned definition, active action nullable with id/status/start/target and bounded versioned pending data. Every opaque field is a **historical capture** only, never permission to execute; later WR05 writer verifies against canonical live validators and WRC fork requires its own typed conversion.
- Shared refinement verifies scene-one transition/null, root hash/revision, ancestor provenance, passage content-vs-hash, uniqueness of pins and new activity/obligation IDs. Keep `SceneCheckpointV1` parse behavior bit-for-bit; don't rewrite persisted objects or silently upgrade a v1 read.
- `packages/db/src/schema/stories.ts`: change **only** the check constraint `story_scene_checkpoint_schema` from `=1` to `IN (1,2)`. Supply one Drizzle migration under `packages/db/migrations/` (config: `packages/db/drizzle.config.ts`); SQL transition: `ALTER TABLE story_scene_checkpoint DROP CONSTRAINT story_scene_checkpoint_schema; ALTER TABLE story_scene_checkpoint ADD CONSTRAINT story_scene_checkpoint_schema CHECK (state_schema_version IN (1,2));` with migration journal metadata generated/updated using the established tooling, not an independent table rewrite; preserve all unique keys/foreign keys and selector columns. **No backfill**.
- `packages/documents` existing local/S3 object read/write functions continue to use exported union schema; no storage backend rewrite. A v2 object is accepted by the same store and hash logic; historical v1 reads remain the same.
