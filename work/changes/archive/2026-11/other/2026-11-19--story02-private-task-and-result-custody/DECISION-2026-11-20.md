## Exact remaining defect: trusted executor policy is not authoritative SQL custody policy

`apps/worker/src/activities/storyteller-distributed-execution.ts` refuses provider-mode tasks. But `packages/application/src/storyteller/execution.ts:readCommittedTask` currently parses and returns **both** scripted and provider tasks; it does not check `task.execution.mode`. The same loader serves `fetchCommittedGeneration`, `claimGeneration`, `saveValidatedResult` and `readValidatedResult`. `claimGeneration` accepts any existing `earliestAttempt` regardless of `requestedProvider` and its state. For provider-mode it can construct a `provider-custody` attempt with real funding IDs. `saveValidatedResult` may write a valid saved result into the earliest existing provider attempt if an executor-token caller supplies it, because it doesn't require a scripted-only attempted lane. This is **source-proved**, not an exploited failure or claim of an actual paid send.

The internal executor bearer is a **trusted service-wide role**, not a generation-scoped capability. Current role tests prove browser/story/control tokens cannot use custody or vice versa; they do **not** prove a compromised executor credential cannot enumerate known generation IDs across stories. Don't claim arbitrary one-task isolation. Strong per-attempt delegation/token scope would be a separate security requirement, not a retrospective acceptance criterion for today's closed first-slice internal service.

**Chosen fix (T05):** enforce `scripted`-only custody **inside Game Authority's database-backed application seam**, not solely in the client/Temporal executor. For a provider-mode task, no task body, claim, attempt mutation or result read/save from the scripted custody endpoints; use a stable explicit fail-closed refusal reason `unsupported-execution` (or `provider-mode-disabled`, choose one name and use consistently) in the versioned DTO, not a misleading 200 claim or `unreadable-task`. Ensure none of the four operations can bypass this restriction. Existing `storytellerAttempt` rows not belonging to the scripted-custody lane must **not** be treated as successful scripted claims or writable attribution. Preserve genuine scripted duplicate claims, same-hash replay, held/claim-without-result semantics and idempotency; never mutate a real provider attempt or its charge on refusal.

This fix **must not** change `createStorytellerExecution.complete`'s separate local provider path or block the future explicitly designed paid path. It protects the currently shipped distributed custody **only**. Any future provider-mode executor protocol needs its own OBS00/Budget/attempt authority, not permission inherited by loosening the scripted endpoint.
