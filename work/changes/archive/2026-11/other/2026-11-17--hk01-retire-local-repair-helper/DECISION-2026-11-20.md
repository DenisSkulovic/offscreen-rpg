# HK01 | Source-backed decision: replace the local recovery CLI safely

**Decided 2026-11-20; source inspection:** live GitHub main through `4b921cec` with direct review of the legacy CLI, `saved-response-settlement.ts`, `budget.ts:settle/uncertain`, `execution.ts`, `dispatch-review.ts`, provider `openrouter.ts`, generation/attempt/review schemas, and the uncertain-work runbook. **Status:** planner blocker resolved for bounded coding tasks; no replacement implemented, no database operated on, no provider called, no live settlement performed. HK01 remains open/unselected.

## Verdict

The old `reconcile-storyteller-response.mjs` is the **only supported/documented local operator pathway** from a *saved invalid provider result* to a settled already-uncertain attempt. It is not safe to simply delete. But the missing source/attempt association **does not require a new provider architecture**:

1. `createOpenRouterProvider.recordResponse` saves `requestSha256`, provider response bytes, HTTP status, receivedAt, optional response/header provider ID, and request purpose to the ignored `data/story-local-evidence` directory. `createLocalStoryProvider` writes files using `wx`; this prevents accidental overwrite, **not tampering**.
2. `prepareReviewedDispatch` persistently inserts `storyteller_dispatch_review` for the **exact attemptId/generationId**, with `packetSha256` of the actual reviewed send. The provider rechecks its frozen wire digest before transport. Thus `evidence.requestSha256 === review.packetSha256` is a strong **request-association test**.
3. `generation` already persists `input`, `state`, `statusRevision`, `attemptId`; `storyteller_attempt` persists provider/model/policy/state, dispatch timestamp, reconciliation and charge; `storyteller_operation` and funding/run rows own accounting. Existing `budget.settle` takes funding + attempt locks, rejects conflicting repeat settlement, updates attempt, generation, operation and accounting **atomically**, but currently does not require a recovery-specific generation-state/version fence or write an operator/evidence audit. That is the narrow missing mutation contract.
4. `saved-response-settlement.ts` **only** gates caller-supplied strings and `usage/telemetry` before calling budget.settle; its 5/5 mock tests are not proof of provenance, cost validation, a database gate or operator parity.

**Important limitation:** a request digest identifies the request, not the authenticity or specific transport receipt of a local response file. For identical request bytes sent by different attempts, `packetSha256` alone cannot distinguish their responses. Therefore the safe local operator pathway must **refuse ambiguous evidence** unless another already-stored provider response ID definitively binds it; do not claim cryptographic provider attestation. An operator's explicit, reviewed approval is still required for any accounting mutation.

## Selected narrow implementation, no new global subsystem

### H1: Pure evidence parser/inspector (HK01 T02)

Add an I/O-free strict `inspectSavedInvalidRepairResponse` validator beside `packages/application/src/storyteller/saved-response-settlement.ts` or a focused module. Inputs are **trusted captured task, generation+attempt identity, exact reviewed request digest, raw bounded file bytes**; optional attempt recorded providerId. Reuse provider request/response normalizers/diagnostics, `usdToMicrousd` and `storytellerTaskSchema`, don't reimplement parser policy. Require `generation.attemptId === attempt.id`, recipe `repairable-turn.v1`, approved/actually dispatched review for this attempt (review was not superseded), task provider execution and route match, recorded response request digest matches persisted review, HTTP 200/complete envelope, body id matches captured headers/provider ID when present, correct model/provider and request purpose, safe integer token counts and total arithmetic, finite bounded cost, invalid-output **repairable candidate** with non-null diagnostic. Valid successful output is **not** this recovery case. Emit redacted typed refusal or immutable `ProposedSavedRepairSettlement` with the exact evidence byte SHA256 and derived usage/telemetry/outcome. No caller-settable charge or generation outcome. No DB, filesystem, provider or budget writes in this layer.

### H2: Read-only operator preview, exact binding (HK01 T03)

Create a separately owned operator runner (prefer dedicated maintenance/tool scope compatible with forthcoming DXK04 scripts). Require explicit local **approved kind** context or a named disposable test database; never default to production, stage or an arbitrary `DATABASE_URL`. Evidence file must be a bounded regular file resolved **inside** an explicitly selected ignored local evidence directory (reject symlink escape, traversals, oversized JSON). Read but **do not change** generation+attempt+dispatch review records and request hash; check state/revision, funding/run identities, request digest, any known provider ID, and **ambiguity** (a second potentially matching uncertain/dispatched attempt with the same wire digest and no differentiating provider ID). No proof? **HOLD**, never guess. Display redacted plan: exact IDs, state+revision, reviewed request hash, evidence hash, provider response ID, cost/tokens, operation result `failed / invalid_output / continue`, and a deterministic plan fingerprint. `--plan` must neither open provider HTTP nor mutate SQL. No secret, raw prompt or provider response printed. Keep the old operator CLI untouched in this task.

### H3: Guarded audited apply (HK01 T04)

Accept `--apply` only with exact plan fingerprint, explicit human-confirmed attempt ID and operator/reason identity. Pre-read the exact evidence bytes then pass the **derived** result, never operator-entered charge. Revalidate ownership, `generation.state='uncertain'`, unchanged `statusRevision`, `generation.attemptId`, `attempt.state='uncertain'`, review id/hash/state and evidence digest in the **same SQL transaction** that settles. Reuse existing `createStorytellerBudget().settle`, **not** a second accounting implementation; a narrow optional recovery fence/audit hook in `budget.ts` is acceptable and required if that is the only way to enforce transaction atomicity. Preserve lock order and normal callers unchanged. A dedicated small immutable audit record unique by attempt ID should store operator identity, reason, plan fingerprint, review/evidence digests, original state/revision and settlement result in that transaction. Inspect existing `storyteller_execution_stage` first; its stage receipts lack operator/reason semantics, so do **not** silently overload it as a financial operator audit.

The budget's normal `settle` is already idempotent on matching settled usage. For operator apply, same previously audited plan may return `already-applied` without new charge; different evidence/intent must conflict; an unknown previously settled attempt without matching audit is held. Simulate concurrent applies and audit-write rollback using a **disposable SQL database only**, with zero provider calls. Never let a successfully settled attempt silently turn `storyteller_funding.stopped` to false: the current code preserves that hold. Re-enabling provider admission is a **separate** future approval and explicitly not HK01.

### H4: Retire legacy only after parity (HK01 T05)

Prove the known valid-invalid-repair path and negatives from the old CLI with pure+disposable SQL tests: wrong generation/attempt, non-uncertain/revision change, provider/model/request digest mismatch, ambiguous identical-request attempts, providerId mismatch, malformed response, token/cost invalid, valid model output, non-repairable recipe, replay, competing apply, audit failure rollback, missing review/evidence, wrong environment. Verify no double charge, no provider resend, no implicit funding reactivation. Then remove `scripts/repo-tools/reconcile-storyteller-response.mjs`, replace its reference in `docs/runbooks/uncertain-work-recovery.md`, `local-storyteller-rehearsal.md` as needed, housekeeping audit, and current developer docs. Preserve dated history accurately. Check `package.json` and all active consumers; coordinate CLI naming/placement with DXK04/DXK06 (Kubernetes-only app runtime). Run wiki change guard and scoped tests. Archive **only with evidence**, not on planning approval.

## Why this should no longer be PLANNER-BLOCKED

The required source, association route, acceptable strict-refusal semantics, state-lock fence, accounting owner, audit destination and proof cases are determined above. The remaining effort is **implement/test**, not an undecided product feature or an external credential prerequisite. Explicitly gate the live operator action: no shared DB, existing uncertain local financial row, provider send, or SQL mutation by an agent without separate authorization. If current source diverges, report the exact different field/schema and stop; don't invent a broad provider custody redesign.

## Adjacent work and exclusions

- **OBS00** governs independent live paid dispatch authority, not this saved-response accounting; there is **no dependency** on implementing OBS00 for provider-free fixture tests.
- **DXK04/DXK06** govern package command modernization and legacy environment removal. This recovery CLI must be a maintenance operation, **not** a host application startup path or reinstated Docker Compose route.
- Source-backed repair of unknown evidence is deliberately unsupported; it remains an uncertain hold. No provider lookup, charge fabrication, successful-output reconstruction, automatic paid retry, account unstop, schema-wide rewrite or production staff console.
