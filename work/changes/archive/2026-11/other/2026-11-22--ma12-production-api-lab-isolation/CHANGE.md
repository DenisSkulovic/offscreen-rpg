# MA12 | Remove developer Lab code from production API runtime

**State:** Done (historical source scope; owner closure 2026-11-27). Current main manifests inspected at `4574db0ab19de2d7254afca0c2faf19a2123697e`: `@offscreen/api-lab` depends on API and Lab Support, while production API declares neither Lab package as a direct dependency. Legacy artifact-specific acceptance retired ahead of monorepo redesign. No new build, graph, artifact or runtime PASS; existing source untouched. Earlier planning below is historical, not dispatchable.

**Observed defect:** `apps/api/src/app.ts` imports Lab Support at top-level even if `developerTools=false`; `apps/api/package.json` requires Lab Support in production. Four Chamber/QA Nest controllers in three API files depend on Lab implementation. Production bootstrap `src/main.ts` does not activate developerTools, but the Lab dependency is still present in the production install.

**Decided design:** create one outer workspace `tools/api-lab` named `@offscreen/api-lab`, depending on API and Lab Support, **never the reverse**. Move `chamber-tools-controller.ts`, `chamber-lab-controller.ts`, `qa-journeys-controller.ts` from `apps/api/src/modules/stories` into that workspace, preserving their four controllers, URL paths, authenticated owner checks, body validation and DI tokens. The production `createApp` accepts a narrowly typed optional `ApiOptionalExtension` (Nest controllers/providers plus optional Story Engine fixture responder), defined entirely with base API/Story Engine/Nest types. New outer `createLabApp` constructs this extension using createChamber/createQaJourneys/createLabWorkbenchService and invokes ordinary createApp. Production main has no Lab factory or import. The old `developerTools`, `qaContext`, `chamberStorytellerControl` options become outer Lab factory arguments, not production API options.

**Known consumers:** `tools/chamber/src/main.ts`, API Integration helpers `app-integration.ts`, `boot03-distributed-app-integration.ts`, `story03-causal-multiprocess-harness.ts` currently enable developerTools; migrate them to `@offscreen/api-lab/create-lab-app`. Other API-only callers remain on `@offscreen/api/app`. API Integration and Chamber receive a declared API Lab dependency. API Lab imports stable API host-contract exports for `IdentityService`, `OPENINGS`, and types, not deep relative workspace paths.

**Packaging source finding:** `infra/images/release/prepare-runtime-tree.sh` currently copies **all** `packages/*/dist` into each release image plus the root pnpm node_modules, regardless of application dependency closure. Thus removing API's Lab dependency alone is NOT evidence of artifact exclusion. MA12 additionally owns a read-only workspace production dependency-closure helper and targeted runtime-tree copy fix; keep other release targets functional. **Acceptance explicitly includes a prepared API runtime tree without `packages/lab-support`, plus an included `apps/game-authority` runtime dependency where the API manifest requires it; image size/cache improvement is measured, not assumed.**

**Exclusive writes:** `apps/api/src/app.ts`, three moved controller files, new `apps/api/src/lab-host-contract.ts`, `apps/api/package.json`; `tools/api-lab/**`; `tools/chamber/src/main.ts`, manifest, exact developer caller files; `tools/api-integration/test/helpers/{app-integration,boot03-distributed-app-integration,story03-causal-multiprocess-harness}.ts`, manifest and any direct developer-only caller genuinely identified; **`infra/images/release/prepare-runtime-tree.sh` and a new `production-workspace-closure.mjs` + focused test in that same directory**. No changes to app-release/install.sh or TURN03 harness. Shared lockfile is custodian-owned. **Never** alter `apps/game-authority/**`, `apps/worker/**`, `packages/story-engine/src/**`, `infra/kubernetes/**`, TURN03 fixture/scorecard, or shared lockfile/catalog before custodial join.

**Done when:** production API manifest and source have zero Lab runtime dependencies; ordinary API build and auth still pass, Lab factory preserves all old authenticated dev endpoints and test harnesses, graph one-way `api-lab -> api`, and no new provider/DB unsafe operation.
