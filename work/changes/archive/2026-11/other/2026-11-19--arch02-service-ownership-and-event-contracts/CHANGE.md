## Outcome and motivation

Ratify proposed process ownership for web/API, the engine, the Storyteller, and notifications. The player edge stays Next.js for the interface and NestJS for authenticated HTTP and the SSE hint. Neither owns a world-state change. Do not add another backend-for-frontend, require WebSockets, or move the story SSE hint onto the broker. GET remains the truth. A Game Economy service was considered and rejected. Optional media and real SaaS billing may be named as later platform processes. They are not required services, not fictional-world services, and not proven. The engine is the single consistency boundary for a committed scene checkpoint. A future fork from any committed scene must reconstruct that scene's mechanical state from the engine's committed record. It must not assemble history by asking whichever service answers first. Web/API, the Storyteller, notifications, optional media, and SaaS billing do not own that historical state. A fork must not inherit later writes from the parent timeline. This is selected future behavior. The current journal and the current-only fork do not implement it. It is not proven and it is not built. A later Storyteller process consumes version-pinned task context and bounded, branch-scoped memory. It does not receive an unrestricted mount of all campaign files or a global graph as its private truth. It returns descriptive proposals with provenance. It does not commit the scene checkpoint or the scene's canon root. A Redis cache, an object listing, or a search index is a rebuildable aid. It must not leak later parent or sibling facts into a fork. ARCH03 owns the retrieval and publication design. This packet does not design that mechanism and does not install Cognee or any index. This limit is selected future behavior, not a built service. Separate authoritative commands, business events, and Temporal workflows. For each retained service row, state authoritative data, incoming commands, produced events, dependents, and failure policy. Record outbox and inbox dedup, event ids, aggregate and version keys, schema evolution, and cross-service consistency. Classify direct HTTP, async broker events, and Temporal orchestration. Label each claim current runtime, proposed target, or proven.

The reader inference to fix: the laboratory can name a later process split without turning the text game into a market, and without describing that split as the running game. The modular monolith on Compose remains the current runtime. Nothing new is proven.
