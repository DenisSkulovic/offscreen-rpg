## Selected contract
- `plan`: pure, **valid JSON** machine receipt; 250000n serialized to decimal string, never float. No `kubectl`, DB connection or secret access.
- `status --target kind-offscreen-lab --owner <existing-auth-user> --suite turn03`: actual **read-only** observation of pinned kind cluster, CNPG cluster, deployment/Pod config; **no mutation flag required**. It then runs scoped SQL grant status against the *verified* actual lab database using an ephemeral localhost-forwarded connection. If no grant exists, say `missing-active-grant`, not `wrong-cluster`; if observation actually fails, emit the specific refusal. No kubecontext changes.
- `ensure --target kind-offscreen-lab --owner <id> --suite turn03 --approval testlab:suite:turn03 --operator <human> --operator-grant-authorized --expect-cluster-uid <uid> --expect-db-uid <uid>`: uses **the same** observation, verifies independently supplied expected UIDs, verifies both actual GA and executor scripted-offline mode and NO provider credentials or provider pins (including secret/envFrom references), verifies exact DB identity, then invokes existing `ensureTestlabGrant` transactional/idempotent store; no new grant schema, no bypass. `--operator-grant-authorized` is an explicit human authorization marker, **not** a substitute for the human authorizing a live DB write in chat.
- Operator credentials: read `lab-postgres/lab-pg-app` Secret's `uri` in the adapter process **after** cluster/DB/workload preflight, never emit it. Start a short-lived `kubectl --context kind-offscreen-lab -n lab-postgres port-forward service/lab-pg-rw :5432 --address 127.0.0.1` child (ephemeral port); use `pg` through `packages/db` dependency resolution, rewriting only hostname/port in memory, retaining secret's DB/user/auth/ssl requirements; DB name must equal pinned `lab`. No credentials in argv, environment dumps, stack traces or receipts; always kill port forward/close pool in finally. No `kubectl exec`, rollout, Secret update, broad port binding or cluster reset.
- Connected DB identity: confirm CNPG Cluster `lab-postgres/lab-pg` UID and `lab-pg-rw` Service selects its ready current primary; refuse endpoint ambiguity/mismatch. Read-only `SELECT current_database(), current_user` on the target session; verify database `lab` and expected user `lab` before all read or write queries. **Do not accept arbitrary `DATABASE_URL` as an override.**
- Workload identity: inspect deployments `lab-authority/game-authority` and `lab-workers/game-executor` and live corresponding Pods (running, Ready; owning deployment and image aligned with observed template), not only checked-in YAML. Require explicit `OFFSCREEN_WRITER_EXECUTION_MODE=scripted-offline-lab`; reject `provider-authorized`, `OPENROUTER_API_KEY`, provider pins and ambiguous `envFrom` / corresponding `secretKeyRef` paths. No secret values ever emitted.
- Guard separation: change `verifyTestlabTarget(observation, { intent: 'read'|'write' })` (or equivalent default-safe API); read checks identity/provider-free/runtime with **no** `operatorGrantAuthorized`; write requires flag and caller-supplied expected UIDs. Preserve all other TESTLAB01 checks and existing disposable tests, adapting harness appropriately.
- Idempotent and auditable: `ensure` calls existing three-row single-transaction grant store with advisory lock and 24h expiry; no recharge/replacement on expired/exhausted/incompatible grants. Operator receipt redacts credentials and contains resolved target identities, grant IDs and `created|reused|blocked`.
- Fail closed: race/redeployment/UID change between preflight and mutation -> refuse; after port-forward readiness, immediately before ensure transaction reobserve cluster/DB/workloads and compare pinned identity and image digests, and **do not** silently retry on target change. Denied by default when no authorization or cannot establish identity. Read-only status may inspect cluster but never starts a mutable SQL transaction.
