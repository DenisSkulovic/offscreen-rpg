## Algorithm

Call readMigrationFiles({migrationsFolder}) from drizzle-orm/migrator; assert loaded count and each folderMillis match validated entry, hash lower hex 64, SQL array. Files are immutable during runner invocation (release asset/owned fixture); no arbitrary source mutations. Use exact loaded array for DDL. Do not parse or modify migration SQL; no automatic nontransactional DDL path.

src/migrations/journal.ts also validates applied prefix: read all rows ordered by id ASC, compare row i to loaded migration i. id positive integer strictly increasing, gaps allowed (rolled-back serial sequence); created_at accepts decimal string (pg bigint default) or safe integer, positive and exact folderMillis; hash exact equality, strict increasing timestamps guaranteed by matching ordered prefix. Applied list may be empty, cannot exceed journal length, no skipped/reordered/duplicate/unknown/tampered entry; invalid null/malformed values fail. Error class/message stable category plus index only, no raw SQL/credentials/hash dumps. Do not repair ledger. Current actual journal has 25 entries, strictly increasing and valid tags; latest generator snapshot drift is irrelevant to historical migration execution.

src/migrate.ts: validate/read file list before DB connect; use dedicated Client and existing connect/statement/idle tx config (strip optional managed property if supplied after DB06 joins, no DB06 dependency now). Acquire same session advisory lock via pg_try_advisory_lock; refuse competing runner immediately, preserve existing error wording. Set session lock timeout via parameterized SELECT set_config('lock_timeout',$1,false) with value min(2000,config.statement_timeout) ms; retain configured statement timeout (default10000, explicit dev migration60000) rather than globally changing it. No retry or client-side race falsely claiming cancellation.
