# AI02 | immutable request and tool-record ordering, no invented historical replay

**Gated design, not yet a Cursor execution authorization.** Authoritative details of GA private prepare and SQL transaction after WR10/WR11 must be rechecked by ChatGPT before this is Ready. Retention/deletion authorization must be confirmed.

**Tables:** Add nullable SHA256-ish `requestObjectHash` (model-step only) and `toolRequestObjectHash` (tool-call-step only) to existing `storyteller_writer_step`, with a single ordered migration. Old rows retain NULL. **No** replacement of `requestCasHash`: it continues to be the provider-wire SHA for model steps and tool input digest for tool steps. No new state machine, timestamp semantics, lock order or provider cost path.

**Private immutable object codecs:**
`writer-provider-request.v1` with `missionId,contextId,ordinal,requestSha256,serializedWire,serializedBytes,compilerVersion,captureSha256,priorToolReceiptHashes[]`. Validate serialized bytes, SHA256 equality to requestSha and pinned model budget/request. Wire version/shape must follow actual integrated `PreparedProviderWire`. Reject unsupported size; do not truncate to create a plausible exact record.
`writer-tool-request.v1` with `missionId,contextId,ordinal,toolCallId,name,args,requestSha256`. Validate request digest using existing `toolRequestCasHash(name,args)`; store private and link before executing side effects. Missing input records in old rows remain `unavailable`, not reconstructed by guessing.

**Prepare path:** derive the exact source message JSON + output schema from immutable capture/prior tool rows → prepare exact provider wire → put private request object to DocumentStore → verify read/hash → SQL CAS attach `requestObjectHash` to the same pinned `requestCasHash` and step identity/version **before** WR10 returns a `ready` send envelope. Already-attached same object is idempotent; conflicting object when same step identity/hash refuses. CAS write failed but SQL never linked ⇒ orphaned private object harmless and eligible for existing garbage collection; no provider has been sent. Must not invoke CAS while holding SQL advisory lock. Capture/source and requestObjectHash are not mutable after dispatch. Request recording must not extend provider transaction failure into double spend.

**Tool path:** after an original provider decision parsed, use existing per-call requestSha+toolCallId dedup fence; store private request object and link to that call's durable ledger **before side-effect**. If a pre-existing tool row is complete but tool request object absent (old format), its output is shown as historical partial, not a newly generated input. In a concurrency conflict, compare prior hash and return original receipt, never repeat Workdesk mutation. Tool read/browse-only calls still get input record and original output CAS when available.

**Transcript reader:** accepts an authorized mission identity and uses persisted SQL step/attempt rows, private CAS request/response and tool request/result objects. Returns `agent-execution-trace.v1` with ordered `model-request`, `model-response`, `tool-call`, `tool-result`, `hold`, `proposal`, `publication` entries, timestamps/status where recorded, hash/identity citations, capture and root pins, and `evidence:'exact-archived'|'hash-match-recompiled'|'current-compiler-only'|'unavailable'|'redacted'`. Reader has **no model transport or mutation capability**. Raw provider reasoning is not synthesized; provider metadata may show reasoning-token *counts* where recorded, not hidden rationale. Separate logical agent rounds from Temporal's activity history.

**Recompile:** only if the exact compiler/prompt version is retained and all pinned sources/prior tool receipt objects are accessible; compute canonical prepared wire SHA and compare to stored SQL hash. New compiler output may be shown as `current-compiler-only` with original hash beside it, never labeled exact. No Library live-head reads; use pinned root and object hashes, verify no future-fork leak.

**Access/retention:** transcripts are `storyteller-private`; only scoped authorized inspection service or local disposable-owner tooling may read. A public story player DTO never includes prompt, tool payload, provider body or debugging metadata. One explicit account/campaign deletion path must handle new request objects and linked records, with user-data retention bounds and audit. If that cannot be source verified, do not implement storage code.

**Negative proof:** lost CAS/SQL link, dangling pointer, duplicate tool call, same ID changed args, response body tamper, capture mismatch, post-delete missing objects, unknown-possibly-sent attempt, unauthorized user reading another mission. Zero extra provider send in all cases. SQL read-only forensic renderer separate from live Writer dispatcher.
