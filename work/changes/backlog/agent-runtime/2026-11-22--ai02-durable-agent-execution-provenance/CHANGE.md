# AI02 | Exact request archive and inspectable Writer execution transcript

**Status: PLANNER-GATED after AI01 + WR10/WR11 integration; privacy, archival and actual split-custody interfaces must be source-reconciled.** Baseline: `undertaking/storyteller-workshop` at `f8a45a7e0a0daa408f05651eb1bb2997ec2daf22`. Stateful feature requiring exact SQL/CAS design, **not** a mechanical refactor. No paid provider call and no assumption that all old prompts are recoverable.

## Evidence already present and absent

Present: `generation.input.writerMissionCapture` pins mission/root/scene and capture version, `storyteller_writer_step.request_cas_hash` is the **SHA of the prepared provider wire** (not an object pointer); `response_object_hash` points to immutable private `writer-provider-response.v1` when WR09A strict delivery succeeded; recorded tool steps include `toolCallId`, request digest and private result/summary pointer; SQL task states and Temporal history identify orchestration. `writer-round-request.ts:compileWriterRoundCapturedRequest` has a fixed short system message and JSON pins/prior summaries. The source does **not** establish immutable storage of the exact outgoing wire and all tool arguments for every historic Writer step. Openings have a separate `openingArtifactSchema` with captured request; do not claim it's the same format as Writer v3.

**Chosen functional outcome:** every **newly admitted** Writer round has a private, immutable, byte-exact request object linked to its SQL model step BEFORE possible network dispatch; every executed tool has a private request record (name, args, call ID and order) attached to its existing durable tool receipt, and the existing private result pointer remains. Strict provider response body and usage already have their authority; **do not duplicate provider charge**. A reader can assemble a chronological **logical agent transcript**: frozen messages and output schema, tool decisions/calls, recorded tool outputs, further requests, final response, billing/attempt states, hold/retry markers and publication IDs when present. The original raw provider decision bytes are preserved if present; provider/internal reasoning is marked `not-provided` unless it actually arrived and policy authorizes storing it. Never claim to reconstruct private chain-of-thought.

## Exact vs reconstructed distinction

- **EXACT-ARCHIVED**: immutable stored HTTP request wire bytes, matching recorded wire SHA and current/committed response pointers; no provider or database rerun required to view them.
- **HASH-MATCH-RECOMPILED**: historical capture and prior receipts reassembled using a pinned available compiler version and its computed request hash equals old SQL `request_cas_hash`; this proves byte-hash equality for the available wire, but not that every omitted old source was retained.
- **CURRENT-COMPILER-ONLY**: old data lacks an immutable wire/object and current compiler gives an output; it is a hypothesis/debug preview, **not** historical request evidence.
- **UNAVAILABLE/CORRUPT/REDACTED**: missing pin, compiler version, CAS record, forbidden access or hash mismatch. Never fabricate messages or silently substitute current library text.

**Storage decision:** introduce an additive `request_object_hash` column (nullable SHA256) on `storyteller_writer_step` for model rows, and additive `tool_request_object_hash` (nullable SHA256) on tool-call rows, preserving existing `request_cas_hash` SHA meaning and `response_object_hash`. Private CAS schemas `writer-provider-request.v1` and `writer-tool-request.v1` hold identity, full *exact* serialized request, compiler/prompt version, digest, plus tool ID/name/args/digest. Use the existing `storyteller-private` DocumentStore boundary, content limits and canonical hashing, not publicly visible Library nodes. No separate event-sourcing database and no duplicate Writer transaction owner.

**Ordering:** (1) generate frozen wire/payload from pinned capture+recorded prior results; (2) store canonical private CAS object, validate bytes/hash; (3) SQL compare-and-set step revision/request SHA and new requestObjectHash **before** possibly-dispatched reservation; failure refuses dispatch and may leave an unreferenced immutable object, never money spent without pin; (4) existing WR10 GA reservation uses linked request SHA/Object, executor sees only necessary wire via authenticated private route; (5) before executing a tool action, persist its exact invocation CAS and link the tool ledger row to that digest, preserving current idempotent write/Workdesk contract and avoiding a second execution on retries. A tool result stored by old code without input args remains an explicitly incomplete historic trace. SQL settlement+responseObjectHash stays WR09A's existing atomic transaction. **Do not put raw requests or results in Temporal history or OTel spans**.

**Retention / privacy hard gate before implementation:** existing account/campaign deletion and private-object retention semantics must be source-audited and extended for these two new object types, including authorization, staff access, backup/export and purge. An immutable record is *append-only until the owner-authorized deletion/retention rule*, not an exemption from deletion. No global unauthenticated debug endpoint or stored credentials. If current deletion cannot enumerate these linked objects safely, **STOP and plan the missing path with ChatGPT**.

**Ownership after AI01:** `packages/story-engine/src/storyteller/writer-rounds/request-and-step.ts` (or post-refactor actual equivalent), tool ledger owner, `writer-round-replay.ts` narrow observation only; `packages/story-engine/src/storyteller/writer-request-provenance.ts` new CAS codec/reader; `packages/db/src/schema/storyteller/.../writer.ts` ADDITIVE nullable columns + one new ordered SQL migration/journal; `packages/storyteller/src/tasks/writer-round-request.ts` only for explicit stable compiler ID (must not change v1 bytes); `tools/api-integration/test/ai02-agent-provenance.integration.ts`. No apps/api/admin/Web/Temporal/workflow edits; GA private prepared-route integration must be source-rebased against WR10, not guessed. Shared lockfile/catalog owned by custodian.

**Acceptance:** exact wire request stored before provider prepare can emit a one-use envelope, one tool request/one result per tool ID, chronological transcript object with verified hashes, restart recovers without dispatch, fork-root source isolation, same input + same pinned compiler produces equal bytes (where historical pins are available), old records never falsely labeled exact. Negative corrupt CAS, mismatched request byte/hash, wrong owner/source, orphan object, duplicate attempt, tool args changed under same ID, forbidden staff access, incomplete deletion inventory. No paid calls.
