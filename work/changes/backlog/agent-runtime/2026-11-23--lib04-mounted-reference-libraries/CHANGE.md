## Selected model
1. **Document** is a typed, immutable content object. **Library** is an independently governed collection at a specific root. **Shelf** is a named, task-visible **read-only mounted view** of one pinned Library root. **Story Library** is the sole writable canonical collection for a story and retains Game Authority publication; its head pointer can change, historical roots cannot.
2. Initially support exactly the already-provisioned source kinds: one story-root view, 0–8 named world source references, zero/one pinned rule source. The start package already models `worlds[]` and `rules`, and instantiation stores campaign-owned `world/references.json`, `rules/reference.json`. These provide **source identity/provenance**, not authority to read by themselves. A future catalog, player-attached external Libraries, licensed craft books, other users' stories and mutable shared library heads are separate work.
3. Attach/mount set is resolved by **trusted application/authority code** from the story's pinned, verified source references, not from model-provided parameters; never accept an arbitrary `rootHash`, S3 URI or tenant library ID supplied in a tool request. A captured task pins the library identity, kind, root hash/revision, alias and exact grant scope. Alias may rename only; cannot alter source identity or grant.
4. Mission-time reads use fresh actor/story/tenant permission checks and document-level visibility; stale/revoked access fails closed even if the pinned root persists. Historical replay stores original source identity for audit but cannot bypass a later revocation. Source lore is **evidence**, not campaign canon, and does not override the Story Library. No automatic mutation, no inline import into story.
5. Reusable reference source manifests are currently `offscreen.world-package-manifest.v1` and `offscreen.rule-package-manifest.v1`, **not** `offscreen.library-root.v2`. Navigation must adapt these existing manifest shapes; do not silently rewrite manifests or assume every source can be traversed with the v2 trie. The Story Library retains existing v1/v2 compatibility.
6. Writer tools are mission-specific adapters. Domain navigation stays provider-neutral. Add separately versioned mission/tool/citation contracts when implemented; do **not** make legacy `writer-mission.v1/v2/v3` read foreign roots, nor weaken `assertNoCapabilityElevation`.

## Stages, not one blind implementation
**LIB04-A (first possible implementation):** read-only, provider-neutral `PinnedShelfSet` navigation over existing verified story/world/rule reference roots, tested with injected readers and authorization. No model runtime, persisted schema, DB mutation or CLI. **LIB04-B (later):** integrate into Writer mission capture, tools and evidence with a new explicit schema version and backward-compatible reads. This requires source-exact capture/round/SQL/Temporal ownership map before readiness; no commission until that map is complete. **LIB04-C (future separate Change):** self-service curated library catalog, attachment/removal UI, grants and optional indexing/caches. Not included here.

## Explicit boundaries
- Documents: immutable object and source-manifest codecs; may expose generic per-manifest bounded traversal helpers.
- Library read capability: resolves mounted source-root membership and validates read budgets. Initially put implementation under Story Engine's storyteller read-only navigation area; reassess a `@offscreen/library` workspace only when more than Storyteller needs an independent stable API.
- Story Engine host: resolve mounts against story/start source references, produce authoritative pinned grants, transactionally bind mission capture to these refs.
- Storyteller: tool schema, allowed capabilities, bounded tool results, evidence and attribution.
- Game Authority: story ownership, access policy, authority for which pinned references are admitted; selected Story Library head and publication.
- Caching: no Redis dependency in any domain implementation; optional local content-addressed cache outside authorization, keyed by immutable hash and object kind, bounded in bytes. Never cache an authorized response independent of actor/grant; do not allow reference caching to evict control/session operational data.

## Non-negotiable acceptance
Two independent pinned references + story canon under one authorized capture; same path names remain namespaced and do not silently shadow; visible doc reads cite exact source root/object/version/section; private entry titles and search counts do not leak; wrong tenant, forged hash, revoked access, stale/grant-mismatched cursor, >128 entry pagination and output byte budgets fail correctly. Existing legacy Writer captures and story/fork state remain unchanged in A. See SOURCE-MAP, EXECUTION, PROOF. **This packet is not yet Composer-ready.**
