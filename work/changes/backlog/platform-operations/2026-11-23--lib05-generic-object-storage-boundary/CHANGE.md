# LIB05 | Reusable object-storage transport under Documents and future Media

**State:** PLANNED / IMPLEMENTATION GATED UNTIL LIB03 INTEGRATES. **Planning baseline:** `undertaking/storyteller-workshop@abdce8d7457305baacd13971f116f343562999ff` (LIB01/LIB02 integrated). **Target:** same Undertaking. **Predecessor:** LIB03 solely to avoid concurrent `packages/documents` barrel/tests/manifests modifications. LIB04-A source navigation can remain independent. **No live bucket/install/test allowed by this planning packet.**

## Chosen architecture
Create a narrow infrastructure workspace `@offscreen/object-storage` for **physical object byte I/O**, independent of Documents, Story Engine and Media. Introduce `ObjectStorage` contract with `putIfAbsent(key, bytes, contentType)`, `get(key,maxBytes)`, `exists(key)`; provide local filesystem and S3-compatible implementations. Lower-level storage keys are opaque **bounded relative object keys** validated once (ASCII slash-separated segments, no leading slash, backslash, '.', '..', empty parts or control chars); content type is explicit. `get` MUST enforce maxBytes while reading, not only after materializing an unbounded response. Use one configured per-request maximum; initial implementation supports bounded byte arrays, not promises of zero-copy streaming. Global upper hard limit 32 MiB; Documents passes its existing 1 MiB ceiling. No public-delete API, no presigned URL, no public bucket, no LIST as authority, no tenant permission grant and no provider request.

Keep `@offscreen/documents` as the **typed canonical object codec**: `canonicalJson`, SHA256, schemas, legacy JSON key naming `objects/sha256/<ab>/<hash>.json`, existing `DocumentStore` typed methods and `DocumentStorageError` codes. Refactor `LocalDocumentStore` and `S3DocumentStore` to **compose** the lower-level raw transport, not inherit its semantics blindly. Backward-compatible constructors, `S3DocumentStoreConfig`, `createDocumentStoreFromEnv`, bucket setup and public exports remain available. Bytes and hashes for identical fixtures must remain exactly identical. Documents still performs both read-back equality after put-if-absent and hash/schema verification on each read. Object Storage never parses JSON, writes Markdown, interprets `visibility`, or chooses Story Library heads.

**S3 semantics:** Preserve current `PutObjectCommand` with `IfNoneMatch:'*'`, guarded `HeadObjectCommand`, `GetObjectCommand`, opt-in `HeadBucket`/`CreateBucket` via explicit lab/bootstrap-only helper, custom endpoint/path-style and credentials. Concurrent same-key put must not overwrite. For existing-key conflict, Documents compares exact stored bytes before accepting same hash. Translate not-found/412/owned-bucket/unknown into explicit storage errors while preserving Documents' existing public error mapping. Never silently downgrade remote errors to local writes. **Local semantics:** preserve exclusive staged file, fsync and hard-link promotion, dedup, and read-after-write verification; no overwrite, no deletion of existing objects. Key validation must reject traversal before disk access.

**Transport vs publication:** raw object persistence is never story publication. Game Authority/SQL remains authoritative for committed document and future media attachment roots. A media pipeline later gets its own MIME/dimensions/provenance/variants, separate provider spend and policy; don't invent `@offscreen/media` implementation here.

## Scope and stop
T01 raw transport package and no-business-logic tests. T02 DocumentStore composition with byte-for-byte fixture equivalence; T03 consumers/build/config and regression. See SOURCE-MAP/TASKS/PROOF. Do not change object naming, stored JSON, DocumentStore method signatures, S3 bucket config env contract, hashes, release manifests, secret handling or persistence SQL. **Stop** if moving local exclusive-write behavior changes durability, if stream limits cannot be enforced, or if the direct S3 adapter must reveal credentials to domain consumers. No new Kubernetes Pod. No Redis cache in this Change.
