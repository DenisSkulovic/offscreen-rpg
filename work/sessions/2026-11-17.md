### Player-experience refoundation: owner intent and research boundaries

**Owner direction.** Treat Offscreen RPG's frontend as a pre-POC, deeply vibecoded artifact and substantially redesign it if necessary. The existing code is not the design authority. Previous UX/PX work is not accepted as a polished aesthetic or a coherent game experience; the owner explicitly rejected generic, outdated-looking, AI-generated UI patterns.

The owner wants a deliberate product-design process before engineering: experience principles, player journeys, page and space architecture, serious visual direction, reusable component patterns, motion/atmosphere, and potentially a composed design system. The game should be visually compelling and sometimes expressive, but not flashy merely for decoration. Preserve and investigate the **idea** of Storyteller-controlled scene presentation while reevaluating its first implementation. The evolving campaign should feel like a self-writing book/story; durable previous scenes and their reading/navigation experience deserve first-class attention, possibly with compact moment summaries and deeper passage reading. Research possible missing player-facing spaces and dashboard concepts rather than treating current routes as requirements.

**Proposed creative hypothesis (not accepted):** living stage during play, living edition when remembering; a stable platform identity plus controlled, world-aware scene variation. Do not turn this into mandatory medieval parchment or a single science-fiction HUD. Compare meaningfully different design compositions using identical narrative content.

**Observed source-bound facts.** Phase 0 inspected the lean ZIP at `9e821c6e15bb90444ec711a1b82b1e18cff9539a`. It found already-existing product and technical experience rules, per-feature stylesheet token namespaces, Storybook fixtures, persisted/paginated story passages, and partial live presentation consumption without an identified normal production authoring path. The inspection was **not** a live browser-based visual assessment, usability study or runtime/gameplay test. See [source audit](../designs/open/player-experience-refoundation/AUDIT.md).

**Owner direction on design pipeline.** The owner asked to plant the Phase 0 design documentation in GitHub and ensure exploratory feature design has a real home separate from late implementation `work/changes/`. The repository already has `work/designs/open/`; use it instead of adding a parallel documentation tree. Accepting the **location and research process** does not ratify any art direction, page concept or product contract.

### Phase 1 expansion: experience architecture, no code

Following the owner's “continue” instruction, drafted a seven-document [Phase 1 design dossier](../designs/open/player-experience-refoundation/phase-1/README.md) under the existing open-design workspace. It defines the “continuing life” mental model; Stories/Now/Journal/context architecture; newcomer, ordinary life/return and six-month history journeys; truthful Now state/choice grammar; a source-faithful multi-depth Journal reading model; fixed design narrative specimens for later visual alternatives; and candidate decisions plus validation gates.

**Strongest proposal, not ratified:** Now and Journal are two complementary primary modes; Journal should become a reader with overview and exact source passages, with derived “moments” explicitly separate from passage/scene/event truth. Return is a nonblocking, source-scoped prelude in Now. Storyteller appearance remains bounded by the selected presentation contract.

**Evidence limitations:** Current `storyHistorySchema` exposes id, sequence, title and paragraphs with 20/page `nextBefore`, not random seek/search, historical choice, persistent bookmark, relationship index or historical appearance. Existing GM05/GM06 evidence channels are separate; proposed Player Replay remains separate and unaccepted. No screens were rendered, usability tested or approved by the owner. Fixed narrative specimens are illustrative text, not actual committed story records.

**Next:** owner review of Phase 1 recommendation and unresolved alternatives; then genuinely different Phase 2 art-direction prototypes using the identical textual corpus. No Changes, implementation work, libraries, API or canonical product/technical contracts were authorized by this design draft.
