# R3 | Installation admission and proof contract
2026-11-26. Baseline dee12a65beb90493728ef935e3d4d473cd264fe2. R3 supersedes inconsistent R1/R2 directions. Status proposed; no source implementation or live mutation.
 
## Scope reduction and alternative
Fresh optional local dev/release only, no automatic occupied legacy admission, no automatic interrupted-install repair, no upgrades. This is appropriate absent application demand. Ordinary Kubernetes reconciliation remains native; failed provisioning is reported, no cleanup or repair implied. Existing data is preserved. A separately authorized recovery experiment may examine owned partial state; no generic journal/controller or destructive retry. Reject automatic server-side apply: it can modify existing resources. kubectl create uses create semantics, AlreadyExists is a refusal; multiple requests are not a transaction. https://kubernetes.io/docs/reference/kubectl/generated/kubectl_create/ and https://kubernetes.io/docs/reference/using-api/server-side-apply/ (retrieved 2026-11-26).
 
## Admission
Use root dependency yaml@2.8.2 already present in package.json to parse pinned bundles (parseAllDocuments, reject parser errors, duplicate identity, unknown kinds, ambiguous namespace, non-object). No new general manifest framework. Inventory key is group/kind/namespace/name with explicit scope from discovery; cluster scoped namespace null. Cert-manager and RabbitMQ operator bundles are separate staged units. Read each manifest identity, plus generated resources and namespace census; discovery absent only when CRD/API absence independently established; forbidden/timeout malformed = unreadable. Cluster-wide RabbitmqCluster list (when API established), legacy messaging namespace occupancy, expected broker namespace, retained PV claimRef matching old/new namespaces, and matching PVC/Secret are checked before writes. Existing namespace not owned by this target refuses; no foreign resource adoption. No alternate broker to sidestep legacy data.
 
Matching dependencies: complete bundle inventory, no terminating resources, exact pinned image specs and actual ready workload image identity, current deployment generation and availability, established CRDs, webhook endpoint and CA readiness. Compare desired intent to observed using per-kind projections with strict equality on security-relevant fields; no generic recursive desired-subset matching. For RBAC compare full rules/subjects/roleRef (order-insensitive only where semantically set-like), for deployments full normalized pod template and selector, for CRDs full normalized spec, for webhook configurations full normalized webhook spec except injected CA bytes (must nonempty and usable), certificates/issuer full spec, services normalized spec excluding server assigned fields, namespace/SA intended metadata and relevant safety fields. API server defaults and admission changes must be explicitly enumerated and checked against actual specimens before freeze. Do not use dry-run apply as sole comparator (unowned extras can survive); do not trust annotations alone. Shared cert-manager matching may be reused without writes; otherwise refuse, never upgrade/delete. Exact projection fixtures are evidence-gated until actual API specimens. Fresh path only when dependencies each absent or matching ready and broker/legacy absent. Complete matching broker path read-only. Partial, unknown, drifted, missing data/secret or incompatible dependency refuse. No automatic fix. Take cooperative context-specific lock (one acquisition, deadline 30s), reassert context/cluster identity before stages; shared cert-manager creation serialized across platform operations or explicitly prohibited concurrent operators. External actors not covered by lock; create-only requests fail on collisions; report partial if any writes may have occurred, never falsely mutated=false. No retry on ambiguous API write timeout.
 
Stages: validate local target, host capacity and all source hashes/immutable images; full inventory; cert-manager create absent bundle then CRDs/deployments/webhook ready; operator create absent bundle then CRD/issuer/cert/webhook/deployment ready; broker namespace create then server-dry-run create of RabbitmqCluster (webhook validation) then actual create; wait structural health. Recheck next-stage absence after prerequisite readiness. If any failure stop with bounded redacted phase receipt and retain state. Per-call deadline 10s except stage waits bounded 240s, broker 420s; overarching 900s matches provisioning subprocess timeout (stage deadlines clipped by remaining budget). No unbounded sleeps. Existing platform memory and volume/context safeguards remain. No live write authorization in design.
 
## Credential and protocol health
Official operator documentation explicitly warns that deleting a Secret causes regeneration without installing new values in the persistent broker: https://www.rabbitmq.com/kubernetes/operator/operator-overview ; https://www.rabbitmq.com/kubernetes/operator/using-operator . Thus even a present generated Secret is not proof of valid credentials. Structural status checks CR generation, conditions, current StatefulSet, Pod, PVC, Service, endpoints and expected status credential reference/key presence; no credential values in logs. Report protocol NOT CHECKED unless actually probed. Do not claim structural readiness means authentication works. Separate ordinary smoke confirms auth and broker data path, no pod restart. Existing matching ensure is structural only, not automatic auth repair. Future app credential/rotation protocol separate.
 
## Verification choice
Use Pika 1.4.4 candidate pinned wheel in a verification-only image (no runtime pip install; hash/base image digest required before commission). https://pika.readthedocs.io/en/stable/examples/blocking_publish_mandatory.html ; https://www.rabbitmq.com/docs/confirms : confirms alone do not establish routing; mandatory plus confirm handles return/nack. Use generated random run ID with Kubernetes create-only fixture Pod/ConfigMap and AMQP server-generated queue names (empty name on declare, durable classic, nonexclusive, non-auto-delete for persistence). Server generated name avoids accidental preexisting queue declaration; capture name as run receipt, delete only that name, never prefix sweep. Use existing default vhost solely on dedicated disposable broker for heavy proof; routine smoke on shared broker should use exclusive auto-delete server-generated queue and no persistent topology. Admin Secret mounted by reference in same namespace, not copied to host, no service account token, no credentials/exception payloads printed. Test wrong password via authenticated protocol denial, reachable positive connection before/after; generic reset not sufficient alone. Pika blocked_connection_timeout plus outer deadline and bounded cleanup. Heavy proof: publish unique persistent payload with mandatory+confirm; repeat ensure while queue exists; preserve queue/payload and resource identities; restart only on explicitly dedicated disposable broker; verify exact payload after new Pod UID, same PVC/Secret UID; hold manual-ack delivery and terminate owned client, observe redelivery then ack and verify empty; cleanup exact owned fixture IDs. Management API auth and metrics response verified separately. No actual pin resolution or live run yet.
