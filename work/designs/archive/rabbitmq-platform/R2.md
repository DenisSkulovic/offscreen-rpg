## 1. Representation: retain tiny render-only Helm chart
The common render.mjs exposes rabbitmq all/namespace/broker sections, validates resource kinds/namespaces and consumes one JSON object per rendered document. common/cli.mjs exposes legacy/json/yaml output. platform-plan.mjs lints/renders selected chart services. Keep the chart as a renderer (not a Helm release or lifecycle controller), remove externalSecret, definitions volume, queue overrides and custom credential generation; add development.yaml, profile storage and namespace, schema and tests. Common profile.mjs becomes canonical namespace/context/storage mapping; render allowlist derives from it; profile values must agree. Reuse common render and target safety. New install interface install.sh [dev|release] defaults release for old calls, plan is read-only through existing platform-plan contract. Core excludes rabbitmq; explicit all includes it. No app/slot integration. Do not change unrelated catalog behavior. Source proof should cover renderer output formats, chart sections and wrong profile/namespace.

## 3. Admission model and failure ownership
Fresh broker requires dedicated target namespace absent, all expected broker identities absent, and absence of legacy messaging/lab-broker artifacts including retained PVC/Secret, as well as absence of any other RabbitmqCluster in selected cluster (singleton policy). Namespace presence alone is not permission; foreign shared resources refuse. Dependency states independently ABSENT (all identities absent with discovery proven), MATCHING_READY (all present, normalized selected spec and current health matches), or REFUSE (any other observation). Cluster CRD absence is established by reading CRD and API discovery; cannot treat discovery/RBAC errors as absent. Existing matching broker may only return success when both dependencies match and ready; never repair dependencies in an occupied broker install path. Exact semantic projections and dynamic generated resource census still need freeze; no broad label-only trust. Compare declarative desired fields including RBAC, webhook config, selectors and image pins, ignore only enumerated defaulted/controller-owned fields (CA injection, status, metadata etc), not arbitrary extra privilege or settings. Distinguish intended cert-manager shared reuse from taking ownership: no apply to matching shared install; no deletion of either controller.
 
All admission completes before write under cooperative host lock; lock does not exclude other cluster actors. Native create rather than apply for fresh objects; AlreadyExists abort, no overwrite. Do not claim atomic cluster transaction; after interrupted multi-document create report partial and preserve resources. Fresh path may include already matching prerequisites. After each stage wait bounded, recheck next stage absent and target identity before writes. Never recreate a missing credential with PVC present. Recovery of partial admission remains a separately authorized diagnostic/repair operation, not universal automatic replay. Need choose explicit safe operator recovery protocol before final defense. No hidden destructive rollback.
 
## 4. Verification refinements
Existing amqp_smoke.py already enables confirms but uses hardcoded lab.durable and handcrafted AMQP protocol. Guest denial currently accepts reset/EOF regardless of handshake stage; this is weaker than proof of authorization. Prefer a pinned mainstream AMQP client in a reproducible fixture image, no pip download during smoke, if existing toolchain can provide it. Otherwise retain minimal stdlib fixture only with strict stage checks, mandatory routing, bounded frame parsing, confirm/nack handling, run-scoped queue and exact payloads; decide after pin feasibility. Negative check must establish valid same-service connection before/after and distinguish explicit ACCESS_REFUSED from transport loss (guest reset after auth stage can be supplementary, not sole authorization proof). Avoid deleting fixed names. Prefer run-owned vhost via create-only admin API (unique name, refuse collision) and run-owned restricted credentials where feasible; not permanent topology. Ordinary smoke no broker restart. Disruptive restart only on dedicated disposable broker, never an occupied shared service. Management endpoint authenticated; broker Prometheus endpoint reachable on cluster-local service; no operator metrics TLS claim. Source-only tests and owner-operated heavy matrix remain separate.
