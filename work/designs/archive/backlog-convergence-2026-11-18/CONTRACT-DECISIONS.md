# Contract decisions | unblocking without bypasses

These are **approved bounded implementation choices for the November 18 convergence**, not claims that the code already does this. When implementing, reconcile the actual product and technical owner pages before claiming product behavior. Do not silently promote experimental mechanics into general canon.

## DIR02 and DIR03

- **DIR02 selected path:** extend the existing `insertContinuationPassage` input by an **optional validated presentation value** and write `storyPassage.appearance` in the *same* publication INSERT, inside the source publication transaction. The presentation is non-authoritative decoration; it may be omitted/null. No new SQL column and no after-the-fact `UPDATE story_passage` of the newest row.
- Use the existing `ScenePresentationV1` / `projectStoredSceneAppearance` shape and exact committed story/passage/offer identity. Avoid a second, silently divergent validator. If schema ownership makes it circular, put the pure check in a lower-level shared contract and preserve versioned refusal/fallback. The **fixture must be deterministic and internal**, never submitted as a browser-supplied authoritative value. Do not invent freeform URLs, CSS or HTML.
- Guard that only the accepted, non-stale, exact-generation source writes the style. Duplicate publication returns original passage, not a second style. Malformed directive is dropped as optional before insert **without cancelling the actual narration**. Historic passages are not re-rendered by a read-only current appearance bridge.
- **DIR03 first mergeable outcome:** support an optional typed `appearanceSuggestion` field in provider-free result/adapter fixtures *only when schema-safe* and demonstrate null/invalid/pass-through behavior through DIR02. No separate paid director, no automatic charge, no unapproved live trial. Write an exact quality/cost acceptance sheet for a future explicitly authorized live experiment, but **do not let its absence prevent merging the deterministic optional protocol**.

## HK01 and OBS00: custody is a capability

- **HK01:** extraction before deletion. Define a reusable `inspectUncertainResponse` pure validator taking captured task, attempt identity and already-saved bytes, returning typed refusal or proposed settlement. Saved evidence must be hash- or provenance-bound to the correct exact attempt and review state. Never “settle” success from partial/unknown provider evidence. A safe `--dry-run` reports no mutation; any `--apply` path remains local/disposable and requires explicit human acknowledgement of irreversible accounting. Preserve current `budget.settle` idempotency and fail-closed unknowns; add fixture assertions of already settled, mismatched IDs/model, malformed cost/usage, absent captured repair capacity and duplicate apply. Only **after** a supported replacement is tested and documented should the old CLI be removed.
- **OBS00-B:** do not derive current entitlement from captured `story.usagePolicy` or worker environment flags. Establish an independent **server-owned, versioned** current policy source with platform ceiling, owner-linked entitlement/grant, active restrictions/suspension, approved provider route and funding mode. Missing grant, revoked owner, expired/revoked run, route mismatch, policy version disagreement or DB read failure **deny before transport**. Read the task's original owner/story/generation identity from DB and compare to captured task before resolving. Reuse `resolveEffectiveUsagePolicy` as pure intersection. The default production worker remains denied unless all independent records and request attestation match. Test mock transport full byte digest for base/repair/memory rounds. **No seed that grants paid access**, no real key and no production activation in this convergence.

## Testability and safe operations

- **QA-SF01:** the five known failing subtests after fixture recovery represent runtime defects until reproduced otherwise. Permit a minimal production code fix only when one failing assertion locates the actual owning behavior. Do not change a 55-day expectation to 0 to achieve green. Regression tests in existing same-role suite first.
- **HK03:** move coherent test groups into typed helpers or suite modules while keeping **all** failing tests, names, behavior and counted assertions. A red baseline is a characterization input, not a freeze. Avoid running multiple destructive focused suites concurrently.

## Mechanical experiments are not calendar promises

- **GM03:** test the exact preapproved quiet-watch fixture for **three 600-fictional-second segments, maximum 1800 fictional seconds**, zero repeatable money/item reward, stop at new decision/hold. First compare three explicit entries through existing accepted-plan machinery. If equivalent, ship the *existing-plan-backed* UX/projection and record **no new standing engine needed**. If it cannot represent the contract, add a strictly bounded repeated activity owner with per-iteration receipt uniqueness and identical stop checks, never a global NPC tick.

Consent after deadline is rejected. Manual response and expiry race under the same story row lock; exactly one commit wins; option invalid/stale -> held. Preserve existing nonconsented legacy behavior elsewhere; do not retroactively add opt-in to all decisions.
- **ENG03:** C1/C2 already prove narrow capture. Inventory actual outstanding purpose families, then take **one** with measured lock-held external I/O and exact source version/fence. No second Storyteller coordinator, no speculative global migration, no document reads moved off lock without captured versions.
- **OBS04:** one committed finite-action settlement/interrupt writer with E0 record inside the existing story transaction; separate internal evidence sequence from player-visible revision and public event order. Capture changed-state keys only, bounded bytes, immutable source IDs. No authoritative game reads from E0, no ghost ledger on rollback.
- **SA07:** a corpus failure is the admission ticket. Improve direct cue/alias/lexical retrieval if that fixes it. A new read-only typed op exists only if the exact authorized source was unreachable under the current affordable ask/read budget. Corpus can decide no new tool.
- **S3a:** a read-only reporting view. Display *proposed* vs *accepted/published* vs *retained canonical identity* vs *selected* vs *packed*, using original persisted provenance; output `unknown` when evidence absent, no raw private text.

## Anti-blocking rule

A safety fence is **a requirement for the implementation**, not by default a veto on writing and testing the safe code that satisfies it. Missing production secrets, purchased allowance, owner account data, or disposable DB availability can legitimately block **live acceptance**, but they do not block pure contract tests, deterministic simulations, or designing a database-backed policy owner. Conversely, never reclassify a missing entitlement or unsent paid call as Done to make a dashboard green.
