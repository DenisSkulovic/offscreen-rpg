## Candidate ownership and execution
Borrow loop, SDK message/tool parsing, schema translation, provider adapters, streaming primitives, workflow replay, timer and activity scheduling where proven. Own mission semantics, scope/grants, context/source selection, tool eligibility and enforcement, stop/budget policy, result validation, lineage and effect custody. Do not write a universal SDK facade before selecting a real consumer. SDK-specific types may remain internal to adapters; stable domain contracts must not require a provider SDK's session representation. A thin integration module in Agent Core plus Workflow-safe entrypoint and worker composition is the initial hypothesis, not a separate package by default.

Workflow code assembles deterministic orchestration from captured data and explicit Activity results. Activities resolve current authority, fetch scoped sources, call providers and execute tools. Workflow history records progress, not canonical Library or financial truth; avoid duplicating the workflow state machine in SQL. Durable provider attempt ledger remains independent of trace export. History payload confidentiality, retention, size, codecs, replay-safe logging, worker versioning, cancellation and migration of in-flight runs need explicit investigation.

Provider call path for both agents and direct inference: requirements -> eligible route -> reserve allowance -> guarded dispatch -> validate/normalize response -> settle or hold uncertainty. Proposed reusable inference-execution responsibility (package candidate ai/inference, name and split unresolved) owns dispatch coordination/custody, not commercial ledger, provider protocol, route selection or agent loop. Existing provider boundary specifies uncertain calls cannot become retry permission. Do not allow nested SDK/gateway/Temporal retries to duplicate billing or bypass route pin. Distinguish definitely unsent, delivered/known usage, known failure, ambiguous delivery; retry only when permitted by actual policy and custody. Tool effects require explicit operation identity, current resource authorization, idempotency or uncertain hold. Guardrails are not security grants.

## Discriminating experiments (not run or commissioned)
Use isolated dossier specimens and fake model/provider server, no real credentials or provider traffic. First resolve supported versions and inspect integration implementation, default retry knobs, Activity payload shape and provider adapter hook. Two comparable small specimens only: Vercel multi-step SDK + Temporal; OpenAI Agents SDK + Temporal. Same mission: read source, delegate scoped research if supported, write staged draft, submit typed proposal. Start without delegation or streaming if necessary to isolate fundamentals. Use a local disposable Temporal service only with separate approved operator commands.
1. Two model rounds, one authorized read, one denied write, typed output; no forbidden handler invoked.
2. Crash after first completed model Activity; resume and verify fake provider count unchanged for that Activity.
3. Crash/lost response after provider received request but before receipt; exactly one transport dispatch for attempt, durable uncertainty, no new calls or released funds until authorized reconciliation.
4. Tool effect committed but Activity completion lost: retry returns existing result or holds, never repeats non-idempotent effect.
5. Revoke grant between rounds; next provider/tool dispatch denied. Child cannot widen source grant or parent allowance; parallel allocations atomic.
6. Provider route switching only at permitted boundaries; verify non-OpenAI adapter preserves tool ids, schema, usage and reasoning continuations. No hidden fallback or retries. Fake two incompatible model routes.
7. Inspect actual workflow histories and telemetry: no credentials, cross-tenant data, raw traces to external destinations; evaluate authorized content retention and payload limits, not claim history contains no content.
8. Measure dependency count, adapter code and complexity qualitatively with same specimen; choose the smallest approach meeting mandatory gates. Pin versions and document failure evidence before formal defense.

Decision posture: borrow-first. Vercel and OpenAI are paired first investigation candidates, not approved dependencies. If one meets needs without duplicating orchestration, stop expanding the framework survey. A custom controller is justified only by concrete missing seams, not familiarity. No framework portability abstraction for hypothetical migration.
