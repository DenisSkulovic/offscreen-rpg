## Ranked material findings

### C01 — high — Essential public-entrypoint proof has no safe reachable target
TARGET.md Proof tiers requires actual dev and release public entrypoints fresh install/no-op; Profile and render contract fixes namespace and names. OBSERVATIONS.md identifies both existing legacy pools. Ordinary ensure must refuse them. Thus successful specimen does not make the required production-path acceptance feasible without either destructive cutover (excluded) or a separately defined isolated target mechanism. Merely adding a namespace override to ordinary ensure would weaken its identity fence. Blocked decision: structural acceptance and promotion boundary. Closure: freeze a feasible, explicitly authorized isolated proof route exercising actual production lifecycle and dispatch for both profiles, or explicitly split fresh-path source/disposable proof from exact public baseline live acceptance gated on migration; specify what each proves and does not prove. No need to repeat successful specimen just to satisfy committee.

### C02 — high — Lock custody and deadlines not established across actual invocation chain
TARGET.md selects per-context cooperating writer lock, invokes Temporal flock supervisor pattern, and says outer deadline allows receipt. Actual infra/platform/temporal/install.mjs lines 257–285 exposes locked-ensure as an ordinary CLI branch and uses context-temporal.lock, not a general context lock. infra/environments/platform-plan.mjs line 701 imposes 600000ms timeout for Redis (Temporal 1200000ms); common/commands.mjs runPlatformCommand default 15000ms. Counterexample: copying the worker entrypoint allows a second cooperating invocation to bypass admission serialization; killing supervisor while descendant Helm remains active can release lock or leave unknown active writer. No evidence this has happened; design does not yet define custody of lock and process tree or total deadline across all reads plus install/receipt. Blocked decision: safe single mutation owner. Closure: identify actual lock participants/key, private worker entry boundary and invocation/termination semantics across public dispatcher, direct CLI, migration and smoke; demonstrate deterministic concurrent admission and timeout/lost-response behavior with no second install while first writer may still act. Explicitly delimit unrelated platform writers; do not require distributed lock or arbitrary-writer guarantees. Existing Temporal pattern is evidence, not proof of Redis safety.

### C03 — high — Absent Helm history is not established by a successful list alone
TARGET.md requires all-state history and says list alone is not definitive; OBSERVER.md specifies anchored list/status/manifest/values, default secret driver. No normative independent inventory of release storage records or error classification is selected. A corrupted/unreadable release record omitted by Helm listing can coexist with absent three resources; fresh install would be attempted on unknown history. Helm name conflicts are not a substitute for zero-write admission, particularly if release record is malformed or storage metadata inconsistent. This is a credible failure path, not a demonstrated cluster defect. Blocked decision: fresh-only admission and partial-state refusal. Closure: decide bounded evidence of absence under supported Helm version/storage semantics, including malformed record, unexpected revision, storage access error and empty list; define fail-closed outcomes and prove no install call in negatives. Do not read/log unrelated secret contents or implement generic release recovery.

### C04 — medium — Observer and public smoke evidence do not yet close runtime identity and preservation contract
OBSERVER.md R8 permits bounded comparisons and explicitly denies general drift detection; appropriate. However recheck after probe is UID/generation/endpoint only: a ConfigMap data edit or Service selector/port edit preserves UID, and a restarted Redis container can preserve Pod UID. A read-only observation can combine stale compatibility and new runtime and report ready. The contract also leaves effective probe target and parsed Redis reply details underspecified (Service DNS PONG is not by itself proof of same server; CONFIG GET/INFO should identify exact intended instance, including expected version and defaults). Existing smoke.sh checks TTL, flush, outage while scaled zero, recovery and volume/context preservation; replacement map mentions TTL/cross-Pod/replacement but does not freeze outage observation or whether old safety invariants and flush are retained or deliberately retired. Blocked decision: exact readiness and proof semantics, not need for universal atomic snapshot. Closure: specify bounded consistency checks for mutable observed fields and container incarnation, exact endpoint/Redis reply checks, and preserve or explicitly retire each old smoke guarantee, including actual outage and recovery; source negatives for same-UID change and false PONG/error, isolated live proof. No demand for detection of arbitrary malicious concurrent writers. 

## Affirmative assessment and limitations

Native release inventory and readback provide a real benefit over create-only kubectl/custom CAS reconciler. Matching-metadata orphan refusal and retained failed release are good discriminating experiments. Local cooperative writer constraint is reasonable; no need for Sentinel, operator, HA, persistence or shared authentication to defend isolated fixture. Docker reported 20k writes, peak 72.49MiB/128MiB and no OOM; sufficient for provisional 32MiB maxmemory and 128MiB limit, not sizing of shared clients. ClusterIP not isolation, and no unauthenticated shared activation permitted. Bounded comparison preferable to generic Kubernetes normalization; exact release digest on observed Kind supported, other forms refuse. Optional Redis application semantics preserved in canonical persistence-and-caching.md; its old create/CAS statement needs eventual reconciliation, not committee editing.
