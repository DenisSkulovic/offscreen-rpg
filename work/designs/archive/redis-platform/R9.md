## C02 — one lock owner, bounded native child commands, uncertain-write fence

Do not copy Temporal's externally callable locked-ensure or its supervisor timeout behavior. All Redis mutations (canonical ensure, smoke including fault/cleanup, later migration) enter one module-private withRedisMutation(profile, operation), never an exported unlocked mutator or CLI bypass. Same fixed per-context Redis lock for all three routes: ~/.local/state/offscreen-rpg/platform-locks/<canonical-context>-redis.lock, local WSL filesystem, owner-only directory/file, refuse symlinks, unexpected owner/mode, unsupported filesystem, HOME/state-root override or unsupported host. No deletion/replacement of lock file, no lock per worktree or namespace. Same OS user/state root and cooperating Redis writers only; other platform services are not serialized, arbitrary kubectl writers excluded. Common cluster identity assertion before and after acquisition; recheck namespace custody. No cross-context lock needed.

Use Linux open-file-description flock: open fixed file once with O_CREAT|O_NOFOLLOW|O_RDWR (0600), fstat, spawnSync('flock',['--exclusive','--wait','30','3'],{stdio:['ignore','pipe','pipe',fd]}); status 0 acquires same open-file-description lock held by parent fd. Close parent fd only after all launched children have exited; no explicit LOCK_UN while child owns fd. All mutation-capable native subprocesses are direct spawn (no shell, no Helm plugins, no auth-provider exec), fd inherited as child descriptor 3 via stdio. Native mutation subprocesses are Helm and kubectl only; no detached grandchildren permitted. Parent SIGKILL leaves direct writer's inherited open description locked until exit. Signal handler stops starting commands, sends TERM then KILL after 5s to direct child and awaits close; do not release lock or report completed before close. On parent death before spawn no writer exists; after spawn writer retains lock. A stuck unkillable child deliberately retains lock; later callers refuse after 30s, not forcibly unlock. No caller can request the unlocked internal function by argv. Read-only plan/status need no lock, report observation separately; they never clear fences. CLI guards and injected runner are not security boundaries against same-user arbitrary code.

A local uncertainty receipt is necessary for the gap between native process exit and remote API commitment, not a generic reconciliation journal or readiness marker. Under lock, before FIRST mutation (including namespace create), durably create one fixed per-context Redis pending file with O_EXCL, 0600; fsync file and parent directory before dispatch. Store operation ID, scope, exact context/namespace, known namespace UID or absent, planned operation, start and phase; no secrets. Existing/malformed/unreadable pending file refuses every Redis mutation in context. No automatic stale expiry or cleanup; no new install on apparently empty history after unknown result. On complete success including required observation and cleanup (smoke), unlink and fsync directory; on failed/unknown mutation or interruption leave receipt, emit redacted diagnostic and stop. Even known nonzero write leaves receipt conservatively. Failure before first write and receipt creation may return without receipt; no writes if durable receipt creation fails. Owner-reviewed explicit recovery only: verify all writer children dead, target and exact inventory, no outstanding API action, decide existing-state repair/cleanup or safe clearance of this exact receipt under same lock. No automated recovery command selected in this structural slice; manual clearance is separately authorized operator action, not ordinary ensure. File is not authority to adopt/delete or report READY. Loss of local state root or host identity is outside cooperating contract; require explicit reconciliation before resuming mutation. This fence is Redis-local and not a cross-service universal marker.

Deadline: monotonic 600s operation budget includes lock wait (max 30s), preflight/read/render commands (max 15s each), Helm install --wait --timeout 180s (outer command max 210s including 5s TERM→KILL), post-observation and receipt. Before any write require at least 360s remaining; reserve 120s for final observation after Helm; namespace create max 15s; recheck remaining before install (minimum 330s), otherwise leave pending/refuse. Each command uses min(own cap, remaining minus 5s kill grace); read-only commands max 15s, kubectl request timeout 10s for API reads, native mutation calls bounded. Smoke has 900s internal budget for scale/outage/recovery/cleanup with same per-command bounds, reserves 180s for final cleanup, stops if insufficient; no automatic cleanup on unknown mutation. Future migration has separate budget before execution, not nested ensure. Actual platform-plan.mjs outer spawnSync currently 600000ms; Redis ensure only removes this external kill timer and invokes lifecycle-owned deadline with inherited output (preserve other phase timeouts). A process stuck in uninterruptible kernel state is a deliberate fail-closed exception to finite completion, not permission to release lock. Parent interruption cannot clear pending. Read-only Redis plan/status can retain bounded outer timer. Common runPlatformCommand remains for reads; Redis mutation runner must implement fd inheritance and awaited termination, not reuse bare spawnSync timeout for writes.

Design-level discrimination performed 2026-11-26 in ChatGPT Linux container, not owner's WSL or Kubernetes: Node fs.openSync, spawnSync flock fd3, competing flock -n returned 1 while parent held fd, child sleep inherited fd3 and parent closed its fd, contender returned 1 until child exit then 0. Actual result acquire 0 / parent-held 1 / child-held 1 / after-exit 0. Reproduction: open temp file, acquire fd3 with flock -x -w 1 3 and stdio fd3, spawn sleep 2 with fd3, close parent fd, contend before/after child exit. Source: https://www.man7.org/linux/man-pages/man2/flock.2.html (open-file-description locks) and https://man7.org/linux/man-pages/man1/flock.1.html (descriptor form). No production runner or signal/receipt crash proof yet. Essential host tests use actual flock and short injected fake mutation executable, two independent process invocations and shared temporary state root through test-only dependency injection (not production env override): contention, direct CLI bypass refusal, parent killed after writer starts, child retains lock, no second write after child exit because pending persists, timeout TERM/KILL and awaited exit, receipt write failure, lost stdout/nonzero/unknown remote response with empty simulated inventory, successful receipt removal and subsequent no-op. Run on actual supported WSL before integration. No need to kill real Helm or disrupt baseline for this host proof.
