# R25 | Admission boundary and narrowed foundation scope
2026-11-26. Integration compatibility a81e275821496e478ba55ae3dce5e72cf63d5dfd; parent a9aea1021aa6cc22893620d36960d0cb68b85286. Design only.
Source anchors: docs/technical/observability/telemetry-and-diagnostics.md sections 2–5 and folded invariants; retention-and-access.md owner map; packages/db/src/telemetry/types.ts registered operations and event contract; runtime.ts allowlistedEvent/emit; packages/cache/src/core/cache-telemetry.ts typed sink with unrestricted namespace/outcome strings. Existing domain telemetry types do not prove runtime value validation or OTLP wiring. Do not change those packages in foundation.
Decision: scope initial structural platform to synthetic-only use. Application admission is a separately commissioned, runtime-validated source adapter plus defensive gateway policy. No SDK activation, auto-instrumentation, raw stdout tailing, paid calls, domain evidence changes, or claims of producer authentication. Trusted local cluster: arbitrary Pod can reach ClusterIP; declared resource identities are not authenticated. NetworkPolicy is not assumed enforced. Backend ingestion interfaces likewise not authorization boundaries. A hostile or compromised Pod can bypass Collector and send directly; this is not tenant isolation. No actual sensitive data may enter this topology. Hosted/hostile tenant deployment requires authenticated ingress and backend network isolation with tested enforcement.
Privacy policy for foundation: fixed synthetic vocabulary; no real app credentials, prompt/output, narrative, player IDs, raw exceptions, SQL values or arbitrary bodies. Keep operational and durable evidence separate. Application adapter must construct allowlisted records, validate values with domain enums and bounded numbers, no arbitrary object serialization, disable unrestricted SDK instrumentation. Future application admission must explicitly review span names, status messages, events, links, resource/scope attributes, trace state, log bodies/severity, metric descriptions/units, datapoint labels/exemplars and numeric/cardinality bounds. Drop unknown signal shapes and processor failures; never echo rejected payload. No claim of information-theoretic sanitization (IDs/numeric data can encode content); producer trust and source contract essential. Slot attribution currently self-declared, not security identity; future authenticated source binding separate.
Concrete experiment decision: distinguish structural foundation safety (no source wiring, no debug exporter, no stdout collection, fixed synthetic contract) from an app-admission sanitizer experiment. Do not use unvalidated OTTL as a security guarantee. Before adopting any gateway filter, selected 0.165.0 tagged upstream syntax and executable validation required. Negative synthetic tests include unauthorized resource/service, unknown names, secret in unknown/allowed key, free-form body, span event/status/link, metric metadata/exemplar, scope attributes; query all relevant backend fields and inspect Collector logs, preserve positive control. No application authorization on a successful synthetic test.
