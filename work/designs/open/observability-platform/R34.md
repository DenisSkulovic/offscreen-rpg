## Whole observation deadline
Baseline diagnostic-live makes six sequential external preflight calls: docker context show/inspect, kubectl config view, then assertPlatformTarget's kind get clusters, kubectl config view and baseline namespace get (commands.mjs:241–338). At 15s each these alone permit nearly 90s, before additional R30 snapshot/identity checks. Existing 180s outer deadline cannot guarantee 120s inventory. Provisioning uses same worker with default 900s check timeout (provisioning.mjs:115–181). Do not widen unrelated timeouts or reuse mutation's 1500s budget.

Freeze observability-only 360s supervisor, 345s worker absolute monotonic budget from entry, partition as follows: 210s maximum pre-inventory identity preflight (including frozen kubeconfig acquisition/validation, local Docker binding, baseline and cluster UID checks), 120s maximum native structural observation (R30; including legacy checks, Helm records, pending observation, PV claimRef and final identity validation), 15s cleanup and bounded terminal receipt. Outer 15s additional launch/transport margin. No stage may borrow from later reserve. Preflight completion before its limit starts inventory immediately, not after waiting; inventory deadline min(start+120s, workerStart+330s); preflight deadline workerStart+210s. Recheck relevant frozen identity after inventory before accepting ready or absent, within same inventory deadline. If stage cannot finish within bound, fail closed; no retry extension. Direct status native read-only observation uses same identity+inventory+cleanup policy, with service-local budget from observer entry; do not double-run preflight or restart budget on delegation. Diagnostic worker passes same absolute budget and already validated identity/snapshot to native classifier through observeSelectedServiceState's existing deps seam. Existing status caller does not need a new supervisor; local bounded runner and cleanup enforce same worker limit. R30 ensure final observation retains its own 120s reserved inventory budget with already established identity, capped by ensure's absolute deadline; no new 345s inside mutation. Read-only observation never acquires mutation lock, creates pending, repairs or changes cluster state; private kubeconfig temporary file allowed, cleanup bounded and credentials excluded from output.

Implement scoped runner using monotonic performance.now; for each preflight subprocess cap timeout to min(15000ms, remaining phase budget, remaining absolute budget); native reads cap to min(10000ms, remaining inventory budget, remaining absolute budget). Include snapshot/identity/Helm/API subprocesses, PV reads, parsing and final identity recheck; no uncapped default runner escape. Before and after each command and before terminal success check deadline, even when subprocess reports exit 0. If remaining <=0 do not launch. For scoped synchronous reads use explicit SIGKILL timeout killSignal (no indefinite wait for SIGTERM-ignoring client); use same process group as diagnostic worker, no detached descendants, no shell, auth plugins/proxy rejected per R30. Preserve timeout as unreadable/failure with stable reason, reject nonzero/signal/error/overflow before parsing output. Bounded output limits inherited (8MiB per native command, diagnostic capture 2MiB; receipt <=16KiB); no raw secret or kubeconfig. Cleanup private snapshot in finally, failed cleanup cannot yield PASS/optional absence; hard external kill may leave owner-private files, disclosed R33 limitation. Outer runCommand kills Linux process group on timeout and commandOutcome rejects result before JSON evaluation even if stdout contains a plausible success/absence. Supported local runtime is Linux/WSL; no new cross-platform process-tree guarantee. No claim of exact scheduling wall-clock guarantee under OS suspension. Supervisor deadline per observability row in diagnostic.mjs and provisioning.mjs post-ensure only; keep cluster/other check timeouts and ensure deadlines unchanged.

## Receipt boundary and deterministic proof
Observability worker emits one bounded JSON object with status and reason, plus typed structural state (absent/ready/partial/foreign/legacy/refused/unreadable/not-ready or equivalent explicit mapping) on completed classifier path. Preflight/timeout/cleanup failure emits FAIL with unreadable state and stable reason. Validate known state/status/reason combinations in diagnostic evaluator for observability only, including NOT-RUN only for default release and positively verified absence; malformed/missing/contradictory/unknown receipt fails, never interpret unsupported as NOT-RUN. Existing provisioning observeOutcome accepts only PASS; additionally validate observability receipt consistency on post-ensure. No new general receipt framework. Preserve unrelated worker contract.
