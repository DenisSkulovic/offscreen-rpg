## Provisional selection
Independent Helm releases for OTel Collector, Prometheus, Loki single binary, Tempo monolithic, Grafana. One optional platform per cluster; dev slots share it, release separate. No operator, Mimir, Kafka or HA. OpenObserve single-node is a credible lower-component alternative (SQLite metadata, disk/object store); prefer modular stack for independent failure domains, PromQL/LogQL/TraceQL experience and existing technical recommendation; switch only if measured budget fails. All-in-one LGTM remains comparison specimen. No measured performance comparison.
Local independent PVCs for each backend, not SeaweedFS. Game storage failure should not also disable diagnostics. Kind physical disk remains shared. PVC request is not a hard quota on local-path; require monitoring, retention, ingestion/cardinality limits and pressure refusal. Hosted object storage separately designed. Grafana datasource provisioning as code; persistent Grafana state only if needed, no manually edited dashboard as sole source.
Candidate retention experiment: 7 days metrics, 3 days logs/traces, 5 GiB requested per backend; no guarantee that filesystem usage stays within request. Validate compaction headroom and real rates before acceptance. Avoid sharing credentials/buckets with game.

## Collection ownership
Application SDK -> single upstream contrib/k8s Collector gateway OTLP gRPC/HTTP; explicit component inventory required at selected version. Traces -> Tempo OTLP; logs -> Loki native OTLP HTTP (base /otlp); metrics -> Prometheus native OTLP HTTP (base /api/v1/otlp). Prometheus independently scrapes allowlisted native exporters and collector self metrics. Prefer cumulative SDK metrics for initial scope; reject unsupported temporality until proof, do not silently drop or double-convert. Preserve unique instance identity for metric writers (no operation IDs); explicitly select resource promotion and test reset/duplicate behavior. Loki index labels limited to environment/namespace/service; instance and pod names structured metadata, trace/span IDs for correlation, no user identifiers. No raw stdout ingestion by default; existing stderr diagnostics remain accessible via kubectl, later scoped parser/allowlist or application OTLP logging, never both for same event. No claim of complete application coverage.
Kubernetes state and node resource collection separate next slice: choose kube-state-metrics and native kubelet scrape via Prometheus vs single cluster receiver plus node DaemonSet; do not enable duplicate signal paths. No cluster-wide filelog preset, privileged host access or operator by default. Workstation recorder stays independent. Security: cluster-local not equivalent to tenant auth; trusted local operator profile only, no hostile multi-tenant claim. Test spoofed identity and do not trust SDK resource attributes for authorization. Explicit source-side safe event contract plus gateway allowlist; arbitrary log body cannot be safely redacted by key filters alone. Grafana loopback access with auth; no public endpoints; backend API trust boundary must be documented.

## Upstream evidence (accessed 2026-11-26; current docs not pinned versions)
- https://opentelemetry.io/docs/platforms/kubernetes/helm/collector/ and https://opentelemetry.io/docs/platforms/kubernetes/collector/components/ : node-local kubelet and singleton cluster collection; duplicate risk. Helm defaults must be explicitly disabled where not used.
- https://prometheus.io/docs/guides/opentelemetry/ : native OTLP endpoint, target_info and resource promotion, delta conversion version-dependent; use cumulative initially and test actual selected build.
- https://grafana.com/docs/loki/latest/send-data/otel/ and https://grafana.com/docs/loki/latest/get-started/labels/ : native OTLP and structured metadata, demote pod/instance labels.
- https://grafana.com/docs/loki/latest/setup/install/helm/install-monolithic/ and https://grafana.com/docs/loki/latest/setup/install/helm/configure-storage/ : single binary filesystem supported, chart moved to grafana-community; no replicas >1 with local storage.
- https://grafana.com/docs/loki/latest/operations/storage/retention/ : compactor retention needs persistent markers and delete request store.
- https://grafana.com/docs/tempo/latest/reference-tempo-architecture/about-tempo-architecture/ and https://grafana.com/docs/tempo/latest/set-up-for-tracing/setup-tempo/plan/ : monolithic bypasses Kafka, filesystem local test; no built-in authentication per deployment docs.
- https://openobserve.ai/docs/architecture/ : consolidated single-node alternative; no comparative memory data.
- https://opentelemetry.io/docs/collector/resiliency/ : bounded queues and retries, in-memory crash loss expected; do not add Kafka merely to protect disposable telemetry.
