# Observability platform renewal | R1 discovery
2026-11-26. Integration baseline 2138ae4a4a188c5dce54e2f77d4211d6ab4f1ed3; design branch design/observability-platform. Proposed, not defended or commissioned. Owner target: serious 20-developer engineering practices on local gaming-PC kind clusters. Evolutionary boundary discovery with independent native-first target; existing collector is not architectural authority.

## Scope and intent
Optional shared platform per cluster (dev slots share one instance; release distinct), OTLP ingress, persistent queryable metrics/traces/logs, provisioned Grafana, resource and privacy controls, repeatable lifecycle and synthetic proof. Preserve native domain forensic evidence (SQL/CAS), workstation Netdata/flight recorder (infra/monitoring), and business authority. No application-wide instrumentation migration, hosted service, HA, destructive migration, paid calls, or live mutation in this workshop.

## Baseline discoveries
- infra/platform/observability/chart/files/collector-config.yaml: core OTLP HTTP 4318, memory limiter 96 MiB, debug detailed exporter for all three signals; no persistent backend. Detailed debug must not receive real sensitive telemetry.
- infra/platform/observability/install.sh: release-only, lab-a, host Docker image inspect/import, custom render/apply and rollout. Existing collector is a synthetic specimen, not demonstrated game telemetry.
- docs/runbooks/kubernetes-observability.md: two-hop synthetic parent/child trace and missing-hop log/counter proof; observed termination race (endpoints empty before pod exit). Preserve proof intent, replace stdout assertions with query-backend proof.
- docs/technical/observability/telemetry-and-diagnostics.md: existing proposed OTel + Grafana/Prometheus/Tempo/Loki separation; telemetry is lossy, never game evidence. Historical source inventory not current instrumentation audit.
- infra/platform/common/profile.mjs: no observability namespace mapping; dev standard vs release local-path storage. Need actual catalog/status/verification consumer map and adjacent native installer contracts before cutover.
- docs/technical/platform/workstation-observability.md: independently owned host recorder, not replacement target.
- work/QUEUE.md: none. Storyteller Workshop overview historical ~75% architecture, ~40% story, ~30% distributed, ~45% overall ±20pp; no new runtime credit. Local worktree state not observable through GitHub.

## Provisional architecture
Application OTel SDK -> shared Collector Deployment via internal OTLP HTTP/gRPC -> Prometheus (metrics transport to choose), monolithic Tempo, single-binary Loki -> Grafana provisioned datasources. Kubernetes/node metrics and stdout logs have separate explicit collection ownership; avoid duplicated metrics/logs and default cluster-wide secret-bearing log capture. Consider scoped DaemonSet only when its coverage justifies RBAC and host access. No operator/CRD requirement by default. Prefer pinned upstream charts/artifacts, native release ownership, distinct namespace and stable internal endpoint. No per-slot backend stacks. No public collector or dashboard endpoints; local loopback access with auth; no assumed NetworkPolicy enforcement on kind. Backend data is diagnostic and disposable only with explicit authority. Local PVC versus isolated S3 buckets requires storage/retention/credential and dependency review. Do not reuse game evidence buckets or database.
Application execution must not depend on telemetry success: asynchronous bounded buffers, timeout/retry/drop visibility, no durable business guarantees. Backend outage isolated by signal, restart loss explicitly documented. Attribute allowlists and sanitization before export; no prompts/story content/credentials/player IDs or high-cardinality metric labels. Resource identity includes environment/slot/service/version; trusted namespace attribution mechanism to be designed. Logs collected once per source. Trace context via W3C; long workflows use short spans/links rather than perpetual trace. No raw SQL bind values or provider payloads.
Exploratory target 1–2 GiB working memory per active stack and 10–20 GiB disk; not validated sizing or container limits. Measure cold/warm idle, load, backend outage and recovery, storage compaction and concurrent dev/release resource costs; tune retention/limits from evidence.

## Research (current upstream docs accessed 2026-11-26; versions NOT selected)
- https://opentelemetry.io/docs/collector/deploy/gateway/ supports centralized OTLP endpoint. https://opentelemetry.io/docs/platforms/kubernetes/helm/collector/ supports Deployment/DaemonSet and warns against duplicate per-node collection. https://opentelemetry.io/docs/platforms/kubernetes/collector/components/ distinguishes node and cluster receivers. Implication: gateway first, agent only if needed. Verify pinned chart defaults, receiver/exporter availability, RBAC and queue limits.
- https://grafana.com/docs/tempo/latest/reference-tempo-architecture/deployment-modes/ and https://grafana.com/docs/loki/latest/get-started/deployment-modes/ support monolithic modes. Filesystem storage suitable for local development/test; production storage decisions separate. Verify selected versions, chart defaults, retention and query APIs.
- https://grafana.com/docs/opentelemetry/docker-lgtm/ positions consolidated image for development/demo/testing; useful comparison specimen, not preferred reference architecture.
- https://prometheus.io/docs/prometheus/latest/storage/ notes compaction can temporarily exceed retention size. Leave disk headroom, validate actual cap/retention and ingestion path.
- https://opentelemetry.io/docs/guidance/blueprints/managed-telemetry-platforms-for-k8s-workloads/ describes memory limiter and sending queues; bounded queues, failure isolation and self-metrics require selected-version verification.
Compare modular stack vs consolidated backend (OpenObserve or equivalent) and LGTM sandbox on memory, component ownership, storage and operational learning; reject distributed Mimir/Kafka/HA without evidence.
