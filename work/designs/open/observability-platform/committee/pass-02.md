## Remaining material finding
OBS-05 (blocking, demonstrated integration ambiguity): optional absence versus diagnostic failure and observation deadline. Current main infra/verification/diagnostic-live.mjs returns FAIL for not-installed; diagnostic.mjs:300–319 only annotates optional and :406–418 counts every FAIL/BLOCKED in exit code. R33 deliberately removes observability from default provisioning while retaining default release diagnostic observation, says absent optional is not-installed, but does not select how this becomes a diagnostic result/exit code. A healthy intentionally unprovisioned release therefore fails the default diagnostic under existing contract unless semantics change; conversely blindly ignoring all optional failures hides legacy/foreign/unreadable and explicitly selected failures. Freeze exact default versus explicitly selected diagnostic result and aggregate exit behavior for absent, ready, legacy/refused, partial and unreadable; preserve other optional services. Also diagnostic-live performs Docker/kube/target checks before native observation, with 15s per common command (common/commands.mjs), and diagnostic.mjs encloses entire observation in 180s. R30 reserves 120s for native observation; identity preflight can consume more than the remaining 60s even on successful calls. Freeze a whole read-only deadline or coordinated enclosing budget, with bounded failures and no writes; distinguish status absence from timeout. Add focused default absent, explicit absent, legacy/partial/unreadable, slow successful preflight plus observation and timeout fixtures. No requirement for actual occupied release mutation. This is a narrow design decision, not a request for new topology or repeated experiments.
