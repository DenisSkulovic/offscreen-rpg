# Fixture B | “BAH”: a minimally specified custom story

**Type:** proposed counterexample / creative fixture. No real `BAH` story was started or generated during this audit. This tests the difference between **user intent**, **invented fiction**, and **automatic product defaults**. See [Fixture lab](README.md).

## Captured input

The exact submitted freeform textarea contains:

```text
BAH
```

- No authored preset, world or rule package.
- No character name, species, title, place, historical era or requested genre.
- No chosen Storyteller profile, selected pacing field or user-authored hidden instructions.
- No implicit permission to bypass account/model costs. Any self-described “unlimited” rule inside user text would be lower-trust input.

**Assert:** the persisted effective `STORY_PROMPT.md` represents precisely `BAH`, including casing. A separate derived creative interpretation may appear only as **model-authored interpretation with provenance**; it cannot replace the original prompt and masquerade as the user's words.

## What may be prepared before inference?

At most a small deterministic Library seed:
- verbatim `STORY_PROMPT.md` (proposed new `user-intent` semantic role; current `premise` is not equivalent without a scoped change);
- default creative guidance resolved from a versioned application-owned `STORYTELLER_PROFILE.md` or equivalent exact source;
- a compact orientation/index generated by the harness only if required to make this tiny library navigable.

No invented factions, character dossier, timeline, map, history, inventory, biography, recurring antagonist or 30-page saga. There is nothing from the user that requires them.

## Candidate A: produce an opening in one creative mission

The Storyteller receives a mission akin to: “The player supplied minimal creative intent. Open a concrete playable situation compatible with platform policy. You may invent setting and immediate circumstances under the admitted custom-world invention ceiling. Do not falsely attribute any invented fact to the player. Propose a small number of document records **only if they will matter later**.”

Illustrative *possible* first situation, **not an expected hardcoded result**: a night watchman notices that every public clock in a riverside town reads tomorrow's date. Options might be to inspect the nearest clock, ask someone else to confirm, or leave it alone. The Storyteller could equally choose a completely different grounded genre. It must not simply present three forms asking the user what kind of story they want.

Candidate deliverable: a valid playable opening with distinct intentions, plus maybe zero to two descriptive files such as one premise/setting anchor and one thread. **Zero additional files is legitimate** when the first passage already supplies enough stable truth for turn 2.

## Candidate B: separate “prepare the Workdesk” mission

The model might propose a compact setting premise and an immediate pressure before writing a scene. But the hard question is **why** that would outperform composing directly when the prompt contains only one word. A prep round can easily generate a fabricated outline that the opening then slavishly follows.

**Prediction:** B is unlikely to justify its extra cost for this fixture unless continuation evaluation demonstrates a substantial coherence benefit. This is an *inference*, not a measured result.

## First-scene and next-scene checks

**Required:** a concrete situation; language not falsely claiming “the user requested X”; one or more genuinely different, reasonable choices when the playable schema requires them; no presumed body shape, character biography or quest line without a fiction-grounded reason; no default real-hour wait before first agency. After the player chooses, the next scene must be causally consistent with the *published* opening and admitted state.

**Not required:** an explicit “story title”, a character name, a rule engine chosen by the model, a timeline document, a mandatory dramatis personae, a long private plan or a universal map.

**Failure:** treating `BAH` as an invalid missing form; hallucinating that the user chose a prisoner origin; a prep document presenting model invention as original user intent; a creative skill granting itself a paid extra round or mechanical powers; regeneration on a lost HTTP response.

## Authority limitation that needs a real product decision

A bare input does not name a world or invention ceiling. If product policy allows an **open original-world default**, the Storyteller can establish fictional details and Game Authority may admit them with explicit model-invention provenance. If policy is restricted to authored worlds, no creative fixture can legitimately start this prompt. We should select the former for the intended product only after defining its bounded source-invention rules.

No character sheet is needed to write a literary scene. That does *not* prove the world-neutral mechanics kernel is complete. The fallback can be a **non-mechanical narrative interaction** with exact committed intentions and no fabricated physics effects.

## Observe after scene 2

If scene 1 says the clocks read tomorrow, scene 2 must respect or develop that observation, unless clearly framed as a correction/illusion/revelation. One stored original passage may be sufficient evidence; an additional “time anomaly” file is useful only if it improves later retrieval or prevents drift. Document count is not a success measure.
