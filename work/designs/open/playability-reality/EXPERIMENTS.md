# REAL03 experiment protocol | Is this worth playing?

**State:** experimental design only. This page does not run models, select providers, authorize spend, choose production pricing, or certify quality. Human judgments are required. Implement no instrumentation beyond existing supported facilities without a separate approved Change.

## First gate: provider-free causal health

Before a paid run, REAL01 must define one actual V0 solo oracle and REAL02 must characterize core publication/recall. Fix blocking crashes and false receipts under normal Change selection. Distinguish a simplified accepted target from a script that requires two players, arbitrary body transformations or unauthorised decision deadlines. No need to complete every dreamworld feature.

## Experiment A: 20–30 accepted solo turns

**Hypothesis:** A bounded Storyteller can sustain a fresh, intelligible and intrinsically interesting life without long multi-round exploration as the default.

Run one prepared small world/character, record source pin/profile/route version, exact consent/spend allowance and a starting state. The player should not be pre-briefed on the expected scene outcomes. Include: an offered uninteresting option, a sensible unoffered intention (record the impulse, do not bypass the selected interface), one quiet interval, one interruption, two meaningful choices, a failed or declined offer, a return encounter and one social continuity requirement. Keep legitimate pauses and no-event outcomes.

**Every turn record:** exact accepted decision/receipt IDs and time, provider attempts (including discarded/repair), prompt/completion tokens and charges, latency, publication state, observed lost/incorrect fact, agency friction, redundancy, enjoyment rating 1–5, and whether the player wanted another turn. The experimenter notes if they needed to edit scenario text or manually repair context. Do not count hand-written scripted lines as model success.

**Pass is not a magic number:** propose go to next iteration only if (a) no false committed effects or source leaks; (b) key continuity judged correct from raw source by independent reading; (c) agency and novelty repeatedly clear user-defined tolerances; (d) actual *total* cost per accepted worthwhile turn is within an owner-set cap; (e) owner voluntarily wants a second session. Record all numerical thresholds **before** spending, not after seeing results. A schema pass without human appetite to continue is a product failure.

## Experiment B: closed-browser return

**Hypothesis:** real-time, admitted offscreen progression makes the player care more than an immediate montage.

Select one admitted work/wait period lasting 20–30 real minutes (or an explicitly labeled accelerated diagnostic variant). Close browser. Do not infer permission to auto-select new work. Reopen after scheduled completion or a declared interruption; include a separate process restart case. Assert exactly once completion/hold, correct recorded elapsed time and source-linked current narrative. Compare (1) quiet result, (2) one legitimate valuable interruption; **no forced event** for entertainment. Ask whether the return felt deserved and whether the wait was a feature or a tax.

Record accepted-work identity, real start/due, fictional time, hold/resume status, actual provider rounds and cost **during idle and on reentry**, duplication/retry behavior, and a short subjective rating. An accelerated developer clock is not proof of twenty minutes of actual wait appeal.

## Economics: what to measure, not guess

- **Numerator:** all settled provider charges, known failed/repaired/discarded rounds, retrieval/embedding charges if any, plus explicit uncertain liabilities. Do not call ambiguous costs zero.
- **Denominators:** accepted decisions, useful published turns, and *worthwhile returns* as distinct categories; do not hide uninteresting/failed outputs by reporting only successful requests.
- **Context growth:** prompt bytes/tokens at turn 1, 10, 20, 30; exact recall reads and omissions; cost delta with larger source corpus.
- **Caps:** per operation, per session, hard review/stop amount and max provider rounds chosen before any live attempt. Budget exhaustion must halt/retain committed mechanics and never authorize hidden retries.
- **Outcome:** compare one-shot cheap baseline to optional bounded exploration only on scenarios where reference recall actually fails, recording incremental quality **per extra cost**.

A one-time recorded ~$0.023 Sol call is a sample of one operation, not a long-play distribution. ChatGPT subscription and API pricing cannot be interchanged.

## Decision rules

If deterministic integrity fails: repair the causal chain, do not add player-facing breadth. If memory recall fails: inspect **creation → publication → source selection → final model input**; add only the missing link. If quality is dull with correct state: redesign choices/scenes and test again, not the knowledge graph. If economics fail: reduce calls/context/repair rate or scope, not user trust. If the return adds no value: reconsider the pace thesis before expanding notifications or autonomy.

**Publication of results:** dated, source-linked evidence in evidence/ or experiments register; include negatives, exact running commands/environment, human rubric, actual costs, and any blocked stages. Never label an unrun protocol "passed".
