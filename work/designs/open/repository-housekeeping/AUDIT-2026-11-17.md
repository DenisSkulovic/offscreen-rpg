## Durable triage rules for Cursor

1. **Delete:** unowned executable with no supported operational use and no live import/caller, after a direct source search and negative proof; use git history for recovery.
2. **Move/reclassify:** past investigations masquerading as *open* status, only with a complete backlink repair and no loss of one authoritative decision/evidence record. A doc-only move is not itself a code-bearing Change.
3. **Refactor:** monolithic code with a demonstrable ownership/test boundary, preserving every observable invariant, mock/provider rule, CLI exit code and negative test. Extract one seam per Change.
4. **Keep:** active migration snapshots, registered CI tools, light adapter wrappers, linked test fixtures/content, historical decisions and forensic evidence. “Old” does not mean disposable.
5. **Do not manufacture work:** deliberately excluded from this effort are a package-wide directory rename, engine/Storyteller prompt redesign, Play UI restyling, open UI01–UI08/DIR01–03 waves, arbitrary DB schema squashing, and the 2026-11-17 retrieval experiments already retired by HAR10.

## Validation / limitations

Audit was static: path inspection, package manifest and entrypoint reading, file-size/line inventory, direct reference search, docs checker self-test, and GitHub SHA comparison. No truthful conclusion about runtime call graph completeness, CI green status or local developer invocation history can follow from those alone. Fresh Cursor checkout must preserve all unrelated working-tree modifications; no blind `rm -rf`, no rewrite of prior commits, no automatic mass archive, no paid provider or destructive DB test.

**Prevention order:** HK02 (docs CI scope) → HK06 (inventory/lifecycle) → HK07 (Git dependency freshness) → HK08 (push/PR/brief/weekly feedback and status convergence). **Cleanup order:** HK01 after independent recovery/caller proof, HK05 after UI03, HK03 only with QA-SF01 baseline, HK04 only with launcher safety matrix. HK03/HK04 may be deferred if their proof cost exceeds the cleanup value. [System target and root causes](PREVENTION-SYSTEM.md).

**Closeout:** record each file disposition (kept / moved / removed / deferred), broken-link and test results, source SHA, and remaining unknowns back into this audit or a dated appendix. After any implementation, reconcile the owning README and STATUS only if actual behavior changed.
