## 1. Problem and alternatives
The native foundation is valuable: five independently owned Helm releases, pinned charts/images, optional profile selection, 3 retained claims, Grafana provisioning, scoped custody. Owner observed ready workloads, authenticated three datasource health, accepted synthetic OTLP submissions. But no complete synthetic backend query proof, no clean A6 pass, no general application telemetry. The permanent inputs retain experimental naming and misleading comments. Collector exact synthetic vocabulary drops actual applications and its Pod-IP receiver cannot accept kubectl port-forward's loopback connection. Install-only lifecycle and structural-only observation cannot recognize or safely evolve configuration. Actual proof defaults contain unwired datasource, incorrect host vs Pod execution, duplicate Python arguments and zero-interval/no-port resource sampling. 118 focused JS passes did not establish real usability. See DESIGN-R2 evidence, source map and acceptance matrix.

Alternatives: retain strict synthetic only (does not meet developer goal); turn existing receiver unrestricted (breaks diagnostics and release compatibility, leaks payloads); separate Collector deployment (extra resources/ownership, no need demonstrated); two distinct receiver IDs in same Collector (selected: render and pinned binary validate PASS, no new resource identity). No umbrella chart: upstream chart-native values already render/install five releases independently. No reset/reinstall: need retained backend state and credential continuity. No generic upgrade controller: only known dev Collector transition now. No persistent connection daemon: foreground process ownership sufficient. No new cluster for ordinary qualification; isolated destructive original proof remains separately gated.

## 4. Developer v1 contract (narrow but usable)
Finite enrolled service names: offscreen-agent-poc and offscreen-developer-proof. Namespace offscreen, environment development, scope offscreen.operational.v1. All three must be exact. No service.instance.id retained: metrics single writer per service/candidate stream; trace/log correlation via native trace IDs and optional run attribute 16 lowercase hex. Producer contract prohibits multiple concurrent writers to same metric stream; first POCs sequential, proof sequential. Distinct future writers require revised metric identity contract. Resource allowlist only service.name, service.namespace, deployment.environment.name. Scope attrs empty, version empty; resource/scope schema URLs must be empty at producer, no general sanitization guarantee. Do not promote run IDs to resource labels. No auto-admission of arbitrary native SDK signals.

Trace names static code-owned dotted lower-case identifiers 1..96 chars, regex ^[a-z][a-z0-9_.]{0,95}$; no dynamic user-derived names. Native trace/span/parent IDs, timestamps, kind, status code retained. Trace attrs only offscreen.run (optional hex16), offscreen.candidate (optional enum vercel/strands/openai/probe), offscreen.outcome (optional ok/error/cancelled), offscreen.retry (optional int 0..32). Invalid allowed value rejects record; unknown attrs stripped. Clear status message, events, links, trace state. Logs body same static name grammar; only same attrs, preserve native trace/span correlation, normalize severity text to empty and event_name empty, severity number retained subject to valid OTLP range. Raw arbitrary body forbidden. No general exception log capture. This contract accepts new static operation names without infra edits.

Metrics deliberately more restrictive. Exactly three initial names: offscreen.agent.runs (cumulative monotonic sum, unit 1), offscreen.agent.active (gauge, unit 1), offscreen.agent.duration (cumulative explicit histogram, unit s). One bounded label offscreen.candidate enum, no other datapoint attributes. Required candidate; reject extra dimensions rather than collapse distinct series. No run IDs, workflow IDs, instance IDs, exemplars. Finite service/candidate combinations, histogram bounds fixed [0.01,0.1,1,10,60] seconds, nonnegative finite values, integer counter/gauge and histogram count; histogram bucket count and sum valid. Producer must enforce fixed histogram shape and nonnegative values; Collector enforces metric name, unit, type, temporality, monotonicity and label set; numeric correctness and fixed histogram bucket boundaries are trusted producer obligations, not Collector enforcement. Exact OTTL processing must be proven before scope defended. Metric names/units verified against actual Prometheus conversion; no guessed query names considered proof. Clear description and metadata; keep unit canonical. Counter cumulative resets on worker restart acceptable; no accounting or billing authority. No automatic native SDK metric import. Metric cardinality includes Prometheus target_info and histogram expansion; verify actual series not just application labels. 
Operational event names and trace names are intentionally not centrally enumerated; approved trusted producer code owns them. Numeric values and strings can encode secrets; policy is not DLP. Error_mode propagate and bounded exporter queues remain. A filter drop may return OTLP success; backend queries are authoritative.
