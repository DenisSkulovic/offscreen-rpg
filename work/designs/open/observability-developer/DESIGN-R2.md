Trust model: trusted single-owner local environment, not a tenant security boundary. Claimed resource identity is a classification hint, not authentication. Do not accept real secrets or domain payloads. No public endpoint, remote producer onboarding, credentials in telemetry or arbitrary auto-instrumentation. No promise of confidentiality against malicious producers. Keep backend retention and limits initially.

Candidate minimal envelope v1:

- traces: bounded static operation identifier, native trace/span/parent IDs and timestamps, kind/status code; allow only typed outcome enum, retry count bounded nonnegative, duration or count where meaningful, finite candidate enum vercel/strands/openai/probe; remove status.message, events/links/tracestate and all other attributes. Operation name not a secret detection boundary; trusted producers must select static code-owned names. Preserve parent/child correlation.
- logs: static event identifier as body (or normalized event attribute projected into body), severity and native trace/span IDs; same typed safe fields. No arbitrary log strings or maps. Unknown structured fields removed. No raw exception, prompts/completions, tool payloads or SQL text/params.
- metrics: first application proof uses cumulative monotonic counter, gauge, explicit histogram; finite registered metric names and label sets initially, no run/trace/user/workflow IDs on metrics, finite candidate/outcome enums, no instance ID resource promotion. Reject malformed numeric values, bound histogram buckets and attribute count; strip exemplars/metadata/description where necessary. Do not silently delete identity-defining labels and merge distinct metric streams; reject unsupported dimensions or choose producer-normalized schema first. Metric cardinality must be proven using adversarial varying IDs; resource target_info and job/instance behavior need backend proof. No guessed full SDK compatibility.

Counter/gauge/histogram values not business authority. No semantic registry for every span operation; metrics vocabulary intentionally more restricted.

Bind fixed default local 14318 HTTP, 14317 gRPC, 13000 Grafana; backend query forwards 19090/13100/13200 opt-in only. Explicit development target, private frozen kubeconfig, bounded preflight requires desired configuration ready and no pending. Reject conflicts; no killing foreign process. Existing dev lifecycle integration only if actual source seam merits reuse; no Tilt slot required.

## 4. Occupied upgrade candidate
Do not use helm upgrade --install, force, take-ownership, or implicit ensure upgrade. Narrow service operation: pnpm obs:upgrade (dev only; Collector only), explicit owner intent, same service custody and pending fence. Preserve current four other release revisions, namespace UID, Grafana Secret UID, all three claim/PV tuples; no backend restart or deletion. Use pinned same chart version, desired descriptor, explicit --reset-values and bounded --wait/--timeout; no auto rollback, retain fence on uncertainty. History max candidate 5, bounded history and Secret metadata validation; confirm exact Helm 3.22.1 flags. No generic upgrade API, no release mutation.

Source deficiencies at baseline:
- readiness.mjs assessDirectInventory checks object existence and Helm ownership, not config; verifyHelmRevisions counts list rows, not actual storage revisions. inventory.mjs listHelmReleases uses helm list (not history); collectInventory fetches manifest by name, not exact revision; sanitizeListedObject drops ConfigMap data and sanitizeSecretObservation drops resourceVersion. findUnknownEnumerated exempts any Helm prefix; no blanket history acceptance. verifyControllerChains currently first owner ref, only Pod loop; verifyWorkloadImages checks related Pods but not exact current ReplicaSet config identity. Need ensure all mutated workload identity checked rather than broad unrelated drift rewrite.
- identity.mjs captureIdentity records tuple but does not compare raw CA to local Kind kubeconfig; recheckIdentity validates ambient context/port and optional namespace UID, not Docker ID, kube-system/baseline UIDs or CA; readNamespaceUid currently ambient. Repair full binding before mutation, use explicit private snapshot for API reads; snapshot immutable in private directory and compare CA/endpoint against independently captured Kind config in memory.
- install.mjs runObservabilityEnsure admits ready/no pending as no-op and absent as install; preserve that behavior with new explicit upgrade-required state when known predecessor config. helmInstallArgv uses same descriptor inputs as render. Original pending tuple and install phase logic not enough to identify upgrade old/new revisions; add operation-specific record with old/current desired config hash, revision, release and target identities; never bypass foreign pending.
- Namespace create UID binding should come from actual create output and compare observation, not adopt observed replacement. Existing custody update uses truncation; malformed pending fails closed; review atomic update and exact operation check before clear. runMutation stderr handling and safe diagnostics need focused repair.

Candidate state machine:
absent -> ensure installs desired; ready-current -> ensure/upgrade no writes; ready-known-predecessor -> ensure refuses upgrade-required, explicit upgrade admitted; foreign/unknown config/unreadable/pending/partial -> refuse. During upgrade acquire exclusive service lock, capture/validate old/new artifacts (known predecessor frozen render/config identity, no trust-on-first-use), verify current release history latest deployed exact revision, previous superseded only and retained known storage records; compare live Collector ConfigMap content, Service ports, workload template/mount/config checksum and current owned Pods against expected predecessor. Freeze desired config hash of canonical nonsecret relevant render projection, not entire Helm dynamic manifest or Git SHA. Old and new config projections must differ only approved paths; no resource replacement. Persist pending before first possible write; invoke exactly one bounded Helm upgrade with same chart and values descriptor. Wait for exact new revision, no old active pod, new ready pinned Pod, exact expected config and endpoints, functional probe, unchanged preserved UIDs and four release revisions, full identity recheck. Clear only own pending receipt on success. On failure retain pending, phase and known-safe diagnostic; do not retry/rollback automatically. Manual recovery separately authorized, no deletion.
Future release history may include rollback/failed revision; initial scope only normal successful bounded history, fail closed on unknown. Define status policy for known predecessor and pending explicitly, no downgrade. Current revision-1 installed platform requires known predecessor evidence, not accepting any current live config. Old configuration snapshot should be maintained versioned input or narrowly scoped predecessor manifest projection, not entire duplicate stack.
