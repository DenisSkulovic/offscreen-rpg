## Foreground supervision
Choose Linux Python stdlib helper (already host dependency), one direct exec wrapper per kubectl child. Node spawns python with expected parent PID, inherited custody fd and argv array, no shell. Wrapper calls libc prctl(PR_SET_PDEATHSIG,SIGKILL), checks os.getppid()==expected immediately after registration, exits if mismatch, then os.execvp kubectl. No elevated/setuid execution; no child daemon. This closes parent-death-before-registration race; parent death after exec kills direct kubectl process. Node tracks ChildProcess handles, no PID scan, direct TERM then 5s KILL if still owned. Never reuse PID after close. Lock fd inherited across exec (verify explicitly; os.set_inheritable(3,True)); if parent dies lock remains until last child exit. Snapshot may remain owner-private after SIGKILL, never auto-delete foreign snapshots; document manual cleanup. All-or-none startup, output drain/caps, exact forwarding lines and actual HTTP probes; gRPC TCP only. 30s periodic checks serialized, no overlapping inventory calls, full identity check budget <=210s with per-command <=15s, failure stops session; no instantaneous revocation guarantee. Connection lock prevents cooperative upgrade; no daemon. Shared lock collision with ports fails without kill. Test parent SIGKILL before/after registration, FD lifetime, normal child close, foreign port, TERM-resistant child. Available Linux prctl and pidfd confirmed, actual helper proof is focused implementation acceptance, not claimed run. No new OS dependency beyond Python. If exact helper behavior fails, stop and return architecture contradiction.
