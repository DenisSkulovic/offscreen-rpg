# Retrospective source-route audit | HAR06 C1–C4

**Status:** completed desk investigation, **not a blinded performance benchmark** (2026-11-17). **Source revision:** `main@4fac2ea4430d91ebba252668a4ae3a309201af60`; code/docs checked against the GitHub commit and independently inspected using the clean portable snapshot `116ef01c77a157490e7dd61fa68a014a66a0c78f`. A Git comparison shows the named game/application source and contract files unchanged between them. **Not executed:** actual HAR06 gitignored machine report; agent/subagent/LLM trials; full wiki CLI benchmark with local dependencies. The auditor knew the HAR06 gold paths, so this audit demonstrates route *existence*, not unbiased route *discoverability*.

**Question:** Did HAR06's wiki-guided control actually follow product/technical source links? Can an ordinary question reach the right implementation without asking a semantic model to infer arbitrary filenames?

## Key implementation discovery

`scripts/repo-tools/retrieval-funnel-run.mjs#armFor` implements its B arm as `wikiHits(question)` **concatenated** with the unchanged `collectLexical(item.queries)` hits. It does **not** call `wiki:read`, traverse Markdown links, read package source maps, or follow module imports. The A and B candidate lists also overlap, so subsequent RRF fusion can double-count the same lexical evidence. **HAR06 does not measure documentation-guided investigation; it measures an additional wiki search list ahead of lexical hits.**

`rgHits` runs predeclared short phrases without inspecting code vocabulary, and truncates each query to eight raw lines before later collecting up to 30. That measures fixed phrase matching, not lexical decomposition or repo knowledge navigation.

**Critical scoring failure (C4):** `rg -n -F "mechanical world effects" packages/game/src/immediate-actions.ts` locates the generated-proposal rejection at line **384** inside `validateImmediateActionProposal` (declaration near line **351**). The HAR06 `matches(hit, role)` scorer demands **both** matching `path` and `role.symbol` appearing in the **same grep line** (`hit.text`). The matched rejection string does not contain the surrounding function name. Therefore even a correct file+line can be marked as not retrieved. This mechanism is present in committed code, but the exact gitignored HAR06 output was **not** available, so its C4 raw hit list cannot be asserted from this audit. **Separate candidate file recall, enclosing-symbol verification, and final answer correctness.**

These are *retrospective* traces. We did **not** measure what a blinded Cursor/Claude session would find or how long it would take. Every case and document was selected while knowing the expected targets; independent validation remains required for comparative claims.

## Decision: repair evaluator semantics, then test actual routing

1. **Fix the false-negative metric before another search run.** A hit naming an existing source file+line should count for **file candidate recall**, with an independent **enclosing-symbol/source evidence** verification step. The same-line grep snippet must never be conflated with symbol identity. Keep absent-feature denials and authority labeling separate from source lookup. Protect with a C4 fixture: code hit at line 384 without function name in text must be a file candidate, but not an auto-verified complete answer.
2. **Implement only a bounded, evidence-traced navigation control if selected.** Question → wiki heading/owner → bounded `wiki:read` (actual source) → **real Markdown link(s)** → package source map → 1–2 import/definition hops → exact source span. Every hop records whether it was an explicit hyperlink, lexical inference, import edge or expert reasoning. The current B concatenation is **not** a substitute.
3. **Separate independent channels before fusion.** Never count the same lexical result as independent supporting evidence merely because B copied it from A. Score wiki-only discovery, incremental links/owners and A/B overlap separately.
4. **Only then rerun comparable cases.** Use pinned clean source, exact line/source proof, review status, recall@5/@20/@30 and actionable negative cases. Do not let an author-known retrospective audit masquerade as a blind score.
5. **No vector vendor, LLM reranker or subagent now.** They cannot remedy a grader that misidentifies correct hits. Reconsider them only if genuinely blinded source-routing and lexical evidence **still** fail to produce candidates.

**Implementation gate:** this is a *design/evaluation note*, not permission to edit scripts or select a Change. If the owner wants changes, create one small Change to (a) separate file-candidate/symbol-verification metrics and (b) execute real source-map traversal. Reuse the HAR06 runner and existing wiki parser. Preserve HAR06 as a completed historical trial and its original machine report.
