## Occupied installation transition (required before live acceptance)

1. Preserve E1 variant inputs independently from target E2 inputs. Exact E1 dev desired Collector is the occupied predecessor (owner observed revision 2); revision number alone is not identity. Older base Collector installations must complete their existing supported transition first, not be adopted as E2. Classify absent, exact E1, exact E2, known owned intermediate pending, foreign/mixed and unreadable separately. Release never follows this path.
2. Under existing exclusive custody, re-observe identity/context/namespace UID, exact Helm manifests/history, admitted workload images, named RBAC absence/collisions, storage and memory. Stop old/incompatible observability mutators before upgrade and verify shared lock/pending semantics; do not rely solely on Git integration. Read-only forwards may require quiescence under existing custody. Record exact pre-upgrade data-plane state and positive synthetic markers in each backend. Existing pending/foreign/unknown state refuses without mutation.
3. Persist a validated pending record **before** mutation, bound to cluster/namespace UID, exact E1 and E2 artifact identities, affected release revisions, phase and preservation set. Generalize only required schema and verifier; old readers must continue to refuse any unknown pending record. Use existing supervised Helm mechanism. No `--force`, deletion/recreate, uninstall, PVC changes, adoption or `--reuse-values` implicit merge. Native render and exact explicit values/args are authoritative.
4. Upgrade only Prometheus first: existing server Deployment/Service/PVC identity retained; Pod/ReplicaSet identity may change as part of rollout. Add precisely owned helper workloads and RBAC; wait for exact desired Prometheus phase, ready scrape pipeline and retained data. Loki, Tempo, Collector and Grafana unchanged at this phase. Then upgrade only Grafana: retain its admin Secret, Service, datasource UIDs, release history and Deployment; expected Pod roll allowed. Other unchanged workloads, manifests and data remain intact. Confirm final structural identity, actual coverage and persistence; then clear own pending record through existing proven custody protocol. Repeat on exact E2 is no mutation. Grafana dashboard failures do not permit deleting storage or other services.
5. Partial failure, timeout, lost identity, interrupted process or ambiguous Helm state stays fenced and reports phase, observed state and permitted next action. No automatic destructive rollback or pending deletion. Design recovery as same-owner explicitly authorized resume only from exact proven phase with original UIDs/pins and no active mutator; otherwise stop for owner-directed recovery. Known intermediate must never be classified ready or treated as fresh install. Decide exact recoverable phases/receipt schema in packet planning against custody source; native interrupted transition proof before claiming resumability. Until then report pending/manual recovery required, not a resume command. Fresh install and normal repeat ensure continue to use existing lifecycle and must reject unexpected objects.

Data guarantees: preserve namespace, admin Secret, all three PVCs/PVs/bindings and stored metrics/logs/traces, existing Helm history and unrelated release identities. For upgraded components permit only expected manifest and rollout changes. Existing unupgraded backend Pods should not be deliberately restarted; if independent restart invalidates observation, re-observe/refuse rather than infer preservation. Keep existing retention, no credentials in receipts. Query historical marker within retention before/after upgrade; identity alone is not data proof. Bounded telemetry interruption during rollout is expected and must be reported, not promised lossless.

## First operator queries after E2

Use existing `pnpm obs:connect --queries` (loopback only), Grafana Explore or Prometheus API, and native kubectl. Example queries (verify actual metric labels against native source):

```promql
count by (job) (up)
count by (job) (up == 1)
count by (namespace) (kube_pod_info)
count(kube_node_info)
sum by (namespace) (rate(container_cpu_usage_seconds_total{container!="",container!="POD",pod!=""}[5m]))
sum by (namespace) (container_memory_working_set_bytes{container!="",container!="POD",pod!=""})
```

No fabricated dashboard numbers. A successful query is not necessarily a useful result: verify nonempty current series, units, expected identity and absence semantics. Capture actual coverage, not just screenshots. Source-only design artifact validation does not establish any of these native gates.
