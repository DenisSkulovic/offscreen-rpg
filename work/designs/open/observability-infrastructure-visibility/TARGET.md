# E2 | Selected direction proposed for acceptance

## 1. Collection topology and scope

Dev-first. Preserve release parsed manifests, pins, readiness behavior and existing telemetry policy exactly until separately authorized release enrollment. One Prometheus server, one Grafana, same datasource UIDs `offscreen-metrics`, `offscreen-logs`, `offscreen-traces`; no federation. Use dev profile overlay values for Prometheus/Grafana analogous to the existing Collector overlay. Preserve base values as predecessor inputs. Fresh dev install converges to E2; occupied E1 requires explicit upgrade. Ordinary ensure must not silently upgrade.

| Signal | Mechanism | Required interpretation |
| --- | --- | --- |
| Kubernetes object state | Bundled kube-state-metrics (KSM) chart 9.1.0, appVersion 2.20.0, enabled in dev Prometheus release | Cluster-wide node, namespace, Pod, Deployment, ReplicaSet, StatefulSet, DaemonSet, Job, PVC and resource requests/limits/status. No Secret/ConfigMap collectors, arbitrary labels or annotations export. |
| Container resource metrics | Explicit authenticated kubelet `/metrics/cadvisor` job on both nodes | CPU rate, working-set memory, network, filesystem where emitted; exclude empty/POD infrastructure containers from workload sums, avoid double-counting network across containers. No assumption completed or pending Pods have resource samples. |
| Node resource metrics | Explicit kubelet `/metrics/resource` job and KSM node capacity/allocatable/state | Node CPU/memory where supported by pinned Kind; node capacity vs pod use clearly labeled. No claim of host Windows or WSL metrics. |
| Component health | Prometheus native explicit endpoint jobs; see coverage table | Every installed component accounted for; Kubernetes readiness is different from scrape health and domain health. |
| Existing operational signals | Preserve Collector self-metrics and existing OTLP ingress/processing/export | Existing synthetic/dev proof retained; do not loosen filters or introduce new OTLP lanes. |

Use the bundled KSM rather than a new chart/operator. Do not enable chart's broad default Kubernetes scrape jobs wholesale (they default to annotation-based discovery, metadata copying and kubelet TLS verification bypass). Dedicated explicit jobs with fixed paths/ports, bounded allowlists and trusted target discovery. Prefer native metric endpoints over custom pollers. Use one standalone read-only Redis exporter Deployment/Service owned by the dev Prometheus release via its `extraManifests` (or equivalently chart-native declared resources if render confirms this interface); do not modify Redis Pod shape or restart its disposable cache just to monitor it. New native pinned exporter image is a prerequisite; no `latest`/floating fallback. No additional Helm release for these two helpers.

Node exporter is not selected for E2: its default host mounts/host namespaces would change the E1 trust boundary and Kind node system metrics must not masquerade as physical-host metrics. Kubelet resource metrics cover the immediate node CPU/memory requirement; node disk/OS metrics beyond proven kubelet series remain explicitly unsupported. Revisit a scoped node exporter only if the owner needs that extra coverage. Do not enable Alertmanager, Pushgateway, reloader sidecars or arbitrary pod scraping.

## 2. Permission and collection contracts

Dedicated service accounts for Prometheus and KSM, no token for Grafana or Redis exporter. Cluster-wide *read* discovery only as required: nodes, namespaces, pods, selected workload controllers/jobs/PVCs and endpoints/service discovery as actually needed; no Secrets, ConfigMaps, mutation verbs, wildcard rules, exec, impersonation or access to application payloads. Keep KSM resource collectors and generated RBAC in agreement, verify rendered rules not just values. No broad metadata labelmap. Cluster identity is `offscreen-dev`, environment `development`; stable namespace/pod/node/service and component identities, fixed job names; pod churn is bounded by retention. No tenant IDs, prompt content, message bodies, raw SQL or unrestricted labels. Metric paths fixed, no user annotation-controlled URL/port/credentials. No public Service, ingress, hostPort, host mount, host network or external remote-write. Do not widen Collector access; local trusted cluster is not tenant isolation.

Prefer direct kubelet HTTPS with verified CA/SAN and dedicated service account bearer authorization (`nodes/metrics` only as required). Verify serving certificates and access on both nodes before freezing this path. The vendored default `insecure_skip_verify: true` is not selected. If current Kind cannot support verified direct access without changing cluster provisioning, return that exact evidence to owner for a narrow alternative decision. API server node proxy via verified API TLS requires broader `nodes/proxy` access with meaningful kubelet privilege implications; do not silently add it or claim that GET makes it harmless. No insecure fallback. This is a genuine evidence gate for resource collection, not a reason to stall independent dashboard/KSM work after approval.

Initial local policy: scrape every 30s, timeout 10s; one scrape per target/path; use explicit metric family allowlists where safe, no arbitrary annotation labels. Initial per-target sample limits KSM/cAdvisor 20,000, other jobs 5,000; target limits 4 for each node job, 100 for each explicitly bounded component discovery job; label limit 40, name/value length limits 128/512; adjust only from measured native evidence (report limit errors, never silently truncate). Keep 7d/3GB metrics retention, 5Gi PVC and 72h logs/traces. These are initial engineering budgets, not measured maxima. Retain Prometheus existing 512Mi memory limit initially and record actual consumption; if qualification cannot fit, propose measured budget correction rather than silently increasing host requirements. Helpers initially request 50m CPU/64Mi RAM, limit memory 128Mi each; measure before acceptance. Preserve memory admission and do not preempt active work. Use no high-cardinality generated test labels.

## 3. Component coverage register

Dashboard coverage is an explicit register of fixed dev components, not a generic `up` table. Required service metrics for installed data-plane components below, subject to targeted endpoint/metric verification before the affected Change is Ready. Absent optional components have no invented green status. KSM covers all their Pods even when richer metrics are unsupported. Use distinct target and service health indicators, not scrape success as business health.

| Component | Direction / actual source anchor | Useful first signals |
| --- | --- | --- |
| Kubernetes control plane / nodes | KSM and kubelet; authenticated apiserver `/metrics` if endpoint and non-resource GET authorized | Ready state, node pressure, API request/error/latency where exposed; etcd, scheduler, controller-manager, CoreDNS, kindnet, kube-proxy visible in inventory, individual richer endpoints only after safe reachability proof (no rebinding control plane listeners) |
| PostgreSQL / CNPG | Existing CNPG instance native metrics endpoint (verify generated Pod/Service port and TLS, expected conventional 9187); `infra/platform/postgres/chart/templates/`, `vendor/cnpg-1.30.2.yaml` | Connection saturation, transaction rates, locks, replication if applicable, storage/health; do not enable query text or custom SQL without review |
| Temporal | Existing server metrics annotations in `infra/platform/temporal/values.yaml`, restrict to explicit frontend/history/matching/worker roles and native metric port/path; no broad annotation scrape | Per-service requests/errors/latency, persistence latency, task queue/backlog when emitted. Worker SDK metrics not implied by server scraping |
| RabbitMQ | `infra/platform/rabbitmq/readiness.mjs` expects named `prometheus` port 15692; actual Service and path verify | Node/queue/message totals, connections, publish/deliver/ack rates, resource alarms where emitted. Default aggregate endpoint; do not enable unbounded per-object metrics |
| Redis | `infra/platform/redis/chart/templates/service.yaml`: `redis.offscreen-dev-redis.svc:6379`; separate pinned exporter with fixed target, no arbitrary target endpoint exposed; read-only monitoring commands, no key enumeration/value access | Redis availability, memory, hits/misses, evictions, connected clients, ops/sec; exporter `up` distinct from Redis availability |
| SeaweedFS | `infra/platform/object-storage/providers/seaweedfs/chart/templates/{deployment,service}.yaml`: mini mode, only S3 port 8333 declared. Verify actual pinned mini metrics capabilities before choosing exact metric port/args; do not assume full distributed topology or scrape S3 data endpoint | Native capacity/requests/errors where supported; PVC binding and pod health always; if vendor mode lacks needed metrics, record explicit gap and owner decision before closing affected service scope |
| Observability | Existing `obs-prometheus`, `obs-collector:8888`; verify native internal metrics paths for Loki, Tempo and Grafana | Scrape failures, active series, storage/ingestion and rejected/dropped signals, exporter health; preserve current OTLP query behavior |
| Platform operators / cert-manager / local-path | KSM inventory for all, explicit safe metrics endpoint for CNPG/cert-manager/RabbitMQ operators when available (vendor manifests show metrics ports; some TLS/auth required) | Readiness/restarts always; controller errors/reconciliation if safe endpoint verified; no controller auth/TLS weakening |
| Traefik | Release-only in current platform plan; `infra/platform/gateway/values.yaml` | Absent/not applicable in dev, future release authorization for request/error/latency metrics; no release mutation now |
| Future dev slot / app Pods | Automatic KSM and cAdvisor coverage as they appear; no per-slot config edits | Resource use, replica/readiness/restart state; domain metrics/logs/traces deliberately not enrolled by E2 |

Before packets: obtain exact port, path, protocol, labels and at least one real metric per selected family using pinned chart/source and bounded owner read-only queries. Resolve KSM and exporter immutable image refs from pinned upstream artifacts and verify render/Kind image identity. Do not ask implementation agent to choose vendors, security models or storage migration. Where a data-plane endpoint is absent, select smallest owner-approved source change with independent subsystem lifecycle proof; if unavailable, explicitly narrow acceptance rather than fake coverage. No new DB or broker credentials in observability configuration.

## 4. Grafana operator experience

Provision repository-owned dashboard JSON via existing Grafana chart dashboardProviders/dashboards or dashboardsConfigMaps (verify vendored render); local Git assets, stable UIDs, no network dashboard/plugin downloads and no UI-only edits required. Keep admin Secret/datasource UIDs and stateless Grafana. Select `offscreen-overview` as provisioned home dashboard using supported native Grafana config; no anonymous login. Native dashboards are read-only canonical artifacts (UI exploration is welcome, changes require Git). All panels query existing datasource UID and proven metric names; distinguish no data, stale target, zero value. Variables cluster (single dev), namespace, workload and node derive from actual metrics, all with clear defaults, drill links preserve scope/time. No dynamic freeform cardinality labels.

| UID / Dashboard | First useful panels |
| --- | --- |
| offscreen-overview | Ready nodes/total, Pod phases/total, unhealthy workload count, CPU cores and memory vs allocatable, resource use by namespace, installed component coverage table, latest scrape freshness, links to details |
| offscreen-kubernetes | Every namespace/pod incl completed jobs, desired/available replicas, restarts and OOM reasons, CPU and memory time series per running container, requests/limits, pending and unscheduled, PVC state/capacity where emitted |
| offscreen-nodes | Node state, pressure, CPU/memory vs capacity/allocatable, top namespaces and workload use; no unsupported host disk panel masquerading as zero |
| offscreen-postgres | CNPG health, transactions, connections, locks, replication applicability, storage |
| offscreen-temporal | Server request/latency/error rates by role; task/persistence metrics where actually emitted |
| offscreen-storage | SeaweedFS health/native metrics and PVC inventory, with explicit unsupported panels omitted/annotated |
| offscreen-messaging-cache | Redis availability/hit ratio/memory/evictions and RabbitMQ aggregate queue depth/message rates/connections/alarms |
| offscreen-observability | Prometheus job status and freshness, scrape errors/limits, active series, Collector ingestion/drop/export, Loki/Tempo/Grafana self-health where emitted; link to existing Explore logs/traces |

Minimum overview is not just charts: each fixed component row must show inventory present/absent and target enabled/expected vs observed, readiness, metric freshness, and declared coverage limitations. Optional absence is distinct from scrape failure; zero-ready Pods with existing replicas is distinct from deliberately parked workloads; stale samples and missing jobs never show healthy. Derive fixed component names from versioned dashboard/coverage declarations with PromQL against KSM and target metrics; no new status database. Test dashboard JSON, unique UIDs, variable expansion, query semantics and actual data. Document operator route and native kubectl cross-checks in existing runbook.
