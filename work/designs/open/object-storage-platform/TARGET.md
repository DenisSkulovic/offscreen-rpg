## Scope and lifecycle

Keep local provider singleton: weed mini, 4.54, existing resource identities and resource limits, local PVC, ClusterIP, no operator. Provider-specific chart and profiles under providers/seaweedfs/; binding.mjs owns provider-neutral resolved configuration; install.mjs owns profile routing; provider provision.mjs and observe.mjs own vendor commands and local observations. No AWS provider management module. Existing dev slot derivation and tenant identity preserved.

Choose native Helm fresh-only installation, ordinary YAML templates for Deployment, Service, PVC (no hooks, namespace, credentials or cluster-scoped resources). Keep chart profiles inside chart/profiles to minimize resolver differences. Namespace and admin Secret are create-only external to chart; explicit profile context, canonical namespace, ownership, resource admission and no arbitrary public namespace override. Existing namespace without complete recognized installation is partial/refused; no automatic adoption. Preflight chart and exact resource inventory; inspect Helm release history including raw release record metadata, not merely helm list. Fresh path requires absent namespace and reserved resources/history, create namespace then admin Secret then helm install object-store <chart> --kube-context <context> --namespace <namespace> -f <profile> --wait --timeout 180s. No upgrade --install, takeover, force, atomic, uninstall, automatic rollback, or namespace/PVC deletion. Partial failures retain resources and return explicit refusal; subsequent ensure cannot recreate or adopt. Existing complete matching native release is observation-only/no new revision; drift/refusal otherwise. Use local cooperating-writer per-context lock for install and provisioning; no cross-service universal framework. Reuse the already accepted Redis R9 custody/uncertain-write discipline where actually shared/available, do not copy it mechanically or assume implementation landed. Exact runner integration is still a source-map item. Helm v3.22.1 behavior and failure/adoption evidence already researched and recorded at ../redis-platform/LIFECYCLE.md and R9.md on main; that evidence supports tooling behavior, not this chart or lifecycle runtime proof.

Legacy continuity: complete existing local installations may remain usable via read-only legacy-compatible observation, never claimed Helm-owned or re-applied. Require matching namespace/owner, current image, deployment selector and generation, service port/selector and actual ready endpoint, PVC identity/bound, admin secret metadata/required keys, no conflicting native history. No repair on drift, partial state or unknown observation. Normal ensure may report compatible legacy/no mutation to preserve local workflow; status distinguishes legacy vs native and endpoint readiness vs tenant usability. Existing slot provisioning continues through one guarded provider adapter, not old install mutation path. This is a proposed choice rather than previously ratified migration permission. Explicit legacy adoption/replacement, secret rotation and cross-provider migration excluded. Local release shared-admin compatibility remains separately labeled and gated; no claim scoped release workload auth until migrated. Fresh release must provision bucket and scoped identity before runtime; existing release may retain current credential binding during transition.

## Binding and consumer integration

Binding schema: bucket, region, endpoint optional, prefix optional, forcePathStyle boolean, credentials discriminated union secret {secretName} or default-chain. No values containing keys, only refs. Local defaults preserve existing endpoints and bucket names. External binding accepts assigned bucket/region and optional HTTPS endpoint; no provider deployment or local admin lookups. External default-chain is SDK behavior not a claim hosted workload identity is configured. Existing CLI remains local dev/release only; external binding is source-level render/config capability, actual hosted environment selector/deployment deferred. Do not silently change binding of existing data. Preserve OFFSCREEN_DOCUMENT_S3_* names, explicit path-style true/1 false/0, omitted retains old endpoint-based default; reject malformed flags and half-pairs. All six workload env blocks use one helper; release content buildFixtureJob uses same resolved binding via small JS env renderer with parity fixture. Keep web without storage creds. Explicit region and prefix when present; no endpoint env when omitted. SDK chain mode omits explicit credential fields.

Source routing: infra/environments/platform-plan.mjs corePhases currently branches dev CLI vs release install.sh; replace object-storage branch before profile split with same installer command plan/ensure + canonical profile/context. Ensure preflight explicitly checks Helm for dev object-storage too. infra/environments/infra-cli.mjs observeSelectedServiceState and release observation currently disagree (dev detailed, release Deployment only); route both through provider observation. Preserve service id and status adapter. infra/platform/common/render.mjs resolvePlatformChartPath currently <service>/chart and parsePlatformDocuments expects one JSON per line; for object storage use its native YAML renderer and exact inventory validation, adapt public render all/namespace/workloads without changing other service parsing; namespace document is synthetic separate render output, never chart-owned. Inspect existing YAML parsing utility/dependency before choosing exact parser. Public chart render and preflight must exercise actual install chart, not a second chart. No public legacy writer.

Runtime: add read-only requireBucket access check to S3ObjectStorage and forwarding S3DocumentStore, map failures to existing typed unavailable; replace ensureBucket in API, authority, worker and fixture importer. Bootstrap-only ensureBucket remains only explicit test/provision paths, never treat BucketAlreadyExists as owned. Scope HeadBucket/ListBucket requirements documented. Actual provisioning stays local adapter and externally provisioned infra. Do not allow silent fallback or automatic data migration. Dedicated local release app Secret and removal of shared admin projection require a safe transition separately from structural source work.
