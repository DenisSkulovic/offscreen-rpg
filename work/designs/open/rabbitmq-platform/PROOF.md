# Proposed proof architecture
Source tests by implementation executor: render both profiles, reject wrong target/storage/invalid manifests, verify exact artifact hashes and schema, fixture inventory cases (absent/matching/foreign/partial/unreadable/timeout/missing credential with PVC/legacy occupancy), assert zero mutations before admission, repeat ensure zero writes, bounded command failures, no secret output, no default topology, CLI plan/status selection and optional core exclusions. Pin client artifact and verify test cleanup ownership. No broad live suite by Cursor.
 
Owner/ChatGPT heavy acceptance: isolated disposable target with explicit authorization and known ownership, no existing broker/application traffic, host memory and disk gate, lock outer scope only. Batch fresh install -> current structural status -> authenticated protocol fixture -> repeat ensure with a retained extra queue and message -> compare identities and mutation log -> consume -> cleanup run-owned resources. Verify positive authentication and invalid credential/guest denial using a reachable service (not just timeout), management and metrics endpoints, no external Service exposure. Use publisher confirms, unique payload IDs, durable queue, persistent messages, manual ack. Normal smoke does not restart broker; it creates and removes only run-owned topology and client objects, not arbitrary fixed names. Use exclusive generated vhost or queue prefix with ownership and collision refusal; exact implementation selection pending. 
Separate disruptive proof on dedicated disposable broker: confirmed persistent message, capture PVC UID/Secret UID/Pod UID (not secret values), replace only owned Pod, wait readiness with deadline, confirm changed Pod UID and unchanged PVC/Secret identity, consume exact payload, then hold unacked delivery and terminate owned client, observe same payload and redelivered flag. Verify all cleanup or report retained run identifiers. Never restart shared occupied broker, force-delete foreign objects, or delete cluster/volume as implicit cleanup.
 
Provisional deadlines: individual API 10s, each controller/CRD/webhook phase 240s, broker readiness 420s, protocol step 60s, total lifecycle bounded 20 min (validate against actual phases before commission). Abort on identity change, unexpected data, insufficient capacity or timeout; preserve diagnostics, no automatic destructive rollback. Repeat on both supported profiles; cold clone/hosted/HA/load/restore deferred. Actual commands, ownership inventory, fixture design and proof tiers must be frozen before formal defense. All new tests NOT RUN; no local cluster access in this session.
