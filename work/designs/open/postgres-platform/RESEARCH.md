## Version pitfalls and evidence limits

- 1.30.2 tagged DatabaseSpec/DatabaseRoleSpec were actually retrieved; 1.30 manual is minor-line documentation. Raw web retrieval failed for several tagged files; GitHub connector succeeded. Several web pages unavailable; tagged docs supplied architecture/storage/bootstrap/config/resource evidence instead.
- Standalone DatabaseRole.status.applied is nullable; nil is not success. Role Secret resourceVersion is the last applied revision, not a guarantee the actual client is using the correct credential. Actual credential test and permission negative needed.
- Native Database CR can manage an existing DB. Existing SQL data/name collision is not proof of ownership; retain policy alone does not prevent destructive ensure: absent or Cluster deletion.
- Temporal design historical experiments observed DatabaseRole/Database current generations and credential resourceVersion matching in dev, existing DB ACL differences, 18.7 servers, and 1 dev/2 release instances at that time. See [dated evidence](../../../../evidence/runs/2026-11-26-temporal-platform.md); these are not fresh observations. No current live claims.
- Initial round's mention of max_connections=20 is an owner report/hypothesis until the later source/config audit. PostgreSQL default alone is not an adequate capacity decision; research CNPG defaults, Temporal actual pool creation, application process counts, reserved slots, memory and host capacity in later round.

## Provisional direction (not ratified)

One operator per context; native Cluster objects; independently provisioned DB/role resources; narrow common Offscreen policy layer for target/ownership, safe explicit operations, credential delivery, ACL SQL and postcondition checks. Preserve existing cluster and tenant identities. No local chart or Helm requirement has been selected; no custom operator/reconciliation loop. Keep operator installation method and version unless evidence justifies changing them. No numeric sizing selected.

Next: compare declaration mechanisms and ownership/operation boundaries as a coherent architecture. Investigate actual pinned CRD/source for critical lifecycle fields before committing specimen. Later compare actual old source only after target is coherent. No local Helm/kubectl, database queries, tests or live mutations run.
