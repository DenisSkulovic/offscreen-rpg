## 1. Selected operation and authority

Keep Helm rendering and pinned native CNPG, no new controller. Four core owners observation/compatibility/operator/ensure. The only automatic mutation is all-absent operator SSA once and create-only absent Namespace/Cluster. No automatic repair. Partial inventory ALWAYS refuses ordinary ensure, even if the missing object is harmless; the only experimentally demonstrated manual completion is the exact publication-viewer ClusterRole, on disposable infrastructure. No new recovery command or generalized manual sequence authorized for other types. Existing topology CAS and separate tenant/Temporal writers remain unchanged. Mutation requires existing explicit authorization plus owner-maintenance quiescence of those writers; no claim of cross-writer synchronization. Unknown outcomes stop, no retry; next explicit invocation re-observes from scratch. Never delete, adopt or overwrite durable objects.

## 2. Pure contracts and state transitions

collectBaselineObservation(profileId,deps) returns target/ownership/preflight observations plus operator records keyed by full group/version/kind/namespace/name, namespace and Cluster records, each {state: absent|present|unreadable, object? , reason?}. A CRD absent is not an arbitrary successful API read: Cluster is unavailable-by-CRD and only treated as absent for fresh install after all operator objects and competing API ownership are absent. Established CRD required before querying Cluster. Non-404 or malformed read never means absent. No Secret values. Target failures short-circuit. Assess returns {operator: absent|partial|pending|ready|incompatible|unknown, namespace: absent|compatible|incompatible|unknown, cluster: absent|pending|ready|incompatible|unknown, refusals:[{id,detail}], observedInstances?}. Unknown/incompatible/partial always dominate create. Namespace absent with Cluster present refuses. Operator pending waits, does not apply. Ready reuse is read-only and never resets observed count.

ensureBaseline returns {ok,stage,outcome,confirmedMutations,actions,refusals,instances?,phase?,primaryPod?,readiness?}. outcome = ready|refused|failed|unknown; stage = preflight|lock|observe|operator|namespace|cluster|readiness|guard. confirmedMutations lists only acknowledged creates (identity+UID) or fully acknowledged operator SSA (inventory identities, observed UIDs when read back); no manifest contents. An incomplete SSA response is unknown even if some outputs indicate success; preserve any individually confirmed identities, never infer no mutation. actions are actual completed/attempted stages with outcome, not future plan; no manifest/raw stdout in execution receipt. ok true only ready. mutated legacy boolean = at least one confirmed mutation; false does not exclude unknown effects. Known AlreadyExists stops, no adoption; transport error/timeout/uncertain response stops as unknown. Subsequent explicit observation does not retroactively certify a prior operation.

## 4. Custody and outer runner

Actual dev phase id cnpg, release phase id postgres (corePhases). defaultPlatformRunner selects 1830000ms/SIGKILL for those two IDs only; temporal remains 1200000ms, all others 600000ms with existing signal defaults. Release install.sh validates no arguments and execs Node release-install.mjs install --repo-root absolute-root; no separate mutation process, curl, shell prepare or retries. Node worker establishes 1800000ms monotonic deadline on entry before any external work, clips all child and sleep bounds; direct kubectl carries lock fd3 on all mutation calls. Lock path persistent private owner-only directory/file, no unlink/explicit unlock. Reject symlink/foreign owner/nonregular before use; open with O_NOFOLLOW and fstat, verify parent private directory, reject inode mismatch. Flock timeout 30s clipped to budget; timeout or nonzero refuses. Read-only children do not mutate, no exec auth plugins. Outer worker death yields unknown, parent cannot infer no writes. Actual kernel/client primitive proofs recorded; full composed runner/guard behavior is implementation acceptance, not already observed.

Release guard begin/end reuse lib.sh require_memory, volume_guard_begin/end, assert_loopback_only under bounded bash -c static script positional args, private temp dir; pre/post guard on all ordinary release install routes including direct CLI. Guard end attempted after known/unknown errors while budget remains; if cannot complete receipt records guard unverified, never success. No cleanup that mutates cluster; temp directory removal only owned files. Existing install completed output only after verified final guard. Root volume guard source test must follow new owner rather than require shell text that no longer owns guard. Direct CLI args validation remains fail closed.
