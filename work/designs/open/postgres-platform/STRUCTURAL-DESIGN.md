## 1. Scope and invariant

Consolidate dev/release baseline observation and installation; not every PostgreSQL mutator. Native CNPG owns reconciliation; existing Helm render-only chart, pin, topology CAS, owned topology procedures, tenant/Temporal policies, resource settings, ACLs, database/endpoint/credential identities retained. No new operator, general lifecycle engine, universal recovery marker, supervisor, automatic repair/upgrade or public CLI. Arbitrary topology CAS unknown-outcome recovery, tenant security, measured capacity and release credential migration remain separately gated. Earlier ACL/tenant specimens do not govern this slice.

Ordinary ensure may create only absent owned baseline Namespace/Cluster and install exact operator only when all its manifest objects are confirmed absent. It never changes existing durable Namespace/Cluster spec, rotates credentials, migrates ACLs or deletes/adopts resources. Healthy reuse observes only (including read-only SQL). Render/plan/status never persist writes. Unknown mutation stops, not retried. Explicit owner maintenance quiescence excludes other topology/tenant/Temporal/old installer/kubectl mutators during install or recovery; cooperating baseline writers additionally serialize via local flock. Read-only healthy reuse need not stop applications. No global admission/host reservation guarantee, no protection against nonparticipating writers or API work after client death.

## 5. Process custody and deadline (C01)

Single Node worker owns mutation and lock for both entrypoints; release install.sh execs Node so outer phase does not supervise an intermediate shell. Read-only guard subprocesses only; direct kubectl for mutation. Existing repository pattern tools/dev-environments/src/domain/dev-worktree-registry.mjs::withExclusiveFlockLockFile. Persistent per-user ~/.local/state/offscreen-rpg/platform-locks/postgres.lock, directory 0700, file 0600, never unlink/replace; reject symlink/nonregular/foreign-owned path. Open fd, spawnSync flock -w 30 -x 3 with fd at stdio index 3, timeout <=31s, SIGKILL. Hold same open-file description until finally close, explicitly inherit fd 3 into every direct mutating kubectl; no explicit unlock before child exits. Plan/status no lock, no nested acquisition or supervisor. Lock only cooperating baseline mutators; maintenance excludes others. Healthy reuse may bypass if no persistent writes.

One monotonic worker deadline 1,800,000ms including lock, preflight, guards and final observation. Outer PostgreSQL phase 1,830,000ms killSignal SIGKILL; other phases unchanged. These ceilings accommodate existing cold caps (operator apply 180s, CRD/rollout 180/240s, cluster 600s plus preflight/inventory/creates), not performance target. Clip each child timeout and request-timeout to remaining budget, no launch exhausted; direct child SIGKILL, check budget before/after; sleep min(5s, remaining), no busy-spin. Verified local Kind kubeconfig only, no exec auth/plugin subprocess. Outer failure not proof no mutation. Worker death must leave lock held by actual direct kubectl while it survives; if executable closes fd, proposal disproved and mutating scope gated. API can continue after client exit; owner maintenance continues through review of unknown state. Sandbox Node/flock experiment supports mechanism, not kubectl/WSL proof. No new supervisor to rescue overbroad guarantee.
