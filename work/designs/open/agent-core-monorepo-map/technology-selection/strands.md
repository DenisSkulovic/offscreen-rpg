# Strands Agents

## Fit and maturity
Model-driven execution, hooks, custom providers, typed tools, interrupts and agent-as-tool. Core source in newer [harness-sdk snapshot](https://github.com/strands-agents/harness-sdk/tree/8e3884657b62c6b989230265307794a5b1352e93), strands-ts/src/agent/agent.ts (AgentConfig, retryStrategy, tool executor strategy, experimental checkpointing), models/model.ts. Apache-2.0 core manifest, Node >=22.0. AWS Bedrock dependencies are real, not a requirement to use AWS as model provider. Optional peer range includes AI SDK provider v3, which differs from Vercel integration's v4; do not assume shareable model object. Old repo releases list 1.3.0; source plugin expects ^1.13.0, so actual npm release must be recovered.

## Native Temporal source
[TemporalAgent](https://github.com/temporalio/ai-integrations/blob/165fe93b5b4908a443076058b903d0f1b6aa3413/typescript/strands-agents/src/temporal-agent.ts) extends Agent, rejects non-null retryStrategy, sets it null. Temporal handles retries. [ModelActivity](https://github.com/temporalio/ai-integrations/blob/165fe93b5b4908a443076058b903d0f1b6aa3413/typescript/strands-agents/src/model-activity.ts#L65-L160) resolves registered model factories, caches model instances for Worker lifetime; input includes model name, messages and stream options; stateful variants also carry modelState. Custom factory config requires explicit named model; default Bedrock fallback exists when no factories supplied. Guarded factory models must not retain tenant-specific mutable state or credentials in process cache. [Plugin](https://github.com/temporalio/ai-integrations/blob/165fe93b5b4908a443076058b903d0f1b6aa3413/typescript/strands-agents/src/plugin.ts) registers model/tool/MCP effects and wraps error classification. [Temporal guide](https://docs.temporal.io/develop/typescript/integrations/strands-agents) supports hooks with explicit Activity bridge, typed structured results, interrupts resumed by Signals, Continue-as-New carrying messages/modelState. SDK snapshot support is not independent durability authority.

## Why promoted
Retry de-duplication is explicitly designed in integration, unlike relying on undocumented interaction of multiple loops. Hook bridge provides inspectable seams for deterministic decisions and external effects; custom model supports guarded inference. This is promising, not proof: HTTP adapters can still retry, Temporal may reattempt ambiguous work, and callbacks can omit authority. ModelState/server conversation ids must be bounded and route-scoped.

## Control concerns
- Lifecycle hooks are not sufficient security: verify every tool effect and model call reaches independently guarded Activity and cannot be bypassed by vended tool, MCP or child agent. Restrict vended tools initially.
- Guide describes subagent snapshots reset before each call unless preserveContext; neither gives scoped inheritance or budget automatically.
- Hook objects nonserializable; map only trusted identifiers and validated arguments into Activity. Context scopes must not be sourced from model content. Worker model cache keyed by model name, no tenant contamination.
- Explicit tool executor strategy/concurrency and limit stop reasons; inspect exact supported release. Streaming/history and provider state are separate risks. [Custom provider](https://strandsagents.com/docs/user-guide/sdk/model-providers/custom_model_provider/), [hooks](https://strandsagents.com/docs/user-guide/sdk/agents/hooks/).

## Specimen and disposition
Add to primary cohort with Vercel/OpenAI. Test same fake mission with registered guarded Model, Activity tool, hook interruption and child scope. Count physical calls despite Temporal retries and provider retry settings; test cache reuse across two isolated fake tenants, no implicit Bedrock fallback, no credential export, replay and cancellation. Test stateful mode only if necessary. Reject if model wrapper cannot bind mission/attempt identity, if SDK/peer artifact unavailable, or if broader harness forces unsafe defaults. Version register and real release compatibility pending. No runtime proof.
