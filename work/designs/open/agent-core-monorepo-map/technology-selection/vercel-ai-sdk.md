# Vercel AI SDK

## What it is and why it fits
Provider abstraction plus a lightweight tool loop, not necessarily a full application framework. SDK v7 rolling docs describe per-step settings, tool approval, stop reasons and subagents. It could supply both Agent Core and direct inference primitives, avoiding parallel provider abstractions. Source at ai 7.0.183 ([tag commit](https://github.com/vercel/ai/tree/0411a13df36b20bf6c67c82c1056e99d0e48257b)); [ToolLoopAgent source](https://github.com/vercel/ai/blob/0411a13df36b20bf6c67c82c1056e99d0e48257b/packages/ai/src/agent/tool-loop-agent.ts) delegates settings to underlying generation machinery; use actual v7 APIs, not examples copied from v5/v6.

## Execution and integration
[Temporal provider source](https://github.com/temporalio/ai-integrations/blob/165fe93b5b4908a443076058b903d0f1b6aa3413/typescript/vercel-ai-sdk/src/provider.ts#L66-L160) implements LanguageModelV4 proxy, serializes options into model Activity, defaults start-to-close 10 minutes with overridable Activity options. [Worker model Activity](https://github.com/temporalio/ai-integrations/blob/165fe93b5b4908a443076058b903d0f1b6aa3413/typescript/vercel-ai-sdk/src/activities.ts#L316-L338) resolves provider.languageModel(modelId), prepares file URLs, invokes doGenerate with Activity cancellation, strips request/response bodies from returned metadata. [Plugin](https://github.com/temporalio/ai-integrations/blob/165fe93b5b4908a443076058b903d0f1b6aa3413/typescript/vercel-ai-sdk/src/plugin.ts) accepts ProviderV4. Thus a guarded Worker provider is a promising seam; exact wire custody must be inside transport rather than inferred from stripped result metadata. File URL preparation occurs before doGenerate: restrict input modalities/URL downloads or guard downloader to prevent unauthorized network effects. Source proxy supports language and embedding models; do not infer durable image/video support from SDK-wide capabilities.

Workflow side: prepareStep/stopWhen, tool selection and deterministic handlers; external effects explicitly proxy Activities. Plugin guide demonstrates multi-step generateText. Verify ToolLoopAgent compatibility and its subagent APIs at pinned release, or use generateText's existing loop without creating a custom while loop. No additional workflow system needed. Use provider registry adapters where useful, not hosted gateway by default.

## Control and failure seams
- SDK maxRetries and provider HTTP retries can stack with Temporal retries; set explicit limits and test actual transport count. [Settings](https://ai-sdk.dev/docs/ai-sdk-core/settings).
- [Middleware](https://ai-sdk.dev/docs/ai-sdk-core/middleware) allows wrapping model calls; use Worker-side guarded model with Activity identity, trusted mission reference and route; verify actual serialization of provider options. Model-visible text/arguments cannot supply principal identity.
- Tool schema validation is not authorization. Inject trusted scope into Activity invocation; deny unregistered or revoked capability; enforce result visibility before history/model.
- Streaming is separately gated: published event parts and completion/cancellation/retry can diverge. Begin nonstreaming. The current plugin serializes full request options into history; encryption, size and retention needed.
- Subagents, compaction, provider-dependent reasoning continuations: available concepts, no assertion native Temporal integration covers all v7 variants.

## Discriminators
Run same fake two-round mission as others. Compare direct inference use of same guarded provider, model-step mutation and explicit tool Activity; verify actual SDK and provider retry knobs, URL rejection, no model-id fallback, cancellation, exact model request and cost usage. Check workflow replay after completed round and ambiguous receipt after dispatch. Use [mock testing](https://ai-sdk.dev/docs/ai-sdk-core/testing) only for local loop tests; HTTP fake plus actual Temporal required for custody. Evaluate whether SDK subagent machinery adds anything beyond explicitly admitted child Workflow.

## Assessment
Strong minimal-dependency/portability hypothesis. Core release Apache-2.0; compatible-looking source peer declarations, published plugin unresolved. Primary candidate. Reject if integration forces unguarded external effects, unbounded retries, unsupported required loop control or a second bespoke runtime. Sources: [loop control](https://ai-sdk.dev/docs/agents/loop-control), [Temporal guide](https://docs.temporal.io/develop/typescript/integrations/ai-sdk), [manifest register](VERSION-EVIDENCE.md). No runtime proof.
