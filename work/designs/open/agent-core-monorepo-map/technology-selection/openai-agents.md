# OpenAI Agents SDK

## Fit
Dedicated agent runner, function tools, structured outputs, sessions, handoffs, child agents, hooks and approval/resume. Provider abstraction supports non-OpenAI model backends; protocol support is not semantic equivalence. Inspected agents-core 0.22.0 [tag](https://github.com/openai/openai-agents-js/tree/@openai/agents@0.22.0), MIT, Zod 4 peer, core runner in packages/agents-core/src/run.ts. SDK offers broad functionality beyond first product need; keep hosted tools, sandbox and voice excluded initially.

## Native durability and interception
[ActivityBackedModel](https://github.com/temporalio/ai-integrations/blob/165fe93b5b4908a443076058b903d0f1b6aa3413/typescript/openai-agents/src/workflow/activity-backed-model.ts#L39-L138) serializes model request (input, instructions, settings, tools, conversation/response ids) and proxies Activity; normal vs local Activity selectable. [Worker createModelActivity](https://github.com/temporalio/ai-integrations/blob/165fe93b5b4908a443076058b903d0f1b6aa3413/typescript/openai-agents/src/worker/activities.ts#L173-L230) resolves ModelProvider.getModel and calls getResponse/getStreamedResponse. A guarded Model implementation on Worker is credible but identity not automatically supplied by the request; verify actual Activity metadata and explicit scope binding. Prefer regular Activities for initial evidence. [Temporal guide](https://docs.temporal.io/develop/typescript/integrations/openai-agents) documents that client or runner supplies model Activity options, not Worker defaults alone. Activity retry error classification is transport-oriented, not financial custody.

## Important documentation/source discrepancy
Rolling guide says use agentAsTool and nested runs inherit sandbox only, NOT parent context, maxTurns, guardrails, model settings or sensitive trace configuration. At pinned newer main [agent-tools.ts](https://github.com/temporalio/ai-integrations/blob/165fe93b5b4908a443076058b903d0f1b6aa3413/typescript/openai-agents/src/workflow/agent-tools.ts#L20-L169), agentAsTool is deprecated in favor of intercepted agent.asTool; options recorded, nested custom provider rejected, single agents-core copy important. This is a release skew, not proof newer semantics fix inheritance. Do not assert that older guide's limitation applies to newer release until matched. Both paths require explicit child admission and independent grant/budget checks. Consider child Workflow instead of handoffs or native delegation; parent remains Storyteller.

## Other seams
- activityAsTool sends model arguments to Activity; guide says RunContext does not accompany them. Do not pass scope via model-controlled fields. Workflow-bound wrapper calling scoped Activity or trusted Activity context lookup is candidate; prove child scope independently.
- Runner's SDK feature set exceeds integration's accepted options. Guide excludes some run options such as signal/toolExecution; use Workflow cancellation scope and explicit admission ceilings. Check selected tag's concurrency controls.
- [Tracing](https://openai.github.io/openai-agents-js/guides/tracing/) defaults may export sensitive traces. Disable external tracing globally and at runtime; verify children and actual egress. Our OTel is not financial ledger.
- Hosted tools and server-side conversation ids may bypass local tool authority or compromise exact historical replay; disable until separately designed. Full serialized input lives in history; budget payload and retention. Session is not canonical Library.

## Specimen
Use TemporalOpenAIRunner with explicit guarded ModelProvider, no hosted tools, deterministic instructions, Activity-backed Library read/stage, structured proposal. Force incompatible tool schema and malformed response, retry failure, revocation, child admission and actual trace suppression. Compare old/new child API only when release-matched. Prove no request reaches provider without stable attempt/grant even after restart and no child uses default model. Check SDK and OpenAI client retry settings, plugin error mapping. Inspect Workflow replay and cancellation cleanup.

## Assessment
Primary contender with richest dedicated runner. Source peer ~0.22.0 matches observed 0.22.0 release; plugin release unresolved. Strong risks are nested authority and option propagation, SDK protocol bias and external tracing. Reject if guardable provider/tool seams require invasive patches.
