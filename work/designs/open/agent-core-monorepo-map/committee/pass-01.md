1. **Agent Core: DEFENDED.** `AGENT-CORE.md` establishes pure serializable contracts, a separate workflow-safe export, static trusted definition/capability binding, deterministic mission admission/limits and terminal outcomes. Native SDK loop and Temporal history own their respective concerns; the test host owns Worker composition. No custom orchestration engine, SQL progress store, Redis or provider catalog is needed for E1. Existing Workflow/Worker owners remain intact. Rejecting a native seam that cannot satisfy essential guarantees is superior to adding a second unreviewed loop.
2. **Technology selection: DEFENDED for synthetic E1.** The reported P0/P1 cohort gives actual mechanism evidence: 4/4 each for Vercel, Strands and OpenAI. Vercel has the smallest observed install footprint (291M vs 305M/345M), bundle (8.61 vs 10.9/10.6 MiB), startup (1.93 vs 2.75/2.50 s) and tied-lowest P1 event count (23 vs 29/23). Warm latency is comparable to OpenAI; no speed, scale or production superiority claim is justified. The patched exact Zod 4.6.7 run reports 4/4 and completed 23-event replay. OpenAI is a credible reserve; Strands' extra configuration activity is not needed. A custom loop offers maximal control but assumes maintenance/replay burden without current evidence of necessity. A production-native decision must be revisited if guarded paid transport or required behavior cannot fit the seam.
3. **Monorepo: DEFENDED.** Five families are physical navigation, not dependency grants, services or deployment units. The 23 existing flat manifests were verified, with zero grouped manifests. E1 preserves all existing paths/names and activates only `packages/ai/agent-core`. Explicit workspace globs and duplicate detection are appropriate. `infra/images/common/workspace-graph.mjs::loadWorkspaceIndex` is flat-only and already rejects duplicate names; `infra/images/development/sync-plan.mjs::workspaceDirForPath` and `isAppManifestOrTsconfig` are flat-only. The chosen compatibility work addresses these seams. Release closure delegates to the common graph. The dev image copies and installs all workspaces but builds existing app prerequisites; this is not equivalent to production runtime closure. Exact final lock/peer graph and affected builds remain qualification. Keeping existing Storyteller and documents source unchanged preserves established consumers; hypothetical package boundaries are not migration orders.
4. **Authority and safety: DEFENDED within E1.** The definition/request/registry intersection, independent synthetic Activity checks, deterministic synchronous tool reservations, sticky denial/failure, capped input/steps/dispatches, retry limits, cancellation propagation, isolated namespace/queue, no real provider/credentials/SQL/domain access and no app registration establish the right boundary. The document/Library separation is consistent with current canonical documents ownership, but no data migration or new authoritative schema is accepted. G3/real G4/G5/protected G6 and expanded G7/G8 remain closed for activation. There is no production permission grant.
5. **Integration and qualification: DEFENDED.** Source-only construction joins on the isolated design branch are safe while no existing app consumes the package. The final acceptance matrix explicitly requires workspace/dependency compatibility, synthetic positive and negative mission behavior, actual physical invocation counts, replay and fresh Worker resume, cancellation/failure, and absence of production exposure.
