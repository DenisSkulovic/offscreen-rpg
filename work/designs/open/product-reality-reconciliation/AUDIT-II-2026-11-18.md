## Verdict

PVAL01–06 **did land**. The repository now more consistently distinguishes selected promises, implementations, proposals and evidence. These are real editorial/governance improvements. But they largely **relabel existing visions** rather than replacing them with one integrated and economically demonstrated game. Of 31 product Markdown files, **9 changed**; the complete export differs in **22 existing files** and adds **8 audit Markdown files** (the snapshot's regenerated metadata/index are counted among existing files). No existing file was removed. Neither comparison nor the archive documents support claiming that PVAL validated actual long-run AI gameplay. `STATUS.md` still says sustained 10–15-turn live creative quality is unproved.

The key new diagnosis is not simply *fiction in a product bible*. It is **missing decision ownership in the semantic middle**: deterministic systems can reliably enforce a declared action, but who decides which people, promises, meanings, changes in allegiance, spatial implications and creative opportunities should be represented *before* the rules can enforce them? Most answers still depend on model judgment plus partial schemas, and they have not been proved in a human-played loop. The product can be mechanically honest while feeling repetitive or narratively forgetful.

### The three most diagnostic adversarial runs

**A. The gift and the forgotten witness.** A named NPC accepts a tracked object after a meaningful exchange. The item transfer commits deterministically. The next turn contains a *socially meaningful* promise and a visible emotional reaction. Restart and return after 15 irrelevant turns. Can the model make and persist a stable participant record, reference the same object owner, recall the specific promise without fabricating it, and distinguish a rumor from established truth? Capture exact proposed documents, committed documents, retrieval decisions, final context and narration. If only the object survives, deterministic correctness has won but the *game* has failed its claimed emotional continuity.

**B. The sensible unoffered action.** Present a threatening stranger with three offered actions: greet, run, argue. The user wants to hand them an object or hide instead. Does the UI give an honest way to do this, or must the player choose an unrelated button? The selected no-free-text contract makes a limited menu a legitimate V0 choice, but measure whether the authored options represent genuine agency. Do not create a universal parser until the human failure rate justifies it; an “ask the Storyteller to consider an alternative” mode can be a separately costed candidate, not a hidden pseudo-choice.

**C. A quiet return that earns its price.** Accept one 20–30 real-minute routine. Close the page. On return, verify the clock, deterministic outcome, single commitment, a possible *admitted* interruption and a concise grounded account. Then compare a purely quiet completion with one genuinely worthwhile development. If the user feels they only waited for a checkbox, the issue is **game design**, not insufficient agent frameworks. Track model calls and cents per return; no model polling while idle.

### Secondary red-team probes

- **Route reversal:** an abandoned route cannot secretly stage its planned encounter; no 3D grid required for a two-location test.
- **Canon temptation:** give the Storyteller a famous setting and obscure unsupported lore. It must abstain or mark invention by campaign policy; a model's pretrained familiarity is not source truth.
- **Budget famine:** zero provider allowance after an accepted action. Time and effects must settle once; UI must not hallucinate a continuation or start an undeclared paid repair.
- **Contrasting protagonist:** a nonhuman fixture must not acquire STR checks, inventory or nutrition merely because the generic app models those for humans. A basic negative test is not proof arbitrary worlds are playable.
- **Fast-versus-slow honesty:** the portfolio demo clock must explicitly disclose acceleration while running the *same* time/receipt mechanics; otherwise it lies about the main game's waiting experience.

## Strategic recommendation: one experimental golden path, two human tests

**Do not attempt to turn all 2,004 lines of product documentation into immediate scope.** Also do not surgically delete long-term ideas merely because they are unproved. Adopt three differentiated lanes:

1. **Core invariants (selected, source-aware):** consent and accepted execution, honest fictional time, finite typed checks/effects/receipts, budget reservation, source and authority fences, truthful status. These survive every experiment.
2. **First-playable product hypothesis (one authored solo setting):** scene, meaningful options, one short action, one quiet meaningful-time activity, one encounter/consequence, one real persisted item/person/promise, one grounded return. No map renderer, universal world kernel, player co-op, automatic personality decisions, full character lifecourse or agentic retrieval requirement.
3. **Research catalogue:** semantic materialization, long-life narrative initiative, arbitrary-world schema, free-form action negotiation, autonomy, map topology, deep memory, advanced presentation, shared worlds. Each is an explicit bet with a price, falsification case, owner, and adoption trigger. The old design pages are useful *evidence of ideas*, not implementation queues.

**Test 1: active play (20–30 turns).** A cheap controlled model route, actual account price/cap and explicit separate authorization. The owner rates consistency, agency, novelty, enjoyment and corrections per turn; record *all* provider rounds and failed costs. Prior to spending, use deterministic fixtures to verify the playable causal path and fix known blocking provider behavior. No UI redesign or new generic engine before first meaningful quality result.

**Test 2: unattended return (at least one closed-browser routine, one restart).** Different product thesis: do fictional duration, state, consequences, saved relationships and one useful narrative update make returning worthwhile? A rapid 30-turn chat cannot answer that.

**Go/no-go questions:** (a) Would the owner voluntarily play another session? (b) Could the Storyteller support that without hand-holding or quietly rewriting truth? (c) Are total accepted-turn and meaningful-return costs inside a chosen budget? If no, shrink creative scope/model recipe or redesign the loop; no architecture gymnastics without demonstrated benefit.

## Editorial guardrails for Cursor

Never equate `Done` with product validated; PVAL01–06 completed documentation corrections. Before proposing a new mechanic, identify (1) player value, (2) the semantic actor that decides it, (3) deterministic admission boundary, (4) exact source/records, (5) fallback if inference fails, (6) model/cost round count, (7) cheapest discriminatory test. If any is missing, the next task is a decision or experiment, **not a generic framework**. All future claims should distinguish **selected**, **source-observed**, **tested**, **historic live**, and **human-play-proven**.
