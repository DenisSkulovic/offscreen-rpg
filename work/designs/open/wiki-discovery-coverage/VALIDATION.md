## Metrics kept separate

- **Structural:** root reachability, broken paths/anchors, section sizes, front-door question routes.
- **Authority:** section-level normative-vs-proposal correctness, source realization attribution, unknown honesty.
- **Dependency:** recall of hand-reviewed affected claims, false mandatory traversals, unknown routes.
- **Coverage:** important task/questions with one focused route versus genuinely unresolved product policy.
- **Comprehension:** correct answer/negative case with relevant quoted source; pages and bytes opened, wasted detours.
- **Maintenance:** no shadow authority, repaired backlinks after splits, planned P/T/C/Related disposition and actual close ledger.

Do not collapse into a single wiki health score. A change with 100% anchors but new false permission claims fails.

## Evidence to save after each Change

Actual repository SHA and dirty state; exact changed canonical headings; before/after query cases and negative fixtures; existing vs added page/owner map; real checks (or why unavailable); reviewed unknowns; independent adversarial interpretation and false-positive examples. Never claim a provider or fresh-agent run from synthetic scripts.

## Research verdict that may reverse design

If a proposed new page merely restates an existing owner and increases follow-up reading, **reject** the page and improve the existing heading. If typed dependency fanout becomes unbounded/noisy, reduce edges to causal selected claims. If per-section authority heuristics confuse selected text that only mentions a proposal, prefer explicit author labels on a small affected subsection over clever guesses.
