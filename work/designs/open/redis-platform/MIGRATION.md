# R7 | Legacy cutover contract (separate authorization)

[R9.md](R9.md) supersedes lock custody, pending receipt, history inventory and runtime observer. Migration is a future participant in the same private Redis lock and must hold one pending receipt throughout exact-object deletion and native installation; no nested locking or independent public locked entrypoint. Separate migration deadline, exact-object proof, operator authorization and recovery procedure still required.

One profile at a time, dev first, release second only after dev verified. Preserve namespace and DNS redis.<namespace>.svc; ClusterIP may change. No service IP continuity guarantee. No automatic adoption, no generic rollback and no migration mode in ordinary ensure. Cache contents explicitly disposable; never migrate or delete authority data. This is design, not permission.

Preflight read-only receipt: verified exact local Kind profile (common target guard), namespace UID/owner and not terminating, expected Deployment/Service/ConfigMap names, UIDs and RVs, exact known legacy labels and config/selector, no Helm release history or ownership annotations; inventory old controller descendants by UID, matching Pods and Service EndpointSlices. Compare to current approved receipt, not historic UID table alone. Require owner attestation all Redis consumers quiesced, no external clients or concurrent infra writers, cache loss accepted; refresh INFO clients/keyspace and workload configuration including envFrom/mount references without secret disclosure. No unexpected clients/objects; if discovered stop and redesign or use parallel path. Acquire same per-context cooperating writer lock across removal and fresh install (single supervisor, no nested lock); revalidate namespace and receipt immediately before each mutation. Existing namespace never deleted.

Removal order: Deployment first with foreground propagation and API DeleteOptions preconditions uid/resourceVersion from approved/current observation; wait exact Deployment and owned ReplicaSet/Pod descendants gone, no matching Pods. Service next with UID/RV preconditions; wait Service and EndpointSlices for old service gone. ConfigMap last with UID/RV preconditions. Re-read each unchanged approved UID and RV before delete; if RV changes from approved receipt stop, generate new receipt and require operator confirmation. Foreground wait bounded; unknown results stop and report partial inventory, never retry a deletion blindly. Raw API DELETE with body via kubectl delete --raw <exact path> -f - (proven namespace cleanup pattern); no label-based delete. Verify API response and complete absence incl old/new selector residue. Then invoke ordinary native fresh install under same lock; source-level internal locked entrypoint, not another flock. No implicit migration by infra:up.

Recovery: If any destructive step failed, unknown, or install failed, keep namespace and remaining resources/release evidence, refuse ordinary ensure on partial state. Operator reviews actual UIDs and state, chooses explicitly authorized completion or reinstallation; no automatic restoration of old cache, no assumption old ClusterIP recoverable. Successful cutover requires native release revision 1, exact expected config/image, endpoint ownership and PING, repeat ensure same resource UIDs/revision, no foreign changes. A separately owned live proof must exercise exact-object deletion preconditions before real replacement. No implementation or mutation authorized by this dossier.

Evidence: owner grep and live env-name census supports likely unused cache; not proof of quiescence. Existing live UIDs are historical observations. Release disposable Helm lifecycle PASS; namespace delete preconditions PASS, exact Deployment/Service/ConfigMap cutover not yet performed. Dev native install and public CLI proof remain acceptance steps.
