# Memory experiment | isolated Docker specimen

Run only with explicit owner choice: bash experiments/memory.sh --confirm-disposable. No existing Kubernetes resources, ports, volumes, or Redis keys touched. One fresh container using observed immutable digest (local presence required), 128MiB memory, no additional swap, 0.5 CPU, 64 PID limit, non-root and no network. Process listens only loopback. Container removed on normal exit; no shared cleanup. Docker daemon and image must already be present. Stop if host resource admission insufficient (owner checks before running). Each benchmark phase bounded by 45s inside container; no automatic retries or image pulls.

Control: Redis 8.2.1, 32MiB maxmemory, allkeys-lru, no persistence, 4 clients, pipeline 8, 4096-byte synthetic values. Three stages 2k/6k/12k writes with random keyspace 1M; total 20k writes, nominal 78.125MiB payload (not retained data; repeats/overhead/evictions affect actual key count). Sample idle then after each stage: allocation, RSS, allocator fragmentation, dataset, client memory, cgroup usage/peak/events and evictions. This is an illustrative memory-pressure experiment, not a throughput benchmark or sizing proof; no assertion that exact eviction count is deterministic. Throughput output is incidental and local Docker only. Expected: first phase below cap, later phases reach eviction, process remains responsive, cgroup OOM events absent if available; distinguish unavailable metrics from zero. If memory pressure, error, timeout, no eviction or image unavailable, record failure rather than retune blindly. Actual service budgets remain provisional. No K8s installation or proof from this fixture.

Upstream reference: https://redis.io/docs/latest/management/optimization/benchmarks/ (2026-11-26, random keyspace and payload size); https://redis.io/docs/latest/commands/info/ and https://redis.io/docs/latest/reference/eviction/ (metrics/eviction accounting; living docs, use observed 8.2.1 fields). Exact version redis.conf https://raw.githubusercontent.com/redis/redis/8.2.1/redis.conf (binary mb, protected mode, client memory settings).
