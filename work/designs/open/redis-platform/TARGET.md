## Ordinary ensure state machine

Inputs profile, explicit context confirmation, authorization and bounded run deadline. Read target through common assertPlatformTarget; validate exact namespace ownership, UID and not terminating. Acquire cooperating writer lock per context, not per pool, using flock supervisor pattern from Temporal. Revalidate target under lock; namespace may be created with kubectl create only if absent, no adoption on AlreadyExists; namespace alone is a valid ready-to-install precondition on next explicit call if correctly owned (unlike partial release). No cache mutation for plan/status. Existing namespace retained.

Observe Helm history through explicit context/namespace list --all plus get status for expected release where present; unreadable never means empty. Include all reserved object names and matching Pods/ReplicaSets/EndpointSlices. Distinguish absent (all reserved resources absent, no release or selector residue), legacy (known raw manifests), partial/foreign/drift/unreadable and compatible. A fresh path refuses any pre-existing reserved object, matching labels or annotations notwithstanding. Compatible deployed release requires revision/status, installed chart identity, exact normalized manifest from helm get manifest and computed values from helm get values --all -o json, matching current desired render/values, live effective config and runtime. No-op means no Helm install, upgrade, patch or revision. Do not use a marker/hash alone as authority. Status reports actual state, does not turn observation completion into READY. Helm list alone not definitive against unreadable storage or nonstandard drivers; refuse HELM_DRIVER and alternate KUBE/HELM endpoint overrides; use default secret driver, exact context. Do not log release contents or Secret values. Error, timeout or unknown install result stops; no automatic rollback/retry/repair. Fresh install: helm install redis <chart> --kube-context <context> --namespace <ns> -f <profile> --wait --timeout 180s; outer deadline allows Helm cleanup/receipt, no early supervisor death. No --atomic, takeover or upgrade flags. Scope is single operator/cooperating writers; no protection claim against arbitrary competing direct writers.

## Independent runtime observation (superseded detail)

[OBSERVER.md](OBSERVER.md) is normative for R7; the R6 text below records the prior broader proposal, not an additional requirement.

Compare normalized desired objects with installed release manifest (ignore presentation ordering/comments; no broad field stripping). Compare live objects through a **closed projection** of supported fields; include all intended mutable policy fields and reject unknown behavior-changing Pod/container fields rather than treating arbitrary injected sidecars or env as compatible. Ignore only identified API/controller generated fields (UID, resourceVersion, generation, timestamps, managedFields, status, allocated Service clusterIP/clusterIPs, known API defaults); define default normalization with exact server fixture before implementation. Projection includes namespace/name, profile ownership, Helm managed-by and release annotations, ConfigMap data and binaryData absence, Deployment selector, replicas, strategy, Pod labels/config checksum, one redis container image/command/args/env/envFrom, ports, resources, probes, volume/mount set, security contexts, service-account token/links, host networking/ports and init/ephemeral containers absence, Service selector/type/ports/protocol and external exposure absence. Compare effective image ID with recorded registry/runtime digest form (fixture observed index digest; other runtime forms need explicit resolution, not suffix guess). Pod UID chain Deployment -> ReplicaSet -> Pod, exactly one nonterminating matching ready Pod, observed current generation and updated/available replica counts; no extra selected Pods. EndpointSlice labeled for Service, ownership reference to actual Service UID, exactly one unique ready nonterminating endpoint target UID equal to Pod and address matches Pod IP; handle IPv4/IPv6 explicitly or refuse unsupported family. Probe PING through intended Service from verified Pod with bounded exec; check Redis version and effective CONFIG GET maxmemory, maxmemory-policy, save, appendonly, maxclients, maxmemory-clients. Verify expected defaults for latter two in fixture, do not claim workload sizing. Read config hash from desired string and compare actual bytes. Probe result and observations bounded; recheck UID/generation/selector after probe to reject stale observations; not atomic snapshot. No secret values, key names, FLUSH or write in status. A separate client Pod can prove cross-Pod connectivity under disposable proof, not mandatory for every status.

Open: exact API-default projection and Helm values normalization require read-only live specimens or deterministic test fixtures; cannot advertise a complete observer until these are frozen. A strict raw deep equality against server-defaulted object is not acceptable, nor an unbounded generic diff normalizer.
