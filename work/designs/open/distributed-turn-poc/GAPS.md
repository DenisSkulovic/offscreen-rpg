## Gate definitions

- **Existing** = source code or a dated test demonstrates a component, not its new distributed deployment.
- **Infrastructure Change** = prior planned packet with its own scope and proof. Component smoke does not prove application integration.
- **Design gap** = one or more consequential contracts remain unresolved and must be specified before Cursor implements the integration.
- **Implementation seam** = code exists in one process but the new network/runtime boundary and migration have no accepted executable Change.
- **Proof gap** = integrated behavior remains untested; no fake green statuses.

## The four deepest integration hazards

1. **Two writers for one world:** moving an imported `@offscreen/application` into both Nest and Game Authority would silently duplicate ownership, perhaps while both read the same PostgreSQL schema.
2. **Two independent delivery owners:** adding RabbitMQ in front of a still-active SQL→Temporal relay can dispatch the same business operation twice or lose it between acknowledgements.
3. **Two incompatible truths:** the latest canonical manifest root plus old scene prose plus today's SQL campaign/item state is not a historical snapshot. A fork built from it is invalid even if every document hash verifies.
4. **Two payment attempts for one intention:** a model timeout after dispatch is not proof of no charge. Retrying a Temporal Activity or RabbitMQ message must not launch a new billable provider call without reconciliation.

## Contract granularity before promotion to implementation

Each future executable Change must name **owned files/interfaces/migrations**, exact source-of-truth writers, incoming/outgoing schemas, state revisions, idempotency and retry/rollback decisions, safe launch/teardown, expected metrics, applicable cost/permission gates, normal/negative tests, canonical docs to update, and isolation from parallel agents. A placeholder “create Game Engine service” with no interface contract is **not Ready**.

**Next design pass recommended:** S01–S06 and P01, starting with one process/transaction owner and RabbitMQ/Temporal placement. It is the highest-impact unresolved seam: it determines who can commit scenes, where the canonical S3 staging happens and what each model worker is allowed to know. It should be detailed before a Game Authority/Storyteller implementation Change is created. Existing ARCH02 may own this work after integration, rather than spawning a duplicate specification.
