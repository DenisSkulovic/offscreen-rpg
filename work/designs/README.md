# Designs | active working set

Unaccepted designs and investigations that still need an owner decision, selected implementation or a dated review. **Completed and dormant folders do not belong under `open/`.** Not product bible. Not a Change or standalone Task authorization. [Work taxonomy](../WORK-TAXONOMY.md) distinguishes ongoing investigation from concluded [research](../../research/README.md) and observed [evidence](../../evidence/README.md). [Current work selection](../QUEUE.md) remains separate.

**Review command:** `pnpm repo:retirement` inventories working designs, their approximate age and Markdown backlinks, and aged archived Changes. No automatic deletion. 

**Retirement:** [2026-11 retirement ledger](ledger/2026-11.md) indexes the first eight pruned design folders (36 files, 308,870 bytes), with exact Git source links. There is intentionally **no permanent designs archive**. After promotion/deferral and a seven-day default cooling-off period, preserve a compact disposition entry and use Git history as the long-term archive. Inbound owner links must be reconciled before deletion. See [work taxonomy](../WORK-TAXONOMY.md).

**Design lifecycle:** investigate and compare alternatives here → explicitly review/accept product outcomes → reconcile accepted requirements into the existing `docs/product/` and `docs/technical/` owners → only then prepare and select bounded `work/changes/` packets for implementation. An open design is not a selected Change, and a committed proposal is not an approved spec. **Each remaining folder requires a named next decision and review date; entries that are merely historical will be retired in subsequent evidence-backed passes, not by blind deletion.** The [player experience program](open/player-experience-refoundation/DESIGN-PROCESS.md) records concrete review gates for the ongoing UI/UX overhaul.
