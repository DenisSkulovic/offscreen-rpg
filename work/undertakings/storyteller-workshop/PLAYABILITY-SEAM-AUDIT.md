# Playability seam audit | new Writer scene versus authorized player intent

**2026-11-21 source-grounded corrective finding.** Baseline: `undertaking/storyteller-workshop` at `9dce31c57cabeb05d417891dc39b1d745f7f7709` (WR05P2 still open). This is a design adjudication, **not** code/test proof. The previous [vision audit](VISION-TO-IMPLEMENTATION-RECONCILIATION.md) correctly identified post-opening Writer work, but did not yet prove whether an opening Writer's offered choices are *executable*. This audit establishes the missing distinction.

## Verified executable path

- `packages/storyteller/src/tasks/writer-mission.ts:writerOpeningSceneProposalV2Schema` has `scene:{content:passageContentSchema,interaction:interactionSpecificationSchema|null}`; no continuation selection semantics, per-option admitted intent, duration, or rule plan. The proposal's `summary/stagedObjectHashes/sourceEvidence` are for source/evidence, not action authority.
- `packages/contracts/src/interactions.ts:choiceSpecificationSchema` is explicitly presentation-only. An option has `id,label,description,risk`; no `intention` or authorized outcome/time. It validates presentation and whether option ID was offered, not that the choice is executable.
- `packages/story-engine/src/stories/resolution-core.ts:createStoryResolutionCore.admit` dispatches on `story.storyteller`. For profiled stories it calls `storyteller/admission.ts:prepareStorytellerResolution`; this insists the passage's `sourceGenerationId` points to a **succeeded `storytellerKind` legacy generation**, parses a `storytellerTask` and `publishedStorytellerSlice(source.output)`, and locates `published.next.options[]` with a non-empty `intention`. A Writer mission generation is not that shape/kind. An opening Writer choice can therefore **look valid but 100% fail on first click**. For a null storyteller, the scripted alternative `prepareScriptedResolution` requires `playableOpeningArtifact` and original source generation output, also not Writer.
- `packages/story-engine/src/stories/storyteller-resolution-authority.ts:commitStorytellerResolution` then stores `storyResolution` + a legacy `StorytellerTask`; `storyteller/publication.ts:publishStorytellerResult` publishes old result into the current or next passage. New Writer loop has no equivalent player-intent admission/continuation publisher.
- `packages/game/src/immediate-actions.ts:validateImmediateActionProposal,immediateActionAvailable` require a full `Character`, including facts and applicable abilities. `packages/story-engine/src/campaign/persistence.ts:requireCampaign` rejects a campaign with null character/content. An abstract or literary world **cannot** make its choices work by pretending it's a D&D character.
- `packages/story-engine/src/campaign/settings.ts:initializeCampaign` already supports `mechanics:false` with **no seed** and creates `campaign` with `character:null,content:null,gameSecond:0,clock`, settings and no mechanical offer. Thus a **world-neutral fictional clock substrate exists**, but the gameplay admission policy is still mechanical-only. Use that substrate instead of a new time microservice.
- `packages/story-engine/src/stories/command-policy.ts:continuationSchema` supports `response`, effect-free continuation and authored `wait/decision` but does not itself authorize player intention or auto-earn time; invoking it after a Writer choice without a proper admission receipt would be an authority bypass.
- `apps/web/src/features/play/ui/story-frame.tsx` and `campaign-offer.tsx` contain functional choice surfaces. They are consumers of authorized contracts; UI wiring can't repair missing server-side choice meaning.

## Corrected acceptance and execution choice

**P1 WR07B remains the substantial, immediate, source-backed Launch→first-scene Change; no need to destroy its current six-task implementation plan. However, its accepted exit must be phrased precisely as *durable first-scene publication/reentry*, not full player-interactive Play.** It may publish a v2 Writer opening with `interaction:null` and genuinely read-only first scene. It **must not** publish a clickable `choice.v1` from Writer-v2 as a working decision unless the backend has proved a corresponding trusted response path. An opening with unbound options must be held/rejected before it becomes public, not silently dropped, converted to fake plans or advertised as functional. Public `ready` means story/passage/checkpoint exist, **not that every possible next action is executable**. Retain the Web `STORY_LAUNCH_ENABLED` gate OFF until either valid choices are handled or the UI honestly renders the first scene without inviting impossible actions. Scripted no-provider E2E is still worthwhile but cannot certify the full undertaking.

**P3 Living Writer is the one big product implementation that makes P1's published first scene genuinely interactive and then repeats for subsequent scenes.** Do **not** create a separate "fix option click" micro-Change. This is the same continuation/admitted-intent kernel needed for each subsequent Writer scene. It must arrive as part of P3, ideally first in the bounded implementation task order.

### Selected P3 world-neutral intent contract (new protocol, not fake old result)

1. **Capture offered meaning:** A new versioned Writer final proposal for scenes with choices pairs each presented option with an authored `narrative-intent.v1` record: same stable `optionId`, bounded `intention` text, explicit `fictionalDurationSeconds` or a *separately authorized* interval/action kind, risk disclosure, and `effects:[]`. Writer cannot grant success, reward, character abilities or a resource transfer. Reject missing/duplicate/unbound IDs, inconsistent risk and a choice that attempts an unsupported mechanic. Keep `writerOpeningSceneProposalV2Schema` intact for already-published v2 openings; use a **new versioned result** instead of silently changing v2 history.
2. **One authoritative choice admission:** Story Engine routes a passage whose source is a Writer mission through a **Writer-intent branch**, not `prepareStorytellerResolution` and not the legacy scripted artifact. Under the owner/story lock, validate the exact displayed `interactionId`, selected `optionId`, source generation/mission, base checkpoint/root/revision, allowed story action kind, no competing active work and operation idempotency. Store the chosen intention/declared duration as a durable `storyResolution` or narrow versioned attached receipt; no text from the client may substitute it. Exact repeated operation returns the same receipt; changed option/actor/version fails.
3. **World-neutral clock:** For target new stories, initialize a clock-backed campaign with `mechanics:false` and `character:null` using existing `initializeCampaign`. It does not imply humanoid attributes, rule package, equipment or a D&D sheet. Add a narrow **narrative-intent authority** path that does **not** call `requireCampaign` or `validateImmediateActionProposal` (both assume character). Its only native effects are admission of a chosen intention, an explicit finite fictional-duration commitment/wait and a source-proven next Writer requirement; it does not invent mechanical world effects. Time advances only on an accepted execution boundary using existing campaign clock/pace discipline, never on model latency. If an actual timed action spans real time at the current pace, use existing interval/wake timing and correct hold/reentry, not an instant `gameSecond += seconds` bypass.
4. **One Writer continuation mission:** Versioned continuation capture identifies parent passage/checkpoint/source/root/settings and the frozen chosen intent/receipt. It enqueues one Writer mission with the same budget/attempt custody as opening. Worker replays one stable operation after restarts and hands accepted prose/source/document changes to Game Authority. Game Authority publishes next passage, interaction/authorizations and v2 checkpoint from the true after-state. Correctly preserve a still-running commitment if no scene is ready. **No dual legacy generation** fabricated to trick the old response route.
5. **Mechanical worlds:** Retain the existing `@offscreen/game/immediate-actions` and campaign action authority. A mechanically meaningful option must carry a valid typed `ImmediateActionPlan` or captured authored plan reference; it is not converted into a narrative-only plan. Writer narrates the **already committed** outcome. Mechanical and narrative-only paths share history, Writer mission, source-root and publication contract, not the rule evaluator.
6. **Scene fidelity:** A choice can have no mandatory new model call when a prepared valid quiet opportunity exists. Simple multiple-choice dialogue may trigger new Writer; abstract/no-character stories and complex character stories are both supported without a universal chat-only or humanoid fallback.

### True full-play demonstration

**Launch from one word → scene 1 with two different authored admissible intentions → choose A once → accepted duration/receipt, no clock drift from inference → Writer scene 2 with changed narrative and v2 checkpoint → choose B → scene 3**, plus one accepted quiet timed interval with zero model per tick. Wrong/old option, no character rules, missing source, duplicate click and crash cannot create a different outcome. Branch-and-fork scene 2 remains consistent.
