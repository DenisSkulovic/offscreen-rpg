- INF58 landed: chart values/schema expose `redis.maxmemoryMiB` / `redis.evictionPolicy`, `resources.{requests,limits}.{cpuMilli,memoryMiB}`, and `data.emptyDirMiB` with strict nested schemas and Helm cross-field fails. Templates split into `_configmap.tpl` / `_deployment.tpl` / `_service.tpl`; canonical `redis.conf` helper drives ConfigMap data and `offscreen.rpg/redis-config-sha256` on the Recreate singleton Deployment. renderPlatformDocuments uses JSON lines, namespace validation and stdinOverlay. Preserve baseline names; config changes deliberately discard cache on rollout.
- INF59 landed (source): `observations.mjs` / `reconcile.mjs` / `readiness.mjs` share observe/plan/ensure for both profiles; ConfigMap is part of ownership observation; auth-bearing render refuses before writes; namespace create uses `kubectl create -f - -o json`; children create-or-CAS-patch in ConfigMap → Deployment → Service order; compatible Service left alone; readiness requires owned identities, generation/replica/service predicates and config-hash when annotated. `dev-install.mjs` and thin `install.sh` → `release-install.mjs` preserve entrypoints; infra-cli maps explicit installed/not-installed/not-ready/unreadable. Multi-object operation remains single-operator local; no hosted-safety claim. Live install NOT-RUN.
- infra/environments/platform-plan.mjs calls dev-install.mjs ensure/plan and release install.sh; infra-cli.mjs uses shared Redis readiness. Existing smoke is dangerous on shared data and refuses occupied default identities; do not reuse for named pool or live application cache verification.
- Existing redis client config permits one REDIS_URL and uses createClient; no Sentinel or cluster discovery contract. Named pools are infrastructure only, no automatic app routing.
