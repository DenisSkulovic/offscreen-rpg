## Design findings
- database.ts returns raw drizzle(pool) and managed transaction/withClient; raw callers bypass custom admission. Later SQL01/domain audit, not this wave.
- execute.ts sets inTransaction after set_config; setup failure misses rollback. commitClient catches every reject as commit-unknown. VER04 already identifies both. DB12 fixes confirmed BEGIN cleanup, narrows definitive server refusal to direct pg DatabaseError severity ERROR and known 40001/40P01/23xxx; all ambiguous failures remain nonretryable commit-unknown. Require actual rollback tag before retry. No general SQLSTATE trust widening.
- Admission controller converts callback success to timeout after deadline, including possible already-acknowledged COMMIT. This is a separate real correctness seam: decide committed result vs generic lease deadlines before implementation. Do not commission a broad admission rewrite or claim hard cancellation. Existing managed policy limits remain unchanged.
- runner.ts validates pre-prefix only and conflates throw undefined with success. DB13 adds full post-ledger verification under existing lock, explicit failure state and safe CLI diagnostics; retains internal Drizzle verified-array call until pinned ORM API/transaction behavior reviewed. No reread of verified SQL at execution. DBOPS01 metadata reconciliation remains blocked from tracked generation intentionally.
- telemetry/runtime.ts has module-global pending instrumentation handoff consumed by admission.ts. DB14 replaces with explicit injected dependency; moves probe and simple types/deadline helpers; no queue semantics change.
