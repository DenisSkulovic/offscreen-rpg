# Cheap executor handoff: approved specification to Cursor

**Use:** format the launch for one source-grounded, reviewed Change, not implement or commission it. Follow [submission standard](../../references/planning-artifact-quality.md), [packet readiness](../../references/packet-readiness-review.md) and [parent procedure](../../references/bounded-parent-orchestration.md). Missing decisions return to ChatGPT. Verify exact target, prerequisites, readiness and owner commission before recommending dispatch.

## Source of truth

Use the selected Change, accepted canonical headings, exact source/contract sections and current baseline. No duplicate summary, legacy FEATURE/PLAN authority or pasted investigation. Root instructions always apply; avoid redundant preload when already loaded. [Model budget](../../references/cursor-model-budget-policy.md) owns actual allowed variants; Composer Standard default, named exceptions only. Parent owns one Change, child one bounded T-ID. Heavy acceptance belongs to ChatGPT/owner unless specifically delegated.

## Deliver this bounded packet

```text
CHANGE: <ID/path, kind, selected outcome>
TARGET/BASE: <branch, SHA, worktree/guard>
COMMISSION: <actual authorized scope and prerequisites>
FIRST: <T-ID or exact eligible wave; task-specific contract/anchors>
BOUNDARIES: <write/resource owners, excluded/forbidden actions>
CHECKS: <assigned focused positive + negative, command/cwd>
ACCEPTANCE: <heavy owner, remaining proof, stop/closure>
RETURN: <committed SHA, actual results, precise blocker or handoff>
```

Do not copy all cards to a child. Use the [canonical T-ID format](../../references/composer-first-execution.md#tasksmd-format). For VERIFY specify command, target/cwd, prerequisites, exact permission, safe stop and factual receipt. For docs-only state exact heading/links, preserved selected claims, semantic negative and Code unchanged. For frontend use [frontend engineering](../frontend-engineering/SKILL.md) only where relevant.

Readiness is not commission; ordinary frozen dependency gates need verified postconditions, not repeated planner approval. Cursor may diagnose a specific local failure and make scoped mechanical edits, not choose architecture, broaden permissions or silently upgrade models. If necessary child context or scope exceeds submission budget, repair/repartition before launch. Parent follows [execution procedure](../../references/bounded-parent-orchestration.md), commits assigned implementation and cheap proof, hands off heavy proof or closes accepted outcome. No successor selection.
