# UI art direction and critique

**Trigger:** an important new screen, redesign, visual-system choice or critique of generic-looking UI. Not a one-line CSS fix, React state/concurrency repair or new product decision without owner approval.

1. Read the affected **product experience** and what the user actually does. Inspect existing design components/tokens only if reuse matters. Do not start by generating a dashboard.
2. Read the relevant sections of [Interface design craft](../../knowledge/interface-design-craft.md), the principal **professional knowledge reference**. Investigate task, content, visual language, hierarchy and legitimate alternative design approaches before proposing one.
3. Offer **two genuinely different visual directions** and compare their suitability, text density, responsive behavior, accessibility, implementation effort and subject-specific identity. State the decisive criteria and what would reverse the recommendation.
4. Select a coherent visual thesis, reading/order hierarchy, typography/spacing/color/material choices, interaction states, mobile behavior and important intentional omissions. Separate visual choices from game mechanics and server ownership.
5. When reviewing, challenge the chosen design from a different perspective: content length, reading focus, empty/pending/blocked states, touch/keyboard and actual screenshots if available. Never certify beauty or accessibility from TSX alone.
6. Deliver a design contract or critique, not code: `visual thesis | alternative rejected and why | hierarchy | repeatable design language | unusual-content stress case | rendered/a11y acceptance | open owner decision`.

**Boundaries:** read-only by default. A document/design artifact may be created only if assigned. No application-code edits, browser actions, image/provider spending or policy changes without separate authorization. For React state and actual implementation use [frontend-engineering](../frontend-engineering/SKILL.md). For product interaction semantics use [player-experience-design](../player-experience-design/SKILL.md).
