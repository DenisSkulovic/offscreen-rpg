# Documentation and implementation Change workflow

**Use:** one selected lasting documentation or executable outcome. [Workflow](../../../WORKFLOW.md) routes other work; [work-unit standard](../../references/change-work-unit-standard.md) owns admission, kind, lifecycle and reconciliation. No design-only or pure evaluation packet.

## Dedicated parent commission shorthand

A direct named Change assignment authorizes that Change's routine lifecycle, not sibling Changes or unassigned live, spend, or destructive proof. Follow [parent commission and branch policy](../../references/bounded-parent-orchestration.md#0-dedicated-change-commission-owner-shorthand). One coordinator per Change. Continue through the authorized tasks, the Change-level join, and clean retirement. Stop for indispensable Change-level acceptance or an actual blocker. A permitted isolated source join is not design certification and is not a merge to main.

## 1. Select a measurable documentation or code outcome

Check [QUEUE](../../../work/QUEUE.md), the [Change catalog](../../../work/changes/README.md), existing work and the actual target and HEAD. Use the [submission standard](../../references/planning-artifact-quality.md): one preferred measurable outcome, normally 5–10 minutes of active implementation. Seven actual assignments is a strong default. Consolidate, simplify or split work whose size prevents reliable execution. Do not split a coherent bounded Change merely to satisfy a count. A tiny settled edit needs no invented packet. Do not create a duplicate active folder.

## 2. Resolve intent and authority before implementation

Material new architecture passes [design defense and owner ratification](../../rules/target-driven-renewal.md) before implementation planning. Evolutionary subsystem work uses proportionate review and does not manufacture that committee. For new behavior or guarantees, promote selected meaning to the canonical product and technical owners. An existing settled contract may be cited. Use [planner source investigation](../../references/planner-investigation-standard.md) against real source, callers, authority and negative paths. Separate proposed, selected, implemented and proven.

Use `planned-impact.v1`: Product, Technical, Code, Related rows, each changed with owner or unchanged because with concrete reason. Documentation kind names exact before/after claim, dependents and semantic negative; Code explicitly unchanged. See [work-unit standard](../../references/change-work-unit-standard.md#documentation-only-change-admission-and-proof). Do not ratify new requirements through editorial edits.

## 3. Write a self-contained executor handoff

Use the [CHANGE template](assets/CHANGE.md) at `work/changes/open/<leaf>/` or, inside a multi-Change Design, `work/changes/open/<design-slug>/<leaf>/`. Material delegated work requires TASKS, SOURCE-MAP, PROOF and exact execution contracts where necessary. An optional [PLAN](assets/PLAN.md) is only a current resumable checkpoint. [Packet construction](../../references/packet-design-manual.md) and [submission roles](../../references/planning-artifact-quality.md#3-execution-packet-shape) own the details. The planner writes source-grounded decisions. The implementation agent does not invent them. Independently review the [readiness dimensions](../../references/packet-readiness-review.md) on the actual candidate. Document completeness is not Ready. Only Critical and High findings block the affected scope. [Implementation handoff](../implementation-handoff/SKILL.md) formats a short launch after commission.

### Bundle scheduling and parallel execution

Use [parallel Change standard](../../references/change-work-unit-standard.md#batch-execution-and-parallel-change-orchestration-2026-11-19). Map the Design's Change edges before task cards. Each commissioned Change has its own coordinator, branch and linked worktree and joins the recorded design implementation branch. No whole Change as a child assignment. Internal checkpoints follow the parent procedure. They are not new approvals.

## 4. Implement only when authorized

Follow [parent procedure](../../references/bounded-parent-orchestration.md) and [implementation slice](../implementation-slice/SKILL.md). Edit only scoped owners, inspect diff, run focused normal/negative checks. Documentation scope does not authorize executable edits. Preserve existing work and safety/authority boundaries. Material contradiction returns to planner; no silent new selected behavior.

## 5. Converge, record evidence and retire

Commit source and actual cheap proof. No merge or archive while indispensable Change-level proof is pending. When that gate passes, archive the packet in the same commission. Design-level proof that the Design still owns does not delay that archive: record those obligations on the Design and do not mark them passed. At closure complete reconciliation for every affected authority heading and known dependent: changed or unchanged with concrete reason, actual source/document revision, evidence tier, negative, owner update or N/A. Apply [documentation reconciliation](../documentation-reconciliation/SKILL.md) only to affected owners; docs-only changes require semantic/status preservation, not just links.

Run applicable `pnpm wiki:change-guard --mode close`, link/maintenance and assigned join checks. Guard checks shape and known dependents, not normative truth. A guard defect needs separate authorized tooling repair, not waiver. Archive actual Done/Cancelled through [retirement procedure](../../../REPOSITORY-STRUCTURE.md#promotion-and-deletion-gate): move to work/changes/archive/YYYY-MM/<program>/<leaf>/, repair links/catalog/QUEUE if selected, compact ledger/full SHA. Batch moves may use scripts/repo-tools/archive-changes.mjs after checking actual scope. Preserve owner-retained legacy material and unique decisions/evidence. The coordinator joins the recorded target with `--leaf` and retires a clean integrated worktree only after that target has the archived packet and not the open packet. `lookup` on that target is the commission check. A constituent Change does not join main. No auto-next and no separate archival assignment.
