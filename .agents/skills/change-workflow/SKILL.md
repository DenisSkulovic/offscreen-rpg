# Documentation and implementation Change workflow

**Use:** one selected lasting documentation or executable outcome. [Workflow](../../../WORKFLOW.md) routes other work; [work-unit standard](../../references/change-work-unit-standard.md) owns admission, kind, lifecycle and reconciliation. No design-only or pure evaluation packet.

## Dedicated parent commission shorthand

A direct named Change assignment authorizes its bounded scope, not sibling Changes or unassigned live/spend/destructive proof. Follow [parent commission and branch policy](../../references/bounded-parent-orchestration.md#0-dedicated-change-commission-owner-shorthand). One parent per Change. Continue authorized tasks through checkpoints; stop at committed acceptance handoff or actual blocker.

## 1. Select a measurable documentation or code outcome

Check [QUEUE](../../../work/QUEUE.md), the [Change catalog](../../../work/changes/README.md), existing work and the actual target and HEAD. Use the [submission standard](../../references/planning-artifact-quality.md): one preferred measurable outcome, normally 5–10 minutes of active Cursor work. Seven actual assignments is a strong default. Consolidate, simplify or split work whose size prevents reliable execution. Do not split a coherent bounded Change merely to satisfy a count. A tiny settled edit needs no invented packet. Do not create a duplicate active folder.

## 2. Resolve intent and authority before implementation

Material new architecture passes [design defense and owner ratification](../../rules/target-driven-renewal.md) before implementation planning. Evolutionary subsystem work uses proportionate review and does not manufacture that committee. For new behavior or guarantees, promote selected meaning to the canonical product and technical owners. An existing settled contract may be cited. Use [planner source investigation](../../references/planner-investigation-standard.md) against real source, callers, authority and negative paths. Separate proposed, selected, implemented and proven.

Use `planned-impact.v1`: Product, Technical, Code, Related rows, each changed with owner or unchanged because with concrete reason. Documentation kind names exact before/after claim, dependents and semantic negative; Code explicitly unchanged. See [work-unit standard](../../references/change-work-unit-standard.md#documentation-only-change-admission-and-proof). Do not ratify new requirements through editorial edits.

## 3. Write a self-contained executor handoff

Use the [CHANGE template](assets/CHANGE.md) in `work/changes/open/YYYY-MM-DD--slug/`. Material delegated work requires TASKS, SOURCE-MAP, PROOF and exact execution contracts where necessary. An optional [PLAN](assets/PLAN.md) is only a current resumable checkpoint. [Packet construction](../../references/packet-design-manual.md) and [submission roles](../../references/planning-artifact-quality.md#3-execution-packet-shape) own the details. The planner writes source-grounded decisions. Cursor does not. Independently review the [readiness dimensions](../../references/packet-readiness-review.md) on the actual candidate. Document completeness is not Ready. Only Critical and High findings block the affected scope. [Handoff](../cursor-handoff/SKILL.md) formats a short launch after commission.

### Bundle scheduling and parallel Cursor execution

Use [parallel Change standard](../../references/change-work-unit-standard.md#batch-execution-and-parallel-change-orchestration-2026-11-19). Separate authorized parents/worktrees, explicit dependency and ownership graph, one integration custodian. No whole Change as a child assignment. Internal checkpoints within one Change follow parent procedure, not new approvals or extra selectors.

## 4. Implement only when authorized

Follow [parent procedure](../../references/bounded-parent-orchestration.md) and [implementation slice](../implementation-slice/SKILL.md). Edit only scoped owners, inspect diff, run focused normal/negative checks. Documentation scope does not authorize executable edits. Preserve existing work and safety/authority boundaries. Material contradiction returns to planner; no silent new selected behavior.

## 5. Converge, record evidence and retire

Commit source and actual cheap proof; hand off mandatory heavy acceptance to ChatGPT/owner, retain branch/worktree. No merge/archive with indispensable proof pending. At accepted closure complete reconciliation for every affected authority heading and known dependent: changed or unchanged with concrete reason, actual source/document revision, evidence tier, negative, owner update or N/A. Apply [documentation reconciliation](../documentation-reconciliation/SKILL.md) only to affected owners; docs-only changes require semantic/status preservation, not just links.

Run applicable `pnpm wiki:change-guard --mode close`, link/maintenance and assigned join checks. Guard checks shape and known dependents, not normative truth. A guard defect needs separate authorized tooling repair, not waiver. Archive actual Done/Cancelled through [retirement procedure](../../../REPOSITORY-STRUCTURE.md#promotion-and-deletion-gate): move to work/changes/archive/YYYY-MM/<program>/<leaf>/, repair links/catalog/QUEUE if selected, compact ledger/full SHA. Batch moves may use scripts/repo-tools/archive-changes.mjs after checking actual scope. Preserve owner-retained legacy material and unique decisions/evidence. Parent integrates to recorded target and verifies safe retirement under the parent procedure; no auto-next.
